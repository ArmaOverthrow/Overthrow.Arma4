title: "Ownership transfer doesn't clear previous owner (IsOwner stays true for old owner)"

---

**Found by:** dev-ops/test-coverage Phase 4 (findings.md bug #10, found by source reading while choosing test seams).

`OVT_OwnerManagerComponent.DoSetOwnerPersistentId()` overwrites `m_mOwners[pos]` but only *inserts* into the new owner's `m_mOwned` list — it never removes the position from the old owner's list. After a transfer: `GetOwnerID(building)` reports the new owner, `IsOwner(oldOwner, id)` still returns **true**, and `IsOwned()` scans the stale list.

**Impact:** real-estate data integrity — any transfer/sale path leaves both players "owning" the building by one accessor while only one owns it by the other. The persistence test suite deliberately routes around this by only taking unowned buildings (`GetRandomUnownedHouse()`); fix will need a test update to cover transfers properly.

---

**Fix (2026-08-03, pending confirmation):** `OVT_OwnerManagerComponent.DoSetOwnerPersistentId()` now detaches the position from the previous owner's `m_mOwned` list before assigning the new owner, and guards against duplicate inserts for the same owner (which `RplLoad`/repeat-set could produce). The renter setter had the identical defect and got the identical fix. `OVT_RplOwnerManagerComponent`'s RplId-keyed setters had the same leak (its `set<RplId>` deduped inserts but never detached the previous owner) — fixed the same way. The `OVT_RealEstateManagerComponent.ApplyPersistedOwner()` workaround comment was updated (its "setter always appends" rationale is no longer true).

**Coverage (per this bug's note):** `OVT_TEST_Persistence_RealEstateTransfer_ClearsPreviousOwner` (Tier D same-session suite) transfers a building between two synthetic owners and asserts the previous owner is cleared and removal is total. **Proven able to fail:** ran red against the unfixed code with the exact BUG-003 message, green after the fix. All group 46/46.
