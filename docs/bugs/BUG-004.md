**Found by:** dev-ops/test-coverage Phase 4 (findings.md bug #9).

`OVT_RecruitManagerComponent.RemoveRecruit()` removes the recruit from `m_mRecruits` and `m_mRecruitsByOwner` but never from `m_mEntityToRecruit` (or `m_mRplIdToRecruit`). Consequences: `GetRecruitFromEntity()` keeps resolving a removed recruit's ID for as long as the entity lives, and `GetRecruit()` then returns null for it — a slow map leak plus a stale lookup that hands callers a dead ID.

---

**Fix (2026-08-03, pending confirmation):** `RemoveRecruit()` now scans `m_mEntityToRecruit` and `m_mRplIdToRecruit` by value and removes every entry pointing at the removed record (value-scan, so it also catches entries under ids the record no longer knows). 

**Coverage:** `OVT_TEST_Persistence_RecruitRemoval_ClearsEntityLookups` (Tier D same-session suite) adds a recruit, removes it, and asserts no entry in either lookup map still points at the removed record. **Proven able to fail:** ran red against the unfixed code with the exact BUG-004 message, green after the fix. All group 46/46.
