**Found by:** dev-ops feature #2, re-confirmed by test-coverage Phase 1 (findings.md bug #3).

`OVT_PersistenceManagerComponent.OnPostInit` logs `[Overthrow] Failed to get SCR_PersistenceSystem instance!` once per world load, immediately followed by `[Overthrow] Initializing Persistence` — a success message printed on the failure path's sibling, which is actively misleading. Pre-existing init-order issue on the `vanilla-persistence` branch; `m_PersistenceSystem` stays null (see BUG-002 for the downstream silent-save consequence).
