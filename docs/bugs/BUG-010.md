**Found by:** dev-ops/test-coverage Phase 1 (findings.md bug #6).

When `DistributeInitialResources` spawns base fortifications, `{BE7B5BAFE1A16A50}Prefabs/Props/Military/Fortification/BarbedTape_Coil.et` emits `ENTITY (E): Destructible SCR_DestructibleEntityClass doesn't have a initial and final phase!` and `DEFAULT (E): SCR_DestructionMultiPhaseComponent can't be attached to a destructible entity of type SCR_DestructibleEntityClass`. The prefab config is base-game shaped, but it's Overthrow's base-upgrade usage that surfaces it — either swap the prefab or override its destruction setup.

---

**Fix (2026-08-03, pending confirmation):** Root cause was a stale entity-class token, not the vanilla prefab itself. Four Overthrow compositions (`AmmoCache_S_US_02/03.et`, `AmmoCache_S_USSR_02/03.et`) declared the coil node as `SCR_DestructibleEntity : "{BE7B5BAFE1A16A50}...BarbedTape_Coil.et"` — the prefab's root class from an older game version. Vanilla since moved the prefab to component-based destruction (root `GenericEntity` + `SCR_DestructionMultiPhaseComponent`), and forcing the legacy class produces exactly the two logged errors (that entity class wants initial/final phases; the multi-phase component refuses to attach to it). The four tokens are now `GenericEntity :`, matching vanilla's own compositions that reference this prefab.

**Verification:** All-group run is clean of both error lines; the small test world did not spawn an ammo cache this run, so the definitive check is a campaign start on Eden (or spawning `AmmoCache_S_USSR_03.et` in Workbench) and confirming the two `Destructible`/`SCR_DestructionMultiPhaseComponent` errors no longer appear during base resource distribution. Note: `Prefabs/Props/Civilian/PicnicTable_01.et` also roots an `SCR_DestructibleEntity` on the same vanilla base and may warrant the same review if it ever logs the same pair of errors (out of scope here).
