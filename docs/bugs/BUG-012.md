**Found by:** core epic discovery (`/discover-feature core/game-mode`, 2026-08-02). Verified at source.

`OVT_OverthrowGameMode.c:789` reads:

```c
OVT_Global.GetConfig() = OVT_Global.GetConfig();
```

— a no-op assignment of a function result to itself, almost certainly a mangled `m_Config = OVT_Global.GetConfig();`. As a result `m_Config` is only ever assigned inside `DoStartNewGame()` (L111). On the **save-load path** `DoStartNewGame()` is deliberately skipped (`EOnInit` only sets `m_bRequestStartOnPostProcess`), so `m_Config` stays null for the whole session while sibling fields (`m_RealEstate`, `m_TownManager`, …) are set — any game-mode member using `m_Config` on that path null-derefs or silently does nothing.

**Fix:** replace the self-assignment with `m_Config = OVT_Global.GetConfig();`. Interesting compiler note: this statement compiles clean on 1.7.0.54 despite assigning to a call expression.
