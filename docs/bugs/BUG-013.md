**Found by:** core epic discovery (`/discover-feature core/config`, 2026-08-02).

`OVT_OverthrowConfigComponent.RplSave` (L530-553) replicates only 11 difficulty fields + 4 server-config fields, initial-state-only (no `RplProp`, no `BumpMe`). These fields are read in **client-side** code but are absent from the stream, so every non-host client silently uses its own prefab default (`Difficulty_Normal`) regardless of what the server runs:

| Field | Client read site |
|---|---|
| `minFastTravelDistance` | `OVT_MapContext.c:64` |
| `QRFFastTravelMode` | `OVT_MapContext.c:81,83` |
| `baseCloseRange` | `OVT_MapContext.c:132`, `OVT_MapRestrictedAreas.c:69`, `OVT_DeployFOBAction.c:36`, `OVT_PlayerWantedComponent.c:443` |
| `fastTravelCost` | `OVT_MapContext.c:379,390` |
| `baseRange` | `OVT_PlaceContext.c:256,282,320,364`, `OVT_BuildContext.c:285` |
| `QRFPointsToWin` | `OVT_EconomyInfo.c:273` |
| `disguiseDetectionDistance` | `OVT_PlayerWantedComponent.c:249` |

`m_Difficulty.name` is also never replicated, so a client cannot even display which difficulty the server is running.

**Impact:** on any server not running Normal, clients compute wrong fast-travel costs/ranges, wrong base placement/build ranges, wrong QRF win threshold in the UI, and wrong disguise detection distances — MP-only, silent, and per-field divergent. Related debt (same file): the hand-written bitstream has no schema versioning, so adding the missing fields desyncs old clients — bump/verify carefully.
