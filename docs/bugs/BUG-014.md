**Found by:** core epic discovery (`/discover-feature core/config`, 2026-08-02).

Two unguarded dereference sites, both fed by **user-editable strings**:

1. `OVT_OverthrowConfigComponent.SetOccupyingFaction` / `SetSupportingFaction` (L272-292) — `factionMgr.GetFactionByKey(key)` is dereferenced with no null check. A typo'd `occupyingFaction`/`supportingFaction` value in `Overthrow_Config.json` (Mechanism C, dedicated servers) null-derefs during `DoStartNewGame()`.
2. `OVT_Faction.Init()` (`Scripts/Game/Faction/OVT_Faction.c:328-341`) — casts `GetFactionByKey(m_sFactionKey)` and calls `GetFactionEntityCatalogOfType(...)` without null checks. A `*_OverthrowData.conf` whose `m_sFactionKey` doesn't match a live faction crashes in `OVT_OverthrowFactionManager.EOnInit`.

**Impact:** a one-character admin typo in the server JSON takes the dedicated server down at campaign start with a VM exception instead of a clear config error. **Fix shape:** validate the key, log a clear `[Overthrow]` error naming the bad key, and fall back to `m_sDefaultOccupyingFaction`/`m_sDefaultSupportingFaction` (the "FIA"-refusal branch at `OVT_OverthrowGameMode.c:117,126` already models this fallback).
