**Found by:** core epic discovery (`/discover-feature core/player-manager`, 2026-08-02). Verified at source.

`OVT_PlayerData.IsOffline()` (`Scripts/Game/Data/OVT_PlayerData.c:35-38`) returns `id == 0`, but `OVT_OverthrowGameMode.OnPlayerDisconnected` sets `player.id = -1` (`OVT_OverthrowGameMode.c:510`). So `id == 0` only matches "never seen this session" (e.g. a save-loaded record before its player connects); a player who connected and **then left reports as online** for the rest of the session.

**Known consumers of the wrong answer:**
- `OVT_JobManagerComponent.c:382` — offline players are supposed to be skipped when iterating job counts
- `OVT_RecruitManagerComponent.c:420,501` — offline-owner recruit handling
- `OVT_WaitTillPlayerInRangeJobStage.c:11` — job stage waits on a player who is gone

**Fix:** `return id <= 0;` (or an explicit connected flag). Note the inverse hazard when fixing: code that relies on `id == 0` meaning "never seen" should be checked. No automated coverage exists (connect/disconnect is JIP/MP territory — manual play-test).
