**Found by:** core epic discovery (`/discover-feature core/game-mode`, 2026-08-02). **Verified against the 1.7.0.54 base game source** (`ArmaReforger/scripts/Game/GameMode/SCR_BaseGameMode.c:920`): the base implementation is NOT empty — it invokes `m_OnPlayerDisconnected`, notifies every `SCR_BaseGameModeComponent`, invokes `m_OnPostCompPlayerDisconnected`, calls `m_pRespawnSystemComponent.OnPlayerDisconnected_S`, and deletes the character RplEntity.

`OVT_OverthrowGameMode.OnPlayerDisconnected` (`OVT_OverthrowGameMode.c:500-547`) calls `super.OnPlayerDisconnected(...)` at L529 and then repeats that entire body inline (L531-546). On every disconnect:

- `m_OnPlayerDisconnected` and `m_OnPostCompPlayerDisconnected` invoke **twice**
- every `SCR_BaseGameModeComponent.OnPlayerDisconnected` runs **twice** (vanilla data collector, voting manager, etc.)
- `OVT_RespawnSystemComponent`/`OVT_SpawnLogic.OnPlayerDisconnected_S` runs **twice**
- `RplComponent.DeleteRplEntity(character, false)` is called a second time (the re-fetched character is normally already deleted/null by then)

The Overthrow-specific work (L502-527: `player.id = -1`, EPF pause+save, init-set removal, `m_PlayerManager.m_OnPlayerDisconnected`) runs once and is fine.

**Impact:** MP-only; double-fired handlers are at best wasted work and at worst double-mutating state in any subscriber that isn't idempotent (base-game subscribers included). **Fix:** delete L531-546 and keep only the `super` call. Note the duplicated block predates 1.7.0 — worth a quick diff against the engine version it was copied from when fixing.
