**Found by:** economy epic discovery (`/discover-feature economy/market`, 2026-08-02).

`OVT_EconomyManagerComponent.ReplenishStock()` (hour-7 pass of the economic clock) contains a comparison that can never be true (`OVT_EconomyManagerComponent.c:304-308`):

```c
int stock = shop.GetStock(id);
int half = Math.Round(stock * 0.5);
if(stock < half)                      // never true for stock >= 0
    shop.AddToInventory(id, half - stock);
```

`half` is derived from `stock` itself, so `stock < half` never holds. It was almost certainly meant to be `Math.Round(max * 0.5)` using the town max-stock computed two lines earlier at `:298-302` — which is currently **computed and never used**.

Two compounding defects in the same function:
- `:292` loops `foreach(RplId shopId : m_aAllShops)` **inside** the per-town loop, so every shop is processed once per town, and `GetTownMaxStock(townID, id)` uses the outer loop's town, not the shop's own — O(towns × shops) with wrong data. (`UpdateShops` at `:359` does it correctly via `typeShops`.)
- Only the gun-dealer branch (`:313-328`) actually restocks anything, and only for `m_aGunDealerItemPrefabs` (e.g. weed) — dealer weapons never restock either.

**Impact:** after `InitShopInventory`'s initial roll, town shop stock only ever decreases (NPC sales + player purchases). Long campaigns drain every shop to empty with no recovery; the scarcity price term (`GetSellPrice`) drifts permanently upward. Zero test coverage — a single Logic/Campaign-tier restock assertion would have caught this immediately.
