**Found by:** economy epic discovery (`/discover-feature economy/shops`, 2026-08-02).

`OVT_ShopContext.Sell()` (`OVT_ShopContext.c:297-348`) runs entirely on the client: it computes the sell price locally (`:303-307`), deletes the item from local inventory (`:339`), then calls `m_Economy.AddPlayerMoney(m_iPlayerID, cost, true)` → `RpcAsk_AddPlayerMoney` (`OVT_PlayerCommsComponent.c:604`), which credits **whatever amount the client sent** with no server-side validation of the item, the shop, the price, or proximity. `m_Shop.AddToInventory(...)` → `RpcAsk_AddToInventory` (`:563`) is likewise unvalidated, as is `RpcAsk_TakeFromInventory` (`:583`) — any client can call them with any `RplId`/quantity. `OVT_SellDrugsAction.c:27` has the same shape.

The only mitigation is the `addingMoney`/`takingMoney` double-fire latch (`comms:7-8`), which is a client-side rate limit, not authority — and it can itself deadlock a client's money ops permanently if the clearing owner-RPC (`RpcDo_DoneAddingMoney`, `:630-640`) is ever dropped.

The **buy** path is the correct pattern already present in the same file: `RpcAsk_Buy` (`:361-459`) re-resolves the shop from RplId, recomputes the price via `GetShopBuyPrice` server-side, checks funds, and charges only for items actually delivered.

Related asymmetries to fix in the same pass:
- The gun-dealer sell multiplier (`gunDealerSellPriceMultiplier`) exists **only** in the UI (`OVT_ShopContext.c:227-230, 304-307`) — nothing server-side would enforce it.
- `m_OnPlayerTransaction` never fires for sells (`comms:453`, always `isBuying = true`), so the black-market/strong-economy town modifiers only see purchases.
- `AddPlayerMoney`'s `doEvent` flag is dropped on the server-local branch (`OVT_EconomyManagerComponent.c:794-802`) — no selling XP in single-player/listen-host.

**Impact:** any modified client on a dedicated server can grant itself arbitrary money (or drain/duplicate shop stock) with a single RPC. MP economy integrity is fully client-trusted on the sell side.
