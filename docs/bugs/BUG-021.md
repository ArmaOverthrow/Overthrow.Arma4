**Found by:** economy epic discovery (`/discover-feature economy/real-estate`, 2026-08-02).

Every real-estate mutation ask applies client-supplied parameters directly with no server-side checks — no ownership re-check, no funds re-check, no proximity check (`OVT_PlayerCommsComponent.c:295-350` for `RpcAsk_SetBuildingOwner`, `RpcAsk_SetBuildingOwnerPersistent`, `RpcAsk_SetBuildingRenter`, `RpcAsk_SetBuildingRenterPersistent`; `:864-887` for `RpcAsk_AddToWarehouse`, `RpcAsk_TakeFromWarehouse`).

Compounding it, the money side of a purchase happens **on the client before the ask**: `OVT_RealEstateContext.Buy()` (`OVT_RealEstateContext.c:196-225`) checks and debits funds locally (`PlayerHasMoney`/`TakePlayerMoney`), then sends `SetBuildingOwner`. `RpcAsk_SetBuildingOwner` also takes `int playerId` from the caller rather than deriving it from the RPC sender, so a client can assign ownership (or renter status) to **any** player.

The sibling shops feature demonstrates the correct pattern in the same file: `RpcAsk_Buy` (`:361-459`) recomputes cost server-side and validates funds before mutating anything.

**Impact:** on a dedicated server, a modified client can grant itself (or any player) any building for free, evict any renter, fabricate warehouse stock, or skip payment entirely. All property and warehouse state is client-trusted.
