**Found by:** economy epic discovery (`/discover-feature economy/shops`, 2026-08-02).

`OVT_ShopContext` computes its page count with integer division, making the `Math.Ceil` a no-op (`OVT_ShopContext.c:146` and `:170`):

```c
m_iNumPages = Math.Ceil(m_Shop.m_aInventory.Count() / 15);
```

Two failure modes:

1. **Items permanently unreachable.** `Count() / 15` truncates before `Ceil` sees it — with 57 items the result is 3 pages (45 items shown), leaving 12 items that can never be displayed or bought. Any shop whose stock count is not a multiple of 15 hides its remainder.
2. **Negative index.** With fewer than 15 items, `m_iNumPages == 0`: the page label renders `1/0`, and `NextPage` (`:87-94`) clamps to `m_iNumPages - 1 == -1`. `Refresh`'s guard `if(m_iPageNum >= m_iNumPages)` does not catch `-1`, so the render loop at `:177` starts at index `-15` → `m_aInventory.GetKey(-15)`.

Fix shape: force float division (`Math.Ceil(count / 15.0)`), floor at 1 page, and clamp `m_iPageNum` into `[0, m_iNumPages-1]`. The arithmetic is a perfect world-free Logic-tier test candidate (prove it can fail with counts 14, 15, 57).

**Impact:** user-visible in every well-stocked shop — gun dealers and general stores with 16+ item types silently hide inventory; small shops show a broken page label and can fault the menu on Next. (Reminder: per project policy the EnforceScript division mode follows the *target* type — `Count()/15` assigned into an int expression is integer division here, unlike the float cases disproven in the test-coverage findings.)
