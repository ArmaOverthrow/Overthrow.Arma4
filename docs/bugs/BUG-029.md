**Found by:** occupying epic discovery (`/discover-feature occupying/base-upgrades`, 2026-08-02).

The proxying virtualization banks a despawned garrison's value in `m_iProxedResources` and re-spends it when a player approaches. `GetResources()` (= live agents × `baseResourceCost` + the bank) is what `SpendToAllocation` measures against — so bank errors corrupt all future spending. Three related defects:

1. **Bank never cleared after re-spend** — `OVT_BaseUpgradeDefensePosition.c:70` and `OVT_BaseUpgradeTowerGuard.c:95` increment `m_iProxedResources` when going out of range, and their `CheckUpdate` overrides re-spend it (`DefensePosition:22`, `TowerGuard:51`) — but unlike the parent (`OVT_BasePatrolUpgrade.c:71`, which clears it), **neither resets the bank to 0**. Each despawn/respawn cycle inflates `GetResources()` further; `SpendToAllocation` goes permanently negative and the upgrade stops receiving budget while appearing fully funded.
2. **Overspend banked before clamping** — `OVT_BasePatrolUpgrade.c:161-172` (and `OVT_BaseUpgradeDefensePatrol.c:46-53`): `m_iProxedResources += newres` happens *before* `if(newres > resources) newres = resources;`, so the unclamped amount is banked while only the clamped amount was paid. Both sites carry `//todo: delete some soldiers when overspending`.
3. **`m_iNumGroups` double-increments** — `BuyPatrol` (`:98`) and `Spend` (`:172`) both increment for the same logical group; only `CheckClean` decrements for real groups. The counter drifts upward, and `OVT_BaseUpgradeDefensePatrol.c:35` branches on `m_iNumGroups == 0` to pick group type.

Fix shape: reset `m_iProxedResources = 0` after the two override re-spends; move the bank increment after the clamp; make `m_iNumGroups` derive from `m_Groups.Count()` + proxied list length instead of hand-counting. Compounds with the dead allocation clamp in `OVT_BaseControllerComponent.SpendResources` (`:294-301`, noted in BUG-026).

**Impact:** garrison strength decays invisibly over a session — bases near player activity (most despawn/respawn cycles) end up under-defended while the ledger says they're fully funded; group-type selection degrades via the drifting counter.
