**Found by:** skills epic discovery (`/discover-feature skills/influence`, 2026-08-02).

The Diplomacy skill's entire payoff runs on the honor system:

```c
// OVT_ConvertSupporterAction.c:9 (client-side user action)
if(s_AIRandomGenerator.RandFloat01() < player.diplomacy)
{
    ...
    OVT_Global.GetServer().AddSupporters(pOwnerEntity.GetOrigin(), 1);
}
```

The server accepts the result unconditionally, with a **caller-supplied count**:

```c
// OVT_PlayerCommsComponent.c:88-92
[RplRpc(RplChannel.Reliable, RplRcver.Server)]
protected void RpcAsk_AddSupporters(vector pos, int num)
{
    OVT_Global.GetTowns().AddSupport(pos, num);
}
```

Compounding it, `OVT_TownManagerComponent.AddSupport()` (`OVT_TownManagerComponent.c:1221-1228`) has **no population cap** — contrast `TakeSupportersFromNearestTown` (`:1194`), which does guard — so support can exceed town population until the next `RecalculateSupport()` clamps it (`:563-585`).

Supporters are real economy: donation income scales with `town.support` (doubled above 75 stability, `OVT_EconomyManagerComponent.c:452`), supporters are the recruitment currency for camps and garrison groups (1:1 with population), and support ≥ 75 suppresses town patrols. A crafted client can max every town's support instantly (`num` = anything), and even an unmodified client at Diplomacy L5 gets guaranteed conversions (`m_fSupportChance 1.0`, `overthrowSkills.conf:142`).

Fix shape: move the roll server-side into the RPC handler (fixed `num = 1`, roll against the *sender's* `diplomacy`, keyed off the sender's player ID, with a proximity check to the civilian/town), clamp `AddSupport` at population, and cap Diplomacy L5 below 1.0 (~0.75-0.9) as a balance follow-up.

**Impact:** multiplayer integrity — town support (and everything it buys: income, recruits, patrol suppression) is client-mintable. Same class as BUG-020/021/025/033.
