**Found by:** jobs epic discovery (`/discover-feature jobs/core`, 2026-08-02).

`findGunDealer`, `findShop`, `placeEquipmentBox`, `recruitACivilian` and `placeACamp` (`Configs/Jobs/`) all set `m_iMaxTimes 1`. That counter is **global**: `OVT_JobManagerComponent.CheckUpdate()` skips a config once `m_aJobCounts[index] >= m_iMaxTimes`, and `m_aJobCounts` increments in `StartJob()` regardless of owner. So after the first player completes (or merely receives) each onboarding job, no other player on that server is ever offered it.

The per-player mechanism exists — `m_iMaxTimesPlayer` checked against `m_mPlayerJobCounts` in the player-allocated offer loop — but it is rendered inert because the global cap fires first. Four of the five configs even set `m_iMaxTimesPlayer 1` (`placeACamp` omits it), which only makes sense if the global cap was not intended to apply.

Likely origin: commit `f7bc36f` "Fix new tutorial jobs spawning for every town" — the global cap fixed the every-town spam but over-corrected to once-per-server.

Both counters are persisted (`OVT_JobManagerSerializer`), so the caps also survive across sessions: on a continued dedicated-server campaign the tutorial chain is permanently dead for every new joiner.

Fix shape: for player-allocated configs (`!m_bPublic`), gate on `m_iMaxTimesPlayer`/`m_mPlayerJobCounts` only (or additionally scale `m_iMaxTimes` semantics to mean per-player when the job is player-allocated); keep the per-town spam fix by relying on the existing "player already has this job index" occupancy check. Existing saves carry the poisoned global counters — the fix must ignore (or migrate) `m_aJobCounts` for player-allocated configs.

**Impact:** every multiplayer server: only the first player gets the new-player tutorial jobs (and their money/XP/item rewards); everyone else loses the onboarding chain entirely.

**Note added 2026-08-09 — the five jobs have since been REMOVED. This bug was NOT closed by that removal.**

It was fixed **in place on 2026-08-03** and has been `closed` ever since: `OVT_JobManagerComponent.c:638-639` reads `bool playerAllocated = !config.m_bBaseOnly && !config.m_bPublic;` and then skips the global `m_iMaxTimes` gate for player-allocated configs (line numbers re-checked 2026-08-09 against the post-removal tree; the fix itself is unchanged). **That fix is still live and still applies to the surviving configs** — it is a property of the offer loop, not of the five jobs, so any future player-allocated job (`m_bPublic 0` and `m_bBaseOnly 0`) is gated per-player, not per-server.

Separately, on **2026-08-09** the `new-player-experience/starter-jobs-retirement` feature deleted all five configs named above (`Configs/Jobs/findGunDealer.conf`, `findShop.conf`, `placeEquipmentBox.conf`, `recruitACivilian.conf`, `placeACamp.conf`) and their registrations in `Prefabs/GameMode/OVT_OverthrowGameMode.et`, replacing them with the shipped tutorial entries in `Configs/Tutorials/`. The stated reason for that removal is **redundancy**, plus the `new-player-experience` epic's binding constraint that a job assigns a directed goal and drops a marker on one named instance. **It is not a closure of this bug** — the bug was already closed, and this note exists so that nobody later reads a false closure into the history.

One consequence worth recording: after the removal **no shipped config is player-allocated** at all. `m_bPublic` defaults to `1` (`OVT_JobConfig.c:31-32`) and no survivor overrides it, so the `playerAllocated` branch this bug's fix added is currently unexercised by shipped content. It remains correct and is exercised by test coverage rather than by a config.

What disappeared with the five jobs, stated once accurately because an earlier figure circulated and was wrong: **$100 in cash, 30 XP, and two field dressings** in total, once per campaign per player. The XP is 30 rather than 10 because `m_iRewardXP` defaults to **5** (`OVT_JobConfig.c:37-38`) and is paid whenever it is above zero (`OVT_JobManagerComponent.c:535-537`); only `recruitACivilian.conf` ever declared it (10), and the other four each paid the default 5.
