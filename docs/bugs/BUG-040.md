**Found by:** jobs epic discovery (`/discover-feature jobs/core`, 2026-08-02).

Three related leaks in the completion/notification path of `OVT_JobManagerComponent`:

1. `RpcDo_NotifyJobCompleted` is `RplRcver.Broadcast` with no owner filter on the receiving side — when any player completes a player-allocated job, **every** client gets the "job completed" hint, including for tutorial jobs they haven't done themselves.
2. The server-side completion path in `CheckUpdate()` also calls `SCR_HintManagerComponent.ShowCustom(...)` directly (`OVT_JobManagerComponent.c:436`) **before** sending the broadcast — a listen-server host therefore sees the hint twice.
3. That same server-side `SCR_HintManagerComponent.GetInstance()` call runs on dedicated servers, where there is no HUD — at best a no-op, at worst a null-path depending on engine behavior.

Related structural note (tech debt, not filed separately): jobs are the only Overthrow subsystem bypassing `OVT_NotificationManagerComponent` and using raw hints, which is why there's no per-player targeting to lean on here.

Fix shape: drop the server-local `ShowCustom` call; either target the completion RPC at the owner's connection, or keep the broadcast and early-out in the receiver when the local player's persistent ID ≠ `job.owner` (public jobs: notify all, matching current design intent). Routing through `OVT_NotificationManagerComponent` would get owner-targeting and consistency for free.

**Impact:** hint spam that misattributes progress in multiplayer and double-hints listen hosts; cosmetic but constant, and it advertises every player's tutorial progress to the whole server.

---

**Note added 2026-08-09 — the five tutorial jobs have since been REMOVED. This bug was NOT closed by that removal.**

It was fixed **in place on 2026-08-03** and has been `closed` ever since. The fix is still live and still applies to every surviving job, verified on the post-removal tree 2026-08-09:

- The server-local `SCR_HintManagerComponent.ShowCustom(...)` call is gone from the completion path; the only `ShowCustom` left in the file is inside the RPC receiver (`OVT_JobManagerComponent.c:1088-1092`), which runs on clients.
- A listen host no longer double-hints: the completion path sends the broadcast and then calls the receiver directly **only** when `RplSession.Mode() != RplMode.Dedicated` (`:565-569`), because broadcast RPCs do not run on the authority.
- The receiver filters by owner: for a non-public config it returns unless the local player id equals the job's owner (`:1079-1086`). Public jobs still notify everyone, which is the design intent this bug's fix-shape named.

Separately, on **2026-08-09** the `new-player-experience/starter-jobs-retirement` feature deleted the five tutorial job configs (`Configs/Jobs/findGunDealer.conf`, `findShop.conf`, `placeEquipmentBox.conf`, `recruitACivilian.conf`, `placeACamp.conf`) and their registrations in `Prefabs/GameMode/OVT_OverthrowGameMode.et`. The reason was **redundancy** against the shipped tutorial entries in `Configs/Tutorials/`, plus the `new-player-experience` epic's binding constraint that a job assigns a directed goal and drops a marker on one named instance. **It is not a closure of this bug** — the bug was already closed, and this note exists so that nobody later reads a false closure into the history.

Note also that all seven surviving configs are `m_bPublic` or `m_bBaseOnly` (`m_bPublic` defaults to `1`, `OVT_JobConfig.c:31-32`), so the owner-filtered branch at `:1079-1086` is currently unexercised by shipped content. It is correct and must stay: it is the only thing that keeps a future player-allocated job's hint private.

The related structural note above still stands unfixed: jobs remain the only Overthrow subsystem using raw hints instead of `OVT_NotificationManagerComponent`. That is jobs-epic tech debt and was explicitly out of scope for the retirement.
