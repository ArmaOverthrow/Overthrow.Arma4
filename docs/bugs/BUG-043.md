**Found by:** resistance epic discovery (`/discover-feature resistance/loadouts`, 2026-08-02).

The four loadout endpoints in `OVT_PlayerCommsComponent.c:1024-1157` perform zero validation: `playerId` is a caller-supplied string never checked against the sending connection; there are no distance/ownership checks on the box or target `RplId`s. Consequences:

- `RpcAsk_DeleteLoadout` deletes **any** player's loadout by name (griefing).
- `RpcAsk_SaveLoadout` can overwrite another player's loadout.
- `RpcAsk_LoadLoadout` is a "spawn mode" that equips a full saved kit gratis onto any player anywhere — it spawns everything from prefabs, has **no legitimate in-repo caller** of its client wrapper, and is a free-item endpoint for any modified client.

Same class as the economy epic's client-authority bugs (BUG-019…024) and the occupying epic's capture RPCs (BUG-025).

**Impact:** loadout griefing across players and free item spawning from any modified client on dedicated servers.

Fix shape: derive the acting persistent ID server-side from the RPC sender; validate box/target proximity and recruit ownership; delete the spawn-mode endpoint or gate it behind a server-side context that legitimately needs it.
