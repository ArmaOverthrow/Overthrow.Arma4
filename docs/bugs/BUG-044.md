**Found by:** resistance epic discovery (`/discover-feature resistance/loadouts`, 2026-08-02).

Loadout extraction reads only the in-hands weapon and the clothing root storage: `ExtractEquippedItems` (`OVT_LoadoutManagerComponent.c:1020-1063`) goes through `weaponManager.GetCurrent()` only, and the storage walk (`:361-411`) covers clothing containers. `EquipedWeaponStorageComponent` (the weapon-slot storage holding slung/holstered weapons) appears solely in the **apply** path (`:1297`) — never in extraction.

Any weapon not currently in hands is silently missing from the saved loadout, and its quick-slot reference is left dangling.

**Impact:** silent data loss on the most common multi-weapon kits (rifle + pistol); players discover it only after applying the loadout and finding the second weapon gone.

Fix shape: iterate `BaseWeaponManagerComponent.GetWeaponsSlots()` at extraction and save each weapon with `isEquipped` + its weapon-slot index, mirroring what the apply path already understands.
