**Found by:** resistance epic discovery (`/discover-feature resistance/core`, 2026-08-02).

`OVT_ResistanceMenuContext.c:206` calls `OVT_ResistanceFactionManager.AddOfficer()` directly on the client. `AddOfficer` (`OVT_ResistanceFactionManager.c:408-412`) does `Rpc(RpcDo_AddOfficer, …)` — a broadcast, which clients cannot send — so only the **local** `RpcDo_AddOfficer` runs on the promoting client. The server, every other client, and the promotee's persisted `OVT_PlayerData` record never learn about the promotion; it evaporates on the next JIP/save. No `RpcAsk_AddOfficer` exists anywhere in `OVT_PlayerCommsComponent` (grep-verified).

**Impact:** a core multiplayer feature — promoting players to officer — is completely broken on dedicated servers. It only works where the promoting player is the authority (local/hosted play).

Fix shape: add a server-validated `RpcAsk_AddOfficer` to `OVT_PlayerCommsComponent` (validate caller `IsOfficer`), route to the manager on the server, then broadcast and persist via the player manager as usual.
