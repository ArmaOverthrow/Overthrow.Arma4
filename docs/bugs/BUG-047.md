**Found by:** resistance epic discovery (`/discover-feature resistance/core`, 2026-08-02).

The three garrison-purchase endpoints validate nothing:

- `OVT_PlayerCommsComponent.c:719-721` indexes `m_Bases[baseId]` unchecked — hostile `baseId` → server VM error.
- `:732-736` / `:747-751` take the *nearest* camp/FOB which may be null; `OVT_ResistanceFactionManager.c:769-775` / `:784-790` then deref `fob.location` — server crash when no camp/FOB exists.
- `prefabIndex` goes into `m_aGroupPrefabSlots` unchecked (`:752/:767/:782`) — OOB crash vector.

Payment happens **client-side**: `OVT_FOBMenuContext.c:85` calls `TakeLocalPlayerMoney` with a client-computed amount, and the server endpoints re-check neither cost nor supporters. A modified client calls the RpcAsk directly and gets free garrisons; an honest client is charged even when the server call fails or crashes.

Same class as BUG-025 (occupying capture RPCs) and BUG-043 (loadout RPCs).

**Impact:** remote server-crash vectors plus a free-garrison / charged-but-failed money exploit on dedicated servers.

Fix shape: bounds/null-check `baseId`, nearest-camp/FOB and `prefabIndex` in the RpcAsks; move the charge server-side into the garrison purchase (validate funds, then spawn); derive the paying player from the RPC sender.
