**Found by:** resistance epic discovery (`/discover-feature resistance/building`, 2026-08-02).

**No server-side charge for buildables.** `OVT_ResistanceFactionManager.BuildItem` (`OVT_ResistanceFactionManager.c:670-717`) never calls `TakePlayerMoney` — compare `PlaceItem`, which charges at `:646`. The legit client pays separately via `OVT_BuildContext.c:533` → the generic `TakePlayerMoney` RPC (`OVT_PlayerCommsComponent.c:615-628`) with a **client-computed amount**. A modified client calls `RpcAsk_BuildItem` directly and builds every structure free; even the legit flow is two unlinked RPCs, so a charge can land without a build or vice versa.

**No validation on either endpoint.** `OVT_PlayerCommsComponent.c:682-685, 705-708` pass straight through; `ResistanceFactionManager.c:602/:605/:673-674` index `m_aPlaceables`/`m_aPrefabs` unchecked (hostile indices → server VM errors); no `CanPlace`/`CanBuild`/item-limit re-check server-side; `playerId` is client-supplied (bill someone else); and since `DoTakePlayerMoney` clamps at zero (`OVT_EconomyManagerComponent.c:955-964`), a $1 player buys a $250 camp even on the honest path.

Same class as BUG-019…025 / BUG-043 / BUG-047.

**Impact:** money exploit (free/underpaid structures), cross-player billing, and remote crash vectors on every dedicated server.

Fix shape: bounds-check indices; re-run placement rules, limits and affordability server-side; charge inside `BuildItem` after validation (mirror `PlaceItem`) and delete the client-side charge; derive the player from the RPC sender.
