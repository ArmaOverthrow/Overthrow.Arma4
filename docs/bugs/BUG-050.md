**Found by:** resistance epic discovery (`/discover-feature resistance/building`, 2026-08-02).

`OVT_PlaceContext.c:144` and `OVT_BuildContext.c:161` compute `Math.Ceil(count / 14)` — the ints divide **first**, so the shipped 8 placeables / 7 buildables give `Math.Ceil(0)` = 0 pages ("Page 1/0" in the UI). `NextPage` (`OVT_PlaceContext.c:114-121`) then clamps `m_iPageNum` to `m_iNumPages - 1` = **-1**, and `Refresh` loops from `i = -14`, reading `m_aPlaceables[-14]` — a VM error from one Next click in normal play.

Secondary: item counts of `14k+1 … 14k+13` also under-count pages, silently hiding tail items once content grows past one page.

**Impact:** guaranteed script error reachable by a single click in the place/build menus on every campaign; wrong pagination display always.

Fix shape: integer-ceiling division `(count + 13) / 14` with a minimum of 1, in both contexts (and a Logic-tier test over counts 0, 7, 8, 14, 15, 28, 29 — proven to fail on the current code).
