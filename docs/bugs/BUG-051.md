**Found by:** resistance epic discovery (`/discover-feature resistance/recruits`, 2026-08-02).

**`RpcAsk_RecruitCivilian`** (`OVT_PlayerCommsComponent.c:826-839`) recruits whatever `SCR_ChimeraCharacter` the client-supplied RplId resolves to — no civilian-faction check, no proximity check, no server-side cost, client-supplied `playerId`. A modified client can recruit occupying soldiers, or another player's recruits, for free.

**`RpcAsk_RecruitFromTent`** (`:847-864`) never checks `CanRecruit` before spawning; at the 16-recruit cap, `RecruitCivilian()` (`OVT_RecruitManagerComponent.c:786`) returns early, leaving an **unowned freshly-spawned civilian** standing at the tent. `TakeSupportersFromNearestTown` silently no-ops when the town has no supporters (`OVT_TownManagerComponent.c:1194`) but the recruit spawns anyway — the supporter cost is skippable. Money for both paths is checked and charged **client-side only**.

Same class as BUG-025 / BUG-043 / BUG-047 / BUG-048.

**Impact:** free recruits (including recruiting enemy soldiers) from modified clients; orphan civilians accumulating at tents; cost/effect decoupling for honest players.

Fix shape: one server-side transaction per path — derive the player from the RPC sender, validate faction == civilian + not-already-recruited + range, re-check cap/supporters/money server-side, and only then spawn/convert; abort (with refund/notification) otherwise.
