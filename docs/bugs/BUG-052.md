**Found by:** resistance epic discovery (`/discover-feature resistance/recruits`, 2026-08-02).

`OVT_RecruitsContext.c:443` calls `m_RecruitManager.RenameRecruit()` directly from the UI. No rename RPC exists anywhere in `OVT_PlayerCommsComponent` (grep-verified). On a dedicated server this mutates only the client's replica of the recruit table: the server's authoritative record, persistence, and every other client keep the old name — and the next `RpcDo_RecruitUpdated` broadcast or a rejoin reverts it on the renaming client too.

**Impact:** a headline recruit-management feature silently broken for all non-host players; names revert seemingly at random.

Fix shape: add `RpcAsk_RenameRecruit(recruitId, name)` with server-side ownership + length validation, apply on the server table, then broadcast the update (the existing `RpcDo_RecruitUpdated` path already carries it).
