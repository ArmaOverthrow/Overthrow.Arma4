**Found by:** resistance epic discovery (`/discover-feature resistance/recruits`, 2026-08-02).

`OVT_PlayerCommsComponent.c:985-992`: the fast-travel RPC calls `SCR_Global.TeleportPlayer` — which applies the transform **synchronously** (base game `Functions.c:1677-1680`) — and only *then* queries `GetPlayerRecruitEntitiesInRadius(playerEntity.GetOrigin(), radius)`. By that point the origin *is* the destination, so the recruits standing at the departure point are never found and never teleported.

Meanwhile the client has already charged per-recruit fast-travel fees (`OVT_MapContext.c:390,466`) before the request.

**Impact:** recruits are stranded at the departure point on every recruit fast-travel; the player pays for companions who don't arrive (and must walk back or re-gather them).

Fix shape: capture the player's position into a local **before** the teleport and search around that; longer-term, move the fee charge server-side next to the actual teleport (see the client-payment class in BUG-047/BUG-048/BUG-051).
