**Found during:** BUG-020 fix (`/fix-feature economy`, 2026-08-03).

The generic money RPCs in `OVT_PlayerCommsComponent` (`RpcAsk_AddPlayerMoney`, `RpcAsk_TakePlayerMoney`) credit/debit **whatever amount the client sends** with no server-side validation. The shop sell path no longer uses them (BUG-020 moved it to a server-authoritative `RpcAsk_Sell`), but they remain client-reachable, and `OVT_ResistanceMenuContext.c:237,258` still legitimately uses `AddPlayerMoney` for resistance-funds→player transfers with the resistance debit done client-side — the same client-trusted shape BUG-020/BUG-021 had.

**Fix shape:** replace the ResistanceMenuContext flow with a validated ask (server-side officer check, funds check, atomic debit resistance + credit player), then either remove the generic `RpcAsk_AddPlayerMoney`/`RpcAsk_TakePlayerMoney` RPCs or reduce them to server-internal helpers (the `addingMoney`/`takingMoney` client latches — which can also permanently deadlock a client's money ops if an owner-RPC drops — go with them).

**Impact:** a modified client on a dedicated server can still grant itself arbitrary money via one RPC; the resistance transfer UI is the remaining legitimate caller keeping the surface open.
