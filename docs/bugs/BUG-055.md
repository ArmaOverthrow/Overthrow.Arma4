**Found by:** towns epic discovery (`/discover-feature towns/core` + `towns/gun-dealers`, 2026-08-02).

`OVT_TownManagerComponent.GetRandomUnownedHouseInTown` (`:726-733`) runs the unowned-house query then immediately `return GetGame().GetWorld().FindEntityByID(m_Houses.GetRandomElement());` with no `m_Houses.Count() == 0` guard. Its sibling `GetRandomUnownedHouse` (`:688-690`) *does* guard — the omission is an inconsistency, not a design choice.

**Reached from:**
1. `OVT_TownController.SpawnGunDealer` (`OVT_TownController.c:252`) — the tier-3 fallback every shipped dealer uses (tier 2 is dead code).
2. `OVT_FindRandomHouseJobStage.OnStart` (`:7`) — already noted in BUG-041's path 2.

**Failure scenario:** a town where every house is player-owned (normal late-campaign state), or whose houses all sit outside the manager's deprecated 400 m `m_iTownRange` (the dealer search uses the controller's 800 m range, the fallback uses the manager's 400 m — a mismatch that makes this reachable on wide towns) → `GetRandomElement()` on an empty array → VM exception on the campaign-start/continue frame, aborting `SpawnGunDealer` and the rest of that town's activation. The defensive "No gun dealer locations found" print at `OVT_TownController.c:263` is effectively unreachable — the crash happens first.

**Fix shape:** one guard returning null + null-checks at the two call sites (the controller already has a graceful no-dealer path; the job stage needs BUG-041's false-with-warning treatment).
