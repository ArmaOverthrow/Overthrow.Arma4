**Found by:** towns epic discovery (`/discover-feature towns/stability`, 2026-08-02).

`OVT_TownModifierSystem.OnTick` (`Scripts/Game/GameMode/Systems/OVT_TownModifierSystem.c:61`) skips permanent entries (`if(mod.timeout <= 0) continue;`) **before** they can be inserted into the `rebuild` list; when any other modifier in the town times out, `:85-94` does `modifiers.Clear()` and re-inserts only `rebuild` — every permanent modifier vanishes server-side. No `RpcDo_Remove*Modifier` is sent for the dropped entries, so clients keep the chips forever, and when the handler re-adds one later, clients accumulate duplicates.

**Failure scenario:** a town has 3 × PatrolHarassment (timeout 0, −6 total) and 1 × CivilianDeath (30 min). The CivilianDeath timer expires → the rebuild wipes all three PatrolHarassment stacks → stability jumps to 100 while the enemy patrol still stands in the square; every client's map panel still shows three harassment chips. The support system's permanent entries (`NearbyRadioTower*`, `NearbyBase*`, `GrowingDiscontent`) hit the same mechanism — the proximity ones partly self-heal because the manager re-adds them every 10 s tick, `GrowingDiscontent` does not (compounded by BUG-058).

**Fix shape:** insert permanent entries into `rebuild` (move the `continue` after the insert), and broadcast removes for anything genuinely dropped. Commit `2587e9c` ("Fixes null town modifiers on array rebuild") shows this rebuild has bitten before.

**Test note:** one Logic-tier case with a permanent + an expiring modifier through `OnTick` would pin this — currently `OnTick` has zero coverage.
