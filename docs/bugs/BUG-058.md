**Found by:** towns epic discovery (`/discover-feature towns/stability` + `towns/support`, 2026-08-02).

`OVT_PatrolHarassmentStabilityModifier` (`Stability/OVT_PatrolHarassmentStabilityModifier.c:3,14-17`) and `OVT_GrowingDiscontentSupportModifier` (`Support/OVT_GrowingDiscontentSupportModifier.c:4,15-18`) both gate their per-in-game-hour work on an instance field (`m_iLastCheckedHour`). But each config's handler is a **single shared object** — `OVT_TownModifierSystem.OnTick` (`:97-103`) calls `config.handler.OnTick(town)` for every town off that one instance. The first town processed in an hour sets the field; every other town early-returns for the rest of that hour.

**Failure scenario:** 12 towns, 8 below 30 stability. Only `m_Towns[0]` ever accrues GrowingDiscontent; the other 7 destabilised towns get zero discontent support all campaign. Equally, the *removal* branch never runs for them, so any stacks they acquired in a session where they happened to be first are permanent (timeout 0 — and see BUG-057 for the opposite failure). Same for patrol harassment: only town[0] ever gains or sheds it.

**Fix shape:** key the gate per town (`map<int,int>` townId → last-checked-hour), or move the hour gate into the system tick.

**Test note:** a two-town Logic fixture driving `OnTick` twice in one "hour" pins this.
