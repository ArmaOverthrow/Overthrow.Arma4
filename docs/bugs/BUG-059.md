**Found by:** towns epic discovery (`/discover-feature towns/stability`, 2026-08-02).

`OVT_TownManagerComponent.Init()` calls `system.Init()` for each modifier system (`:178-181`) **before** `InitializeTowns()` (`:183`). `system.Init()` → `LoadConfig()` → `PostInit()`, which iterates `m_Towns` to call every handler's `OnStart(town)` (`OVT_TownModifierSystem.c:43-46`) — while the list is still empty. `OnStart` therefore never executes for any handler.

**Impact:** `OVT_RandomStabilityModifier`'s `m_fGameStartFactor` (30× CorruptMayor, 20× OrganizedCrime, 30× DrugProblems — the "towns start with problems" seeding) never applies. Every campaign opens with every town at a flat 100 stability, and any future handler relying on per-town `OnStart` setup is silently skipped.

**Fix shape:** call `InitializeTowns()` before the systems' `Init()` loop, or defer the `OnStart` fan-out to `PostGameStart` (which is also where the tick starts). Watch the client/server split: `LoadConfig` must still run on all machines, `PostInit`'s handler bootstrap stays server-only.
