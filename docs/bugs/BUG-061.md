**Found by:** towns epic discovery (`/discover-feature towns/core`, 2026-08-02).

On maps without authored `OVT_TownController` prefabs, the deprecated auto-detection path spawns controller prefabs at each detected town (`OVT_TownManagerComponent.SpawnTownControllers`, `:1016-1032`) and pushes name/size/pop/range into the fresh components — but **never inserts them into `m_TownControllers`**. That array is only populated by the defined-town discovery path (`FilterTownControllerEntities:1132-1134`).

`OVT_OccupyingFactionManager.StartTownQRF` (`:754`) does `townManager.m_TownControllers.Get(townID)` to read the town's QRF attack geometry. On a legacy map the array is empty → out-of-range `Get` on the first town QRF of the campaign.

**Also unguarded:** `PostGameStart`'s activation loop (`:199-204`) dereferences `FindEntityByID` + `Cast` results with no null checks — a destroyed/unstreamed controller aborts activation for every remaining town.

**Impact:** community/modded maps relying on the (still advertised, deprecation-warned) auto-detect path get a mid-campaign crash; on authored maps only the unguarded activation loop remains a hazard.

**Fix shape:** either insert spawned controllers into `m_TownControllers` (restoring the index-alignment contract) or formally drop the legacy path with a clear startup error; null-guard the activation loop either way.
