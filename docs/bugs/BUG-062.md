**Found by:** towns epic discovery (`/discover-feature towns/core` + `towns/support`, 2026-08-02).

`OVT_TownManagerComponent.GetNearestTownInRange` (`:792-806`) is a plain `foreach` that returns the **first** town whose distance is within its size-derived range — not the nearest. Array order is world-query order, i.e. arbitrary but stable, so the mis-attribution is deterministic: always the same wrong town.

**Callers affected:** `OVT_StabilityModifier.AddModifierToNearestTownInRange` / `OVT_SupportModifier` (civilian deaths −5 stability / −20 support-rate, OF deaths −5 / +5) — every death-driven modifier. The ranges are the deprecated component attributes (city 600 / town 400 / village 250), so on dense map regions two towns' radii routinely overlap.

**Failure scenario:** a village and a town 300 m apart; a civilian dies 200 m from the village and 380 m from the town. If the town precedes the village in `m_Towns`, the town eats the CivilianDeath penalty and the village never does — every time, for the whole campaign.

**Fix shape:** track the minimum distance across all in-range towns (mirror `GetNearestTown`'s loop with the range check), and add the missing Logic-tier case — this function currently has zero coverage and a test would have exposed it immediately.
