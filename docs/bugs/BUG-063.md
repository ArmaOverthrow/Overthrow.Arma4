**Found by:** towns epic discovery (`/discover-feature towns/support`, 2026-08-02). Same client-trust class as BUG-034/BUG-047/BUG-054.

`OVT_ConvertSupporterAction.PerformCivilianAction` (`OVT_ConvertSupporterAction.c:4-18`) rolls `s_AIRandomGenerator.RandFloat01() < player.diplomacy` **on the client**, then calls `OVT_Global.GetServer().AddSupporters(pos, 1)`. The server side (`OVT_PlayerCommsComponent.c:88-92`) is a bare pass-through: `RpcAsk_AddSupporters(vector location, int num)` → `AddSupport(location, num)` — no distance check, no diplomacy re-roll, no rate limit, no clamp (see BUG-064), no null/range check on `GetNearestTown`.

**Failure scenarios:**
- A modified client calls `RpcAsk_AddSupporters(anyTownLocation, 9999)` and instantly flips every village on the map (support% ≥ 85 flips are certain).
- Even unmodified: `MarkAsPerformed()` is client-local on a `HasLocalEffectOnlyScript()` action, so in co-op **every player can convert the same civilian**, and the flag doesn't survive the town controller's civilian despawn/respawn cycle — the same civilian is re-convertible every presence cycle.

**Fix shape:** move the roll server-side (server-held `OVT_PlayerData.diplomacy`), validate the civilian entity + interaction distance instead of a raw location, cap `num` to 1, and rate-limit per player. Replicate or server-track the per-civilian performed flag if one-attempt semantics matter.
