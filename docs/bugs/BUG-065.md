**Found by:** towns epic discovery (`/discover-feature towns/support`, 2026-08-02).

`Configs/Modifiers/supportModifiers.conf:94-102` gives `RevolutionaryMomentum` (+10, 3600 s) `flags 3` (STACKABLE) with **no `stackLimit`**, so the `[Attribute]` default 5 applies. `OVT_RevolutionaryMomentumSupportModifier.UpdateAllTownMomentum` (`:29-80`) runs on **every** town-control change and calls `TryAddSupportModifier` for each qualifying town — each flip adds another stack; `RemoveSupportModifier` removes exactly one.

**Failure scenario:** the player flips five villages in sequence. Every non-resistance town within 2 km of any resistance town accumulates 5 stacks = **+50** support-rate — combined with posters (+25) that clears the +75 deterministic-gain threshold, guaranteeing +1 supporter every 70 s regardless of RNG. Conversely, losing a town removes one stack, so momentum decays 5× slower than it built — sticky in the wrong direction. Contrast `RecentBattlePositive`/`NearbyBasePositive`, which correctly use `flags 1` (non-stackable).

**Fix shape:** `flags 1` on the config entry (one-line), or an explicit `stackLimit 1`. Note the config-index identity: edit the entry in place, never reorder the file (saves persist indices).
