**Found by:** towns epic discovery (`/discover-feature towns/map-info`, 2026-08-02).

`OVT_MapIcons.c:29-31` sets `m_fRefreshInterval = 3.0` and `m_fRetryInterval = 1.0` (intended seconds), but `:261` compares them against `GetGame().GetWorld().GetWorldTime()` — which returns **milliseconds** (`BaseWorld.c:244-245` in the vanilla reference tree). Any elapsed time ≥ 3 ms passes the check, i.e. every frame.

**Impact:** with the map open, `ValidateReplicationReferences()` (`:347-418`) walks `GetGunDealers()` + `GetAllShops()` + `GetAllPorts()` doing `Replication.FindItem` → `GetEntity()` → `GetWorld()` per entry — several hundred lookups **per frame** on a populated Everon — and `RetryFailedIcons()` re-attempts every failed icon per frame (with `Print` calls on failures, so the log floods too). The hit is worst on clients with slow-resolving RplIds, which is exactly when the failed lists are non-empty.

**Fix shape:** multiply the intervals by 1000 (or divide the world time) — two lines. Consider demoting the validation-failure `Print`s at the same time.
