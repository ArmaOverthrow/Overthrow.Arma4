**Found by:** towns epic discovery (`/discover-feature towns/map-info`, 2026-08-02).

`OVT_MapIcons` positions icons by index across parallel arrays, and two construction patterns break the alignment:

1. **POI registry vs widget list.** The build loop (`OVT_MapIcons.c:488-505`) `continue`s past a POI when `m_bMustOwnBase` and the nearest base is enemy-held, or when `CreateWidgets` returns null — but the update loop (`:309-343`) does `foreach(int i, Widget w : m_POIWidgets) { OVT_MapPOIData poi = m_aPOIs[i]; }`, indexing the **unfiltered static registry** by widget position. The moment one POI is skipped, every subsequent widget is positioned at the wrong POI's coordinates and re-skinned with the wrong icon (`poi.m_UiInfo.SetIconTo` at `:331`). `m_bMustOwnBase` POIs (base garages/armouries) are common and flip as bases change hands — this is a live shifting-icons bug, not a corner case. The bounds guard at `:311` only prevents the crash, not the misalignment.
2. **Insert-before-validate.** Gun-dealer (`:119-124`), shop (`:145-150`), port (`:196-201`), fallback (`:224-232`) and owned-house (`:526-530`) blocks all do `m_Centers.Insert(...); m_Ranges.Insert(...);` **before** `CreateWidgets` is null-checked — one failed creation shifts every subsequent icon's position and zoom ceiling.

**Related in the same file:** the owned-house zoom ceiling truncates `m_fCeiling` (0.6) into an `int` (`:520`) so every owned house is always visible (the `IsHome → range 0` branch is a no-op); the job-waypoint block `return`s instead of `continue`s on a failed widget (`:780-781`), skipping all fallback icons.

**Fix shape:** insert into the parallel arrays only after successful creation; iterate POIs with an explicit index pairing (store the POI index alongside the widget); `float range`; `continue` not `return`.
