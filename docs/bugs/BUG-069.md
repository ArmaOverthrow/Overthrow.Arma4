**Found by:** towns epic discovery (`/discover-feature towns/map-info`, 2026-08-02).

Four related lifecycle defects in `OVT_MapContext`:

1. **Two unequal close paths.** The input handler `MapExit` (`OVT_MapContext.c:341-349`) closes the layout + all three modes + the map. The engine's map-close invoker path `OnMapExit` (`:300-304`) calls only `DisableMapInfo()` + `DisableFastTravel()` — **no `CloseLayout()`, no `DisableBusTravel()`**. Closing the map any way that bypasses the input listener (holstering the map gadget, death, another menu force-closing it) leaves the town-info panel stuck on screen (`m_wRoot` never removed, `m_bIsActive` stays true; `MapExit`'s mode-flag guard then early-returns forever).
2. **Bus mode survives close.** After an engine-side close, `m_bBusTravelActive` stays set — the next `MapSelect` click on any subsequent map open executes the bus-travel branch and charges a fare.
3. **Panel stacking.** `m_bOpenActionCloses 0` (`Character_Player.et:41`) disables the close-on-reopen short-circuit and `ShowLayout` overwrites `m_wRoot` unconditionally — with map info open, choosing "Map Info" from the (still reachable) main menu creates a second panel and orphans the first; repeatable to N panels.
4. **Listener leak.** `PostInit` (`:34`) inserts `OnMapExit` into the **static** `SCR_MapEntity.GetOnMapClose()` invoker and nothing ever removes it; `PostInit` runs per character entity, so every respawn adds another listener bound to a dead context (stale `m_Owner`/`m_wRoot` dereferences waiting to happen).

**Fix shape:** make `OnMapExit` the single teardown (layout + all three modes) and have `MapExit` call it; remove the invoker subscription on context teardown/control change; either honour `m_bOpenActionCloses` or close the existing layout in `ShowLayout`.
