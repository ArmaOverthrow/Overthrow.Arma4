**Found by:** towns epic discovery (`/discover-feature towns/map-info`, 2026-08-02).

**Drawn** (`OVT_MapRestrictedAreas.c`): occupying bases at `baseCloseRange` (`:69`), occupying-held radio towers at 20 m (`:78`); resistance-held bases and towers are explicitly skipped (`:61-64`, `:74-76`) — no circle.

**Enforced:** the FOB deploy check — client (`OVT_DeployFOBAction.c:36,50`) and server (`OVT_ResistanceFactionManager.c:436,449`) — rejects within `baseCloseRange + 50` of **any** base and within `20 + 50 = 70` m of **any** radio tower, regardless of controlling faction. The server-side rejection is silent by design ("Silently fail - client should have already validated").

**Failure scenario:** the player parks the mobile FOB just outside the red ring (or anywhere near a resistance-held base/tower, which shows no ring) and deploys. The client-side pre-check may pass or fail inconsistently with the drawing; if the request reaches the server it is dropped with **zero feedback** — the truck just doesn't deploy, reading as a bug every time.

Three mismatches: (a) +50 m invisible margin on every base; (b) towers drawn at 20 m, enforced at 70 m; (c) friendly bases/towers enforced but never drawn.

**Fix shape:** draw the enforced radii (`baseCloseRange + 50`, 70 m) and include friendly sites (different colour if the distinction matters), and/or add a server → client rejection notification on the deploy path. Coordinate with the resistance epic (deploy validation) — the constants should come from one place.
