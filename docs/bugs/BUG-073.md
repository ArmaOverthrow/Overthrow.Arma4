**Found by:** resistance epic discovery (`/discover-feature resistance/wanted-system`, 2026-08-03).

Four related authority defects in `OVT_PlayerWantedComponent`:

1. **Client-authoritative player wanted level.** The 1 Hz tick is gated by `if(!GetRpl().IsOwner()) return;` (`:202-204`), and for a player character the owner is the controlling client. All four `[RplProp]`s are mutated there via `Replication.BumpMe()` — but RplProps replicate server→client only, so client-side writes never propagate. Meanwhile `SCR_CharacterDamageManagerComponent` and `SCR_AIConfigComponent` write the same props **on the server**. Two writers, one authority.
2. **Double-registered tick.** At `OnPostInit` on a dedicated server the character is still server-owned (ownership transfers later in `SCR_PlayerController`), so the `CallLater` very likely registers on **both** server and client. The server's values overwriting the client's is why the system appears to work — at the cost of running the full detection scan twice per player and allowing transient divergence between what the client HUD shows and what the server enforces.
3. **`m_bIsDisguised` is not replicated at all** (plain bool, only written inside the tick) yet is read client-side by the HUD (`OVT_WantedInfo`) and server-side by `SCR_CharacterDamageManagerComponent` — whichever machine doesn't tick sees a permanently false disguise state.
4. **`EnableWantedSystem()` (`:167-170`) never calls `Replication.BumpMe()`** (and `m_bWantedSystemEnabled` is declared `float` at `:13-14` despite the `m_b` prefix), so re-enabling after the spawn grace or recruitment doesn't reach proxies.

**Impact:** hosted play mostly masks it; on dedicated servers it produces doubled scan cost, client/server disagreement on wanted/disguise state (HUD shows undercover while the server treats you as blown, or vice versa), and a state model that any future change can silently break. Same "works hosted, degrades dedicated" class as BUG-045/049/052.

**Fix shape:** make the server the single writer — run the tick on the authority for all characters (drop the owner gate or invert it to `IsMaster()`), promote `m_bIsDisguised` to a RplProp, fix the enabled flag's type and bump on enable/disable. The client only needs the RplProps it already reads.
