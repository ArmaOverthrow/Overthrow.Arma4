**Found by:** resistance epic discovery (`/discover-feature resistance/wanted-system`, 2026-08-03).

`OVT_PlayerWantedComponent.OnPlayerLoot(IEntity player)` (`:210-221`) subscribes to the global `OVT_OccupyingFactionManager.m_OnPlayerLoot` invoker but never compares the `player` parameter to `GetOwner()` — every subscribed component reacts to **any** loot event. `SCR_LootAction` (`:15`) is `HasLocalEffectOnlyScript() == true`, so on a dedicated client only the local player's component is subscribed and it happens to work. But on a **listen host** the server owns every recruit and dormant town civilian, so all their components tick locally and are all subscribed: the host looting a single body makes every currently-seen recruit (and any not-yet-disabled civilian) jump to wanted level 2 with a `WantedHostileFaction`-style escalation they did nothing to earn.

**Impact:** hosted-MP recruits spuriously become wanted (and therefore hostile targets for the OF) when the host loots; combined with recruits' independent wanted decay this reads as random AI aggro against your own squad.

**Fix shape:** first line of `OnPlayerLoot`: `if (player != GetOwner()) return;`. (The subscription itself also leaks — see BUG-075.)
