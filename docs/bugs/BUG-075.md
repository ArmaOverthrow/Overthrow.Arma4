**Found by:** resistance epic discovery (`/discover-feature resistance/wanted-system`, 2026-08-03).

`OVT_PlayerWantedComponent` inserts `OnPlayerLoot` into `OVT_OccupyingFactionManager.m_OnPlayerLoot` during init, but `OnDelete` (`:805-808`) only removes the call-queue tick — the `ScriptInvoker` subscription is never `Remove()`d. The manager-held invoker therefore accumulates a reference to every wanted component ever created: every dead player body cleanup, every despawned recruit, every town civilian that despawns with its cell.

**Impact:** unbounded growth over a long session (town civilians churn constantly — every `Character_CIV.et` carries the component), plus invoke-on-deleted-component risk each time anyone loots. Severity is capped because the handler body is short, but it is a textbook invoker leak per the project's own memory-management patterns.

**Fix shape:** mirror the insert with `m_OnPlayerLoot.Remove(OnPlayerLoot)` in `OnDelete`, alongside the existing `CallQueue.Remove`.
