**Found by:** resistance epic discovery (`/discover-feature resistance/wanted-system`, 2026-08-03).

Two related defects in `OVT_PlayerWantedComponent`'s decay state machine (`:462-479`):

1. **Timer carry-over.** When decaying 2→1 the timer is reset to `wantedOneTimeout` (120 000 ms default). If you are then re-seen, `:477-479` jumps the level back to 2 via `SetWantedLevel(2)` — but leaves the timer untouched, so the next decay from level 2 takes up to 120 s instead of `wantedTimeout` (30 s). The same applies to `SetBaseWantedLevel` escalations mid-countdown: raising the level does not restart the timer, so a freshly-escalated level can decay almost immediately if the timer was nearly expired.
2. **Silent re-escalation.** The `:478` jump uses the unconditional `SetWantedLevel` rather than `SetBaseWantedLevel(2, reason)`, bypassing the notification path — the player gets stars back with no message explaining why.

**Impact:** inconsistent decay pacing (sometimes 4× the difficulty-configured timeout, sometimes near-instant decay after an escalation) and an unexplained HUD state change. Gameplay-fairness noise rather than a break, hence low priority.

**Fix shape:** reset `m_iWantedTimer` to the level-appropriate timeout whenever the level *increases* (in `SetBaseWantedLevel` and the `:477-479` branch), and route the re-escalation through the notification path with a reason tag.
