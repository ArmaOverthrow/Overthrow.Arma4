**Found by:** resistance epic discovery (`/discover-feature resistance/wanted-system`, 2026-08-03).

BUG-013 (closed) fixed clients reading unreplicated difficulty fields by adding `wantedTimeout`, `wantedOneTimeout`, `disguiseDetectionDistance` and `baseCloseRange` to `OVT_OverthrowConfigComponent`'s hand-rolled `RplSave`/`RplLoad` bitstream (`:544-553`, `:592-595`). The residue: `OVT_PlayerWantedComponent` still reads these on whatever machine ticks (`:249` disguise distance, `:443` base range, decay timeouts at `:462-479`), and the stream is **positional and unversioned** — every field must be written and read in exactly matching order across client/server builds, with no marker to detect a mismatch.

**Impact:** latent, not active. Any future edit that adds/removes/reorders a field in only one of the two functions (or a client running a different mod version than the server) silently shifts every subsequent field, giving clients garbage wanted timeouts/ranges with no error. The failure mode is invisible in testing because hosted play never exercises the stream.

**Fix shape:** minimal — keep write/read adjacent with a comment pinning the order and add a leading version/magic int that `RplLoad` validates; larger — migrate the difficulty block to `[RplProp]`s on the config component so the engine owns the encoding.
