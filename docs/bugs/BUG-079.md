**Found by:** BUG-007 investigation (2026-08-03) — seen in `.tmp/run-tests/crash.log` of an All-group run (`{6A6E2A002F53A581}`), repeated VM exceptions during the persistence tier.

```
Reason: NULL pointer to instance. Variable '#array' during call 'array<@EntityID>.Count'
Class:    'OVT_BaseUpgradeDefensePatrol'
Function: 'GetResources'
Stack trace:
Scripts/Game/Controllers/OccupyingFaction/BaseUpgrades/OVT_BasePatrolUpgrade.c:144 Function GetResources
Scripts/Game/Controllers/OccupyingFaction/BaseUpgrades/OVT_BaseUpgrade.c:66 Function Serialize
Scripts/Game/Controllers/OccupyingFaction/BaseUpgrades/OVT_BasePatrolUpgrade.c:188 Function Serialize
Scripts/Game/Persistence/Serializers/Components/OVT_OccupyingFactionManagerSerializer.c:230 Function WriteBase
Scripts/Game/Persistence/Serializers/Components/OVT_OccupyingFactionManagerSerializer.c:139 Function Serialize
```

`OVT_BasePatrolUpgrade.GetResources()` (line 144) iterates/counts `m_Groups` while it is null — presumably the upgrade's `PostInit()` never ran (or ran on a different instance) before the occupying-faction serializer walked base upgrades on save. Tests still pass (exceptions are non-fatal, `noThrow`), but every save emits VM exceptions and the serialized resource total for that upgrade is wrong/absent. Needs a null guard or guaranteed init of `m_Groups` before `Serialize()` can be reached.
