Play-testing the shop-ux Sell mode: worn clothing appeared in the sell list and could be sold; deleting the worn container silently deleted its contents.

**Root cause (evidence, not inference):** vanilla `Character_Base.et:176` declares the character loadout storage with `StoragePurpose 0x9` = `PURPOSE_DEPOSIT | PURPOSE_LOADOUT_PROXY` — so the engine's `GetItems(PURPOSE_DEPOSIT)` legitimately returns worn uniform/vest/backpack (and dog tags + held gadgets via two other storages that never clear the default 0x1). The plan's arsenal precedent used the same mask for loadout *validation*, where including worn gear is intended — it was never a safe-to-delete partition. Bonus finding: `EStoragePurpose` ordinals and flag bits diverge from GADGET_PROXY on, so `& PURPOSE_DEPOSIT` idioms elsewhere in the codebase work by luck.

**Fix (built 2026-08-04, compile + All 52/52 green):** `OVT_SellableItemScanner.CollectUnequippedItems` keeps the mask as a cheap first pass, then post-filters every item through a hardened `IsEquipped` — class-cast classification (in-hands incl. left-hand gadget, worn-cloth check, LoadoutSlotInfo/EquipmentStorageSlot/HandSlot slots, equipped-weapon/loadout/hand-slot storages) with fail-safe → equipped (under-sell, never over-sell). Client and server share the classifier; vehicle cargo path deliberately untouched.

**Pending:** runtime play-test confirm — worn/slung/held gear absent from Sell; backpack contents (incl. spare uniform) still sellable; Sell All leaves loadout intact; MP client sell matches server.
