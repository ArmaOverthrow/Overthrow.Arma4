**Found by:** design discussion during the 2026-08-04 no-cheat play-through (not a regression — the counter-mechanic never existed).

Posters and the new pirate radio transmitter (added 2026-08-04) are placed as physical entities and grant town support modifiers via `OVT_PlaceableSupportModHandler`, but the occupying faction never interacts with them: patrols walk straight past hostile propaganda. The only pressure on these placeables is the modifier's own timeout — the physical objects persist forever and the player just re-places/refreshes on a timer, which is busywork rather than risk.

**Desired shape (per design discussion):** patrols that come within perception range of an illegal placeable (`OVT_Placeable.m_bIllegal 1` — posters, pirate radio; declarative, added 2026-08-04) should remove it after a short interaction, and removal should also remove/decrement the linked support modifier stack (posters: one stack per poster; pirate radio: the whole modifier). This should be **built into the deployments system** (`Scripts/Game/GameMode/Deployments/`) rather than bolted onto the wanted component's per-character scan — the deployment/patrol side owns "what does a patrol do when it finds X".

Notes for the implementer:
- `OVT_PlaceableSupportModHandler.OnPlace` only ever ADDS modifiers; there is no removal path linking a placed entity back to its modifier stack. That linkage (entity → town + modifier name) needs to exist first.
- `RemoveSupportModifierByName` removes exactly one stack — correct for posters.
- Placed entities are tracked by `OVT_PersistenceTracking` and carry `OVT_PlaceableComponent` (owner uid) — deletion must go through the same server-side path the removal mode uses (`RemovePlacedItem`) so persistence stays consistent.
