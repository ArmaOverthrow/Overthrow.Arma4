**Found by:** reading the engine log while verifying the radio-tower sabotage job (`jobs/core`, 2026-08-06). Visible in every run, including the autotest runs:

```
17:40:57.318   WORLD   (E): Unknown class 'OVT_HireGunnerAction' at offset 232(0xe8)
```

Commit `5793c47b` ("Remove Recruit Gunner functionality", 2025-06-18) deleted
`Scripts/Game/UserActions/OVT_HireGunnerAction.c` and cleaned the action out of
`Prefabs/Weapons/Core/Turret_Base.et`, but missed the second reference in
`Prefabs/Vehicles/Wheeled/BTR70/BTR70.et:6`, which still carries the whole orphaned block:

```
  ActionsManagerComponent "{C97BE5489221AE18}" {
   additionalActions {
    OVT_HireGunnerAction "{5DA6925BDEA42B49}" {
     ParentContextList {
      "door_l01" "door_r01"
     }
     UIInfo UIInfo "{5DA6925BA36FD17C}" {
      Name "#OVT-RecruitGunner"
     }
     "Sort Priority" 1000
    }
   }
  }
```

**Impact:** low but not zero. The engine logs an error every time the prefab is parsed, which is
noise in every log a developer or CI reads. The deserializer stops at the unknown class at that
offset, so the surrounding `ActionsManagerComponent` block is what absorbs the damage — worth
confirming by hand that the BTR70's remaining door actions (enter/lock/etc.) still appear in game,
since this is the only component the prefab declares.

**Fix:** delete the orphaned `ActionsManagerComponent` block from `BTR70.et` (the whole thing — its
only content is the dead action), or re-point it at a surviving action if the BTR70 was supposed to
keep a door action the other vehicles have. `#OVT-RecruitGunner` in
`Language/localization_Overthrow.st` is then also unreferenced.

**How to confirm the fix:** the string `OVT_HireGunnerAction` should return no hits repo-wide, and
`grep "Unknown class" .tmp/run-tests/console.log` after `tools/run-tests.sh` should show only the
two unrelated base-game `SCR_WidgetExportRuleRoot` lines.
