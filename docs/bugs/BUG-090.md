## Summary

The Enfusion engine **never loops an `Rpc(...)` call back to the sender**. On a listen-server host, the server and the owning client are the same process, so an `[RplRpc(RplChannel.Reliable, RplRcver.Owner)]` sent from the server to the host's own controller is silently dropped — the host receives nothing.

At least two existing controller components send owner-targeted RPCs **without** a host direct-call branch:

- `Scripts/Game/Components/Controller/OVT_BaseServerProgressComponent.c` — base transfer/capture progress
- `Scripts/Game/Components/Controller/OVT_ShopTransactionComponent.c` → `RpcDo_SellResult`

## Expected

A player hosting a listen server sees their own sell results and base-transfer progress, exactly as a remote client does.

## Actual (predicted from code reading — not yet play-test confirmed)

The host sees nothing from these paths. Remote clients are unaffected. This would present as "sell toast never appears when I host" and "transfer progress bar never moves when I host" — symptoms easy to misattribute to the shop or base logic rather than to RPC routing.

## How it was found

Discovered while implementing `new-player-experience/tutorial-system` Phase 3 (owner-RPC delivery). The tutorial system hit the same wall and had to add the missing branch:

```
Notify(entryId):
    guard Replication.IsServer()
    if this controller belongs to the LOCAL player   -> call RpcDo_ShowTutorial(entryId) directly
    else                                             -> Rpc(RpcDo_ShowTutorial, entryId)
```

Without that branch the host received **zero** tutorial popups. The same comment appears on BUG-035.

## Suggested fix

Apply the same local-player direct-call branch in both components' server-side send wrappers. Small change; the shape is already proven in `OVT_TutorialComponent.Notify()`.

## Verification needed

Confirm the symptom first — it is a code-reading prediction, not an observed failure:

1. Host a listen server (not a dedicated server) as the only player.
2. Sell something at a shop — does the sell result appear?
3. Start a base transfer — does the progress bar move?
4. Repeat both on a **dedicated** server with a remote client, which should work today.

## Notes

- Not introduced by tutorial-system; pre-existing and out of that feature's scope.
- A dedicated server has no local player, so this bug is invisible there — which is likely why it has survived.
- Worth grepping for other `RplRcver.Owner` senders with the same gap before closing.
