## Summary

`OverthrowShopPrevCategory` and `OverthrowWarehouseTakeAll` are bound to `gamepad0:shoulder_left`. The base game's `VONContext` holds `shoulder_left` (`VONChannel`, `VONDirectToggle`, plus the LB+A / LB+B / LB+X combos) at **priority 110**, which outranks every Overthrow menu context (priority 50) and is live every frame while the player is alive and conscious (`SCR_VONController.Update:963-964`).

So on a gamepad, paging shop categories or using warehouse take-all plausibly also keys the radio.

## Expected

LB pages shop categories / triggers warehouse take-all, with no VON side effect.

## Actual (predicted from code reading — not yet play-test confirmed)

Both fire. VON wins the priority contest, so the radio may key and the menu action may not register at all.

## Why the conflict checker misses it

`.claude/skills/overthrow-ui-patterns/scripts/check-input-conflicts.py` reads the top-level `Actions` block plus `ActionRefs` lists. The base conf additionally declares **197 actions inline inside `ActionContext` blocks**:

```
ActionContext X { Actions { Action Y { … } } }
```

Those are live in that context but appear in **no** `ActionRefs` list, so the checker cannot see them. This is a cross-context *and* inline case, so it is doubly invisible.

## How it was found

Found while implementing `new-player-experience/tutorial-system` Phase 6, doing a combo-aware **and inline-aware** re-survey of both `chimeraInputCommon.conf` files. That survey also falsified an earlier assumption in the same feature that `KC_T`, `KC_K`, `KC_O` and `shoulder_left` were free — all four are bound by inline-declared actions (VON push-to-talk, compass, watch).

## Suggested fix

Two parts, independently useful:

1. Rebind these two Overthrow menu actions off `shoulder_left`.
2. **Teach `check-input-conflicts.py` to parse inline `ActionContext { Actions { … } }` declarations.** Until it does, its output understates real collisions and any "no new conflicts" gate built on it is weaker than it reads. This is the higher-value half.

## Verification needed

1. On a gamepad, open the shop, press LB to page categories — does the radio key? Does the category actually change?
2. Same in the warehouse with take-all.
3. Confirm the actions work correctly on keyboard, isolating the issue to the pad binding.
