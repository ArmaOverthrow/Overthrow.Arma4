## Resolution (2026-08-08): Closed — not a bug, report misread the enclosing method

The cited `Insert` at `:33` is inside **`OnShow()`** (which starts at line 20), not `PostInit` — the context never overrides `PostInit` at all. Verified on both `main` (`Insert(Refresh)`) and `new-player-experience` (`Insert(OnSkillChanged)`): subscribe in `OnShow`, unsubscribe in `OnClose`, and the base `OVT_UIContext` calls `OnShow()` from every `ShowLayout()` (`OVT_UIContext.c:156`) and `OnClose()` from every `CloseLayout()` (`OVT_UIContext.c:184`), including the reopen-while-active path. The lifecycle is already symmetric; the "suggested fix" describes the code as it already is. No code change made.

## Summary

`OVT_CharacterSheetContext` subscribes to `m_OnPlayerSkill` in **`PostInit`** (`:33`) but unsubscribes in **`OnClose`** (`:185`). `PostInit` runs once per context lifetime; `OnClose` runs on every close. So the subscription is removed the first time the sheet is closed and **never re-added**.

Result: from the second visit onward, buying a skill no longer refreshes an open character sheet. The player sees stale values until they close and reopen it.

## Expected

Buying a skill refreshes the open character sheet, every time.

## Actual (predicted from code reading — not yet play-test confirmed)

Works on the first visit of a session. Silently stops working from the second visit on.

## Root cause

Lifecycle asymmetry — a one-shot `Insert` paired with a per-close `Remove`. The correct pairings are `PostInit`/`OnDelete` or `OnShow`/`OnClose`; mixing them leaks in one direction or, as here, unsubscribes permanently.

## Suggested fix

One line: move the `Insert` to `OnShow` so it pairs with the `OnClose` `Remove`. `OVT_TutorialContext` (added by tutorial-system Phase 6) uses the symmetric `RegisterInputs`/`UnregisterInputs` pair and can serve as the model.

## How it was found

Found while implementing `new-player-experience/tutorial-system` Phase 6, auditing subscribe/unsubscribe symmetry across UI contexts after the feature's own Quality Bar required that `OnClose` remove exactly what `OnShow` inserted.

## Relationship to tutorial-system

**Not introduced by this feature, but it is in a file this feature edited.** Phase 0 repointed both the `Insert` and the matching `Remove` at a new `OnSkillChanged(int, string)` wrapper when `m_OnPlayerSkill` gained arguments — it changed the _target_, not the _lifecycle_, so the pre-existing asymmetry survived unchanged. Definition-of-Done item Q6 ("skill purchase still refreshes the character sheet") is satisfied in the sense that behaviour is identical to before the feature; it was already broken on the second visit.

Left unfixed to avoid widening the feature's scope. It is a genuinely one-line change if you want it folded in.

## Verification needed

1. Open the character sheet, buy a skill — does it refresh? (Expected: yes.)
2. Close it, reopen it, buy another skill — does it refresh? (Expected: **no**, this is the bug.)
3. Confirm the values are correct after a close/reopen, isolating the fault to the live refresh rather than the data.
