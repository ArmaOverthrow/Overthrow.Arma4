## Summary

Placing the pirate radio transmitter charges the player and grants the `PirateRadio` support modifier, but no model appears. The placement ghost is spawned **client-side** by `OVT_PlaceContext.SpawnGhost()`, whereas the real entity is spawned **server-side** by `OVT_ResistanceFactionManager.PlaceItem()` (`:703`, `OVT_Global.SpawnEntityPrefabMatrix`). A runtime-spawned entity only reaches clients if it carries an `RplComponent` — and this prefab does not.

`Prefabs/Props/Military/Radios/OVT_PirateRadio.et` is the whole file:

```
GenericEntity : "{4417ED07902CE47E}Prefabs/Props/Military/Radios/RadioStation_ANPRC77_01.et" {
 ID "F0DBA538AC2A0552"
 components {
  OVT_PlaceableComponent "{6A7D9B2E00000047}" { m_sPlaceableType "PirateRadio" }
 }
}
```

Its base chain (`RadioStation_ANPRC77_01.et` → `Destructible_Props_Base.et`) is a static world prop — nothing in it declares replication.

Every other placeable in `Configs/Resistance/placeables.conf` does have it:

- `Prefabs/Props/Posters/Poster_Join_v1.et` declares `RplComponent` **and** `SCR_EditableEntityComponent` explicitly
- sandbags/hedgehogs use vanilla `PrefabsEditable/Auto/...` `E_` prefabs, which carry replication by construction
- `OVT_AmmoBox_Placed.et` / `OVT_Camp.et` are Overthrow prefabs built on replicated bases

## Expected

Placing the pirate radio spawns a visible transmitter for every player.

## Actual

Money is taken, the modifier is granted, and (on a dedicated server) nothing is drawn for anyone. On a listen-server host the entity exists locally, so this is easy to miss in Workbench Play mode and in single-player-style testing.

## Root cause

Missing `RplComponent` on a prefab that is only ever spawned at runtime by the server. Same class of fault as the faction-manager case recorded in memory: an Overthrow prefab inherits a vanilla base that never needed replication because vanilla only ever places it at design time.

## Suggested fix

Add `RplComponent` to `OVT_PirateRadio.et` (and, to match the poster prefab, `SCR_EditableEntityComponent` with `m_Flags PLACEABLE` if it should be editor-visible). This is a Workbench prefab edit.

While there: confirm the placed radio survives save/continue — `OVT_PlaceableComponentSerializer` tracks placed entities by prefab + transform, and an entity that never replicated is worth re-checking on the persistence side too.

## How it was found

Community report ("it spawns no model when placed; not sure if this is intentional, but it makes it not immediately clear whether placing it worked"), then traced through the place path. Confirmed by diffing the pirate radio prefab against the four placeable prefabs that do work.

## Verification needed

1. On a **dedicated** server (`tools/launch-server.sh`) with a remote client, place a pirate radio — nothing appears (this is the bug).
2. Repeat as a listen-server host — the model most likely *does* appear, which is the reason this survived.
3. After the fix, confirm both cases draw the model, and that removal mode still deletes it.
