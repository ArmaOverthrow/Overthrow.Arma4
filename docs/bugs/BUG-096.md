## Summary

`OVT_PlaceContext` carries one rotation across every ghost it ever spawns, and nothing ever resets the pitch and roll for a ground placeable.

`Scripts/Game/UI/Context/OVT_PlaceContext.c:456`:

```
m_ePlacingEntity = OVT_Global.SpawnEntityPrefab(m_pPlacingPrefab, pos, "0 0 0", false);

if(m_vCurrentTransform)
{
    m_ePlacingEntity.SetTransform(m_vCurrentTransform);   // full 4x4, rotation included
}
```

`m_vCurrentTransform` (`:21`, `protected vector m_vCurrentTransform[4]`) is written once per frame from the live ghost (`:62`) and is never cleared. Two consequences:

1. **Carry-over.** Place a poster on a wall — the wall branch writes a wall-aligned orientation (`:65-68`) — then switch to a ground placeable such as the pirate radio. The new ghost is stamped with the poster's wall rotation. `OnFrame` afterwards only calls `SetOrigin()`, so pitch and roll are never corrected, and `RotateLeft`/`RotateRight` (`:585-613`) only touch **yaw** for ground placeables. There is no player input that can level it again.
2. **First ghost of a session.** A fixed `vector[4]` member is zero-initialised, and the `if(m_vCurrentTransform)` guard on a fixed array does not distinguish "not set yet". The very first `SpawnGhost()` therefore applies an all-zero (degenerate) rotation basis before `OnFrame` has ever run.

The `m_bPlaceOnWall` placeables are immune to both because they overwrite yaw/pitch immediately afterwards (`:470-474`); that is why posters look fine and this shows up on the ground placeables.

## Expected

A ground placeable's ghost is upright, at the player's chosen yaw, regardless of what was placed before it.

## Actual

The ghost renders tilted ("Dutch angle"), and the tilt is baked into the placed entity — `DoPlace` sends `Math3D.MatrixToAngles(mat)` from the ghost's transform straight to the server.

## Root cause

One shared transform used as both "keep the player's chosen yaw between ghosts" (the intent) and "restore the entire orientation of an unrelated placeable" (the effect), with no seeded/unseeded distinction.

## Suggested fix

Keep only what the carry-over is actually for. Either:

- store the yaw alone (`float m_fCurrentYaw`) and apply it via `SetYawPitchRoll(Vector(m_fCurrentYaw, 0, 0))` for ground placeables; or
- keep the matrix, add an explicit `m_bHasTransform` flag, and for non-wall placeables zero pitch and roll after `SetTransform`.

The second is the smaller diff; the first removes the whole class of fault.

## How it was found

Community report against the pirate radio ("appears to be at a Dutch angle during placement"). Reading the place path showed the tilt is not specific to that prefab — it is whatever the previous ghost was rotated to, or a zero matrix on the first one.

## Verification needed

1. Enter place mode for the **first** time in a session and pick any ground placeable (ammo box, sandbags, pirate radio) — is the ghost upright?
2. Place a poster on a sloped or angled wall, then switch to a ground placeable — the ghost should now be visibly tilted (this is the carry-over case).
3. Confirm the tilt persists into the placed entity, not just the preview.
4. Confirm rotate left/right cannot correct it.
