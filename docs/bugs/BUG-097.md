## Summary

`OVT_EconomyInfo` holds the delta ticker's entire state in an instance field:

`Scripts/Game/UI/HUD/OVT_EconomyInfo.c:14`
```
protected ref OVT_MoneyDeltaTracker m_MoneyDelta = new OVT_MoneyDeltaTracker();
```

but the info display is declared **once per occupiable prefab**, not once per player:

- `Prefabs/Characters/Factions/INDFOR/FIA/Character_Player.et:159`
- `Prefabs/Vehicles/Core/Wheeled_Base.et:12`
- `Prefabs/Vehicles/Core/Helicopter_Base.et:14`
- `Prefabs/Weapons/Core/Turret_Base.et:10`
- plus the three recruit/civ character prefabs

Each is a separate `SCR_BaseHUDComponent` entry and therefore a separate `OVT_EconomyInfo` object with its own `OVT_MoneyDeltaTracker` — its own `m_iLastMoney`, `m_iDelta`, `m_fTimer` and `m_bSeeded`.

Getting into a car switches which instance is ticking. The one you left stops being updated mid-count; the one you arrive at re-seeds from scratch (`OVT_MoneyDeltaTracker.Update`, `:42-49`: first observation learns the balance and shows nothing). Getting out swaps them back, and the character's stale tracker — still holding the balance from before you got in — now sees a difference and renders it as a fresh `+$X`.

That is exactly the reported shape: **delayed until getting out of the vehicle, and possibly shown twice.**

## Expected

One money ticker per player. A change credited while driving shows immediately, once, and does not reappear on foot.

## Actual

Deltas earned in a vehicle are withheld until dismount, and a delta already shown by one instance can be shown again by the other.

## Root cause

Per-entity display state for a per-player quantity. Noted in the code's own comment (`:311-317`) that the ticker is polled rather than subscribed "because its lifetime does not obviously match the economy manager's" — that lifetime mismatch is precisely the bug.

## Suggested fix

The tracker must outlive any one info display. Options, cheapest first:

1. **Static/shared tracker.** Make the tracker a static owned by the local player (e.g. hung off `OVT_OverthrowController` or a `static ref` keyed to the local persistent ID) and have every `OVT_EconomyInfo` instance read the same one. Minimal change, fixes both symptoms.
2. **Move the state to the client controller.** A small client-side component on `OVT_OverthrowController` owns the delta; the info displays become pure renderers. Cleaner, and matches how the rest of the client state is organised.

Either way the tracker must be seeded once per session, not once per HUD instance.

## How it was found

Community report: "Green / red money changes on HUD are delayed until getting out of vehicle (or repeated? Unsure)." Confirmed by reading the info-display declarations across the character and vehicle prefabs.

## Verification needed

1. On foot, sell something — the ticker shows once and clears after ~4 s. (Baseline.)
2. Get in a car, then receive money (rent tick, job completion, a passenger paying) — does the ticker show while driving?
3. Get out — does the delta you already earned appear now (delayed), or appear a second time (repeated)?
4. Repeat in a helicopter and in a turret, which have their own instances too.

## Notes

The money **text** itself is fine — it is re-read from the economy manager every frame by whichever instance is active. Only the delta, which is derived from frame-to-frame history, is instance-bound.
