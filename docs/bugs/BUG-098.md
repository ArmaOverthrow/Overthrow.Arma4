## Summary

`Configs/System/ShopConfig.conf` gives the electronics shop a single, unfiltered rule:

```
OVT_ShopInventoryConfig "{647C9C57C8E13015}" {
 type SHOP_ELECTRONIC
 m_aInventoryItems {
  OVT_ShopInventoryItem "{647C9C539D5A77DE}" {
   m_eItemType EQUIPMENT
  }
 }
}
```

No `m_sFind`, no `m_eItemMode`, and all three faction include flags default to `true` (`OVT_EconomyManagerComponent.c:35-42`).

`m_eItemMode` defaults to `"2"` = `SCR_EArsenalItemMode.DEFAULT`, and `FindInventoryItems` treats DEFAULT as a **wildcard**, not as a value to match:

`Scripts/Game/GameMode/Managers/OVT_EconomyManagerComponent.c:1467`
```
if(mode != SCR_EArsenalItemMode.DEFAULT)
{
    if(item.GetItemMode() != mode) continue;
}
```

So the rule matches every `EQUIPMENT` entry in the catalogue in every mode. Vanilla files tripod and mortar parts as exactly that — `Configs/EntityCatalog/US/InventoryItems_EntityCatalog_US.conf`, `DeployableParts` list:

```
Prefabs/Items/Equipment/Tripods/M2/Part_M2_Gun.et         m_eItemType EQUIPMENT  m_eItemMode SUPPORT_STATION
Prefabs/Items/Equipment/Tripods/M2/Part_M3_Tripod.et      m_eItemType EQUIPMENT  m_eItemMode SUPPORT_STATION
Prefabs/Items/Equipment/Tripods/M60/Part_Tripod_M122.et   m_eItemType EQUIPMENT  m_eItemMode SUPPORT_STATION
Prefabs/Items/Equipment/Mortars/M252/Part_M252_BasePlate.et  ...  SUPPORT_STATION
```

(equivalents exist in the USSR and FIA catalogues).

This is also why the general store needs its `m_sFind` strings (`PaperMap_`, `Binoculars_`, `Watch_`) — without one, an `EQUIPMENT` rule is a firehose.

## Expected

Civilian shops sell civilian goods. Crew-served weapon parts belong to gun dealers or to the port's extended catalogue, not to an electronics store in a town.

## Actual

Tripod-mounted weapon parts and mortar components appear on the shelf of a civilian shop, at civilian prices, with no faction or legality gate.

## Root cause

An unfiltered `EQUIPMENT` rule combined with `SCR_EArsenalItemMode.DEFAULT` being overloaded as "match any mode". The eligibility path used by the sell browser (`IsSoldAtShopCached` → `GetShopTypeResourceIds`, `:691`) applies the same rules, so these items are also *sellable* at electronics shops.

## Suggested fix

Pick one, in the config — no code change needed:

- Add `m_eItemMode DEFAULT`-excluding filtering by giving the rule an explicit mode. Note this needs the wildcard semantics addressed first, since DEFAULT currently means "any".
- Or add `m_sFind` terms the way the general store does, restricting electronics to the intended item families.
- Or split the rule and mark deployable parts out of civilian scope entirely.

If the intent is to make crew-served parts obtainable but risky, the mechanism already exists: attribute them to the occupying faction and let the `m_bIncludeOccupyingFactionItems` flag do the work — but note the import path's client list ignores those flags today (BUG-102).

A separate, smaller decision worth making at the same time: whether `SCR_EArsenalItemMode.DEFAULT` should keep meaning "any mode". It is not obvious from the config side, and it is the reason this rule is broader than it reads.

## How it was found

Community report ("Tripod-mounted weapons are available in civilian shops"). Traced from `InitShopInventory` (`:1714-1735`) through `FindInventoryItems` to the vanilla catalogue entries.

## Verification needed

1. Open an electronics shop in any town and page through the stock — tripod/mortar parts should be present.
2. Check a general store too: it should be clean (its rules are all `m_sFind`-filtered).
3. Switch to sell mode at an electronics shop while carrying a tripod part — it should be listed as sellable, which confirms the same rule set drives both directions.
