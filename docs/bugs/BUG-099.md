## Summary

On a shop card the price sits inside `ImageOverlay`, on top of the 3D item preview and the light `Effect_AssetCard_Splatter_01` texture, with nothing behind it.

`UI/Layouts/Menu/ShopMenu/ShopMenu_Card.layout`:

```
ImageWidgetClass { Name "Splatter"  Texture "...Effect_AssetCard_Splatter_01.edds"  Size 400 300 }   // no Color -> white
TextWidgetClass  { Name "Cost"      Text "$10000000"  FontProperties { Font Roboto_Bold.fnt } }        // no Color -> white
```

Two things stack up:

1. The `Cost` widget is a **raw** `TextWidgetClass` — unlike `EntityName`, which inherits `WidgetLibrary/TextWidgets/Text_BodySmall.layout` and gets the library's styling. So there is no shadow, no outline.
2. `EntityName` is legible because it sits over `AssetCardBackground` (`Color 0.005 0.005 0.005 1`, near-black). `Cost` has no such plate — its backdrop is whatever the preview renders plus a white splatter.

`OVT_ShopMenuCardComponent.ApplyEnabledVisual` then explicitly re-asserts white on every refresh (`:158`, `cost.SetColor(Color.White)`), so this cannot be fixed by authoring a colour in the layout alone.

`PlaceMenu_Card.layout` has the identical structure, so the place menu is very likely affected too.

## Expected

The price is readable against any item preview.

## Actual

White-on-white for light-coloured previews and wherever the splatter lands. Effectively invisible.

## Root cause

Overlay text with no contrast guarantee: no plate, no outline, no shadow — and a component that forces the colour to white regardless.

## Suggested fix

Any one of these fixes it; the first is the most robust:

1. Give `Cost` a background the way `EntityName` has one — a small dark panel/rounded plate behind the text in the top-right corner of the card.
2. Rebase the `Cost` widget on a WidgetLibrary text layout that carries a shadow/outline, and stop forcing `Color.White` in `ApplyEnabledVisual` (keep only the *disabled* grey).
3. Tint `Splatter` dark (as `SCR_AssetCardFrontUIComponent` does in the vanilla content browser, which drives the overlay through `m_sImageOverlayName` rather than leaving it plain white).

Whatever is chosen must be applied to `PlaceMenu_Card.layout` as well, and the disabled-state colours in `ApplyEnabledVisual` need to stay legible against the same backdrop.

## How it was found

Community report ("Prices shown on item portraits in shops are unreadable (white text on white background)"). Confirmed from the layout and the card component.

## Verification needed

1. Open a shop and look at the price on a light-coloured item (bandages, white/tan clothing) — should be unreadable today.
2. Compare a dark item — the price should be legible, which localises the fault to contrast rather than to the widget being hidden.
3. Check the place menu cards for the same problem.
4. Check the disabled (greyed) card state after the fix — `COLOR_TEXT_DISABLED` is `0xFF808080`, which also needs to survive on the new backdrop.
