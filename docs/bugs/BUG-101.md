## Summary

Both halves of a transaction award XP, with no cooldown, no per-item cap and no check that the item was not just bought from the same shop:

`Scripts/Game/GameMode/Managers/OVT_SkillManagerComponent.c:204-217`
```
void OnPlayerBuy(int playerId, int amount)
{
    GiveXP(playerId, 1);
}

void OnPlayerSell(int playerId, int amount)
{
    int xp = 1 + Math.Floor(amount * 0.01);
    GiveXP(playerId, xp);
}
```

`GiveXP` (`:260`) has no rate limit and no ceiling — it adds, streams, and notifies on level-up.

The cost of a round trip is only the shop margin. `GetBuyPrice` (`OVT_EconomyManagerComponent.c:555`) is `GetSellPrice + (price × m_fShopProfitMargin)`, and `OVT_ShopSellRules.GetSellMultiplier` returns exactly `1.0` at every shop type except a gun dealer. So buying then immediately re-selling at a **non-gun-dealer** shop returns the base price and loses only the margin, while paying out `2 + floor(saleTotal × 0.01)` XP per cycle.

Buy 10 of something expensive, sell 10 back, repeat: XP scales with the *value* moved, the cash loss scales only with the margin, and nothing bounds either.

## Expected

XP rewards trading activity, not the act of clicking buy and sell on the same counter.

## Actual

An unbounded XP source available from the first shop a player reaches, gated only by starting cash.

## Root cause

XP is awarded per transaction event, with no notion of net economic activity and no anti-churn rule. The sell reward being proportional to value (`amount × 0.01`) while the buy cost is only a fixed percentage margin makes the exchange rate favourable at high item values.

## Suggested fix

Options, roughly in increasing order of effort:

1. **Award sell XP only on net-new goods.** Track, per player, value bought at a shop within the last N minutes and subtract it from the sell amount that earns XP. Simple version: no sell XP for a resource id the player bought at that same shop recently.
2. **Cap XP per shop per period.** A per-shop cooldown or a daily trade-XP budget. Blunt, but one config value and it closes the loop.
3. **Rebalance so the round trip is XP-negative.** Increase `m_fShopProfitMargin`'s effect or make sell XP proportional to *profit* rather than gross, so churn cannot pay.

Whichever is picked, it belongs next to the two invokers in `OVT_SkillManagerComponent`, not in the shop code — `m_OnPlayerBuy` / `m_OnPlayerSell` are the only XP entry points for trading.

## How it was found

Community report ("Exploit found: possible to cheese XP by buying and immediately selling items in the same shop"). Confirmed against the XP handlers and the buy/sell price derivation.

## Verification needed

1. Note XP, buy one mid-price item, sell it straight back at the same shop, note XP and cash. Expect roughly +2 XP for a small cash loss.
2. Repeat with a stack of 10 high-value items and confirm the XP gain scales with value while the cash loss does not.
3. Check a gun dealer separately — its sell multiplier is a difficulty value and may make the loop cash-negative enough to be self-limiting there.

## Notes

Not a regression: both handlers predate the shop-ux work. What made it easy to exploit is that sell is now a first-class menu mode.
