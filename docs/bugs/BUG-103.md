## Summary

The visible container at a port is a **child** of the port entity, pinned at the parent's origin:

`Prefabs/GameMode/OVT_Port.et`
```
GenericEntity {
 components { OVT_PortControllerComponent {...}  RplComponent {...} }
 {
  GenericEntity : "{8F08705D73A7C711}...CargoContainers/CargoContainer_01/CargoContainer_01_20ft_red.et" {
   coords 0 0 0
  }
 }
}
```

so the container's height is entirely the port entity's height, and that is a hand-typed absolute Y in the world layer:

`Worlds/MP/OVT_Campaign_Eden_Layers/ports.layer`
```
Port_StPhillipe { coords 4410.808 1.594  11158.649 }
Port_StPierre   { coords 9986.973 2.898  1518.956  }
```

There are only two ports and they carry different Y values (1.594 vs 2.898), which is consistent with each having been placed by hand. Saint-Pierre's sits above the quay surface at that spot, so the container hangs in the air.

## Expected

The container rests on the quay.

## Actual

It hovers. Cosmetic, but it is the landmark that tells a player where importing happens, so it reads as broken.

## Root cause

Level authoring, not code: an absolute Y that does not match the terrain/quay height at `9986.973, 1518.956`.

## Suggested fix

**This is a Workbench edit, not a script change.** In the Eden world's `ports` layer, select `Port_StPierre` and drop it to the surface (or adjust its Y until the container sits flush), then save the layer. Check `Port_StPhillipe` at the same time.

If the container should visually sit on the ground independently of where the port's logical origin is, the alternative is to give the child a local Y offset in `OVT_Port.et` — but that just moves the hand-tuning somewhere else, and the two ports would still need separate values. Moving the port entity is the right fix.

## How it was found

Community report ("Container at Saint-Pierre port hovers above the ground"). Confirmed from the port prefab's child transform and the two hard-coded positions in the ports layer.

## Verification needed

1. Travel to Saint-Pierre port and look at the container — should be visibly floating.
2. Compare Saint-Philippe, which has a different authored Y and may be correct.
3. After the fix, confirm the import/trade proximity checks still pass — `IMPORT_MAX_PORT_DISTANCE` is 30 m and `DistanceToNearestPort` measures from the port entity origin, so a large vertical move changes those distances slightly.
