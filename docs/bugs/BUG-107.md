## How this was found

Source verification during `new-player-experience/field-manual` authoring. Both help surfaces say recruits gain experience by "killing occupying faction soldiers", which is the intent; the sweep read the awarding site to confirm the wording and found it does not consult the configured occupying faction at all. This is invisible to play-testing on a stock server, because on stock Arma Reforger the occupying faction key really is `US` or `USSR`.

## Symptom

On a server whose occupying faction comes from a compatibility mod with any faction key other than `US` or `USSR`, **recruits never gain experience and never level, silently.** No warning, no log line, no partial credit. Kill counters do not advance either.

## Root cause

`OVT_RecruitManagerComponent.OnAIKilled` gated XP and kill-counting on the literal faction keys `"US"`/`"USSR"` instead of the configured occupying faction — the same question `OVT_QRFControllerComponent.CheckUpdatePoints` (`OVT_QRFControllerComponent.c:121`) already asks correctly via config.

## Resolution (2026-08-14)

**Fixed as ride-along task T1.6 of `resistance/recruit-ux` Phase 1.** `OnAIKilled` now compares the victim's faction key against the configured occupying faction (`OVT_Global.GetConfig().m_sOccupyingFaction`), with the config lookup null-guarded. Verified by compile-check and the All test group (143/143 green at time of fix). Change is in the working tree with the recruit-ux feature (not yet committed at time of closing).
