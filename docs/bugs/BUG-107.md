## How this was found

Source verification during `new-player-experience/field-manual` authoring. Both help surfaces say recruits gain experience by "killing occupying faction soldiers", which is the intent; the sweep read the awarding site to confirm the wording and found it does not consult the configured occupying faction at all. This is invisible to play-testing on a stock server, because on stock Arma Reforger the occupying faction key really is `US` or `USSR`.

## Symptom

On a server whose occupying faction comes from a compatibility mod with any faction key other than `US` or `USSR`, **recruits never gain experience and never level, silently.** No warning, no log line, no partial credit. Kill counters do not advance either.

## Root cause

`OVT_RecruitManagerComponent.OnAIKilled`, `Scripts/Game/GameMode/Managers/OVT_RecruitManagerComponent.c:695-710`:

```c
Faction faction = victimFaction.GetAffiliatedFaction();
if (!faction)
    return;

// Only award XP for killing occupying faction members
string factionKey = faction.GetFactionKey();
if (factionKey != "US" && factionKey != "USSR")
    return;

// Award XP
killerRecruit.m_iKills++;
AddRecruitXP(killerRecruit.m_sRecruitId, 10); // 10 XP per enemy kill
```

The two literals are the only gate. `m_iKills++` and `AddRecruitXP` sit **after** the early return, so both the counter and the XP are lost.

The comment on `:702` states the intent precisely ("occupying faction members"), and the codebase already has the correct idiom for expressing it. `OVT_QRFControllerComponent.CheckUpdatePoints`, `Scripts/Game/Controllers/OccupyingFaction/OVT_QRFControllerComponent.c:121`:

```c
if(character.GetFactionKey() != OVT_Global.GetConfig().GetOccupyingFactionData().GetFactionKey()) continue;
```

That is good evidence the hardcoded keys are an oversight rather than a deliberate restriction: the same question is asked correctly a few files away.

## Fix (proposed)

Resolve the key from config instead of comparing to literals:

```c
string occupyingKey = OVT_Global.GetConfig().GetOccupyingFactionData().GetFactionKey();
if (faction.GetFactionKey() != occupyingKey)
    return;
```

Guard the null case (`GetOccupyingFactionData()` before config is initialised) the way the QRF site's callers do, and consider whether the supporting faction should also count, which is a separate gameplay call.

**This is a gameplay call in one respect:** if the two literals were a deliberate whitelist (award XP only against the two vanilla militaries and never against a modded faction), the current behaviour is correct and the comment on `:702` is the thing that is wrong. That reading is hard to defend given the QRF precedent, but it should be stated rather than assumed.
