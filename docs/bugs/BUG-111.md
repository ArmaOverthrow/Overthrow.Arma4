## How this was found

Source verification during `new-player-experience/field-manual` authoring. The sweep enumerated every path that can raise a wanted level so the manual could describe them; this one is a collateral escalation that never names the player who caused it, and would be nearly impossible to attribute in play. A passenger who becomes wanted while sitting in a parked car has no feedback telling them why.

## Symptom

When an occupying-faction character is killed, **every occupant of every vehicle within a 5 m sphere of the body is escalated to wanted level 3**, and any disguise they were wearing is blown. Participation is not checked. A player parked beside a firefight they had nothing to do with is escalated identically to the shooter.

## Root cause

`Scripts/Game/Components/Damage/Modded/SCR_CharacterDamageManagerComponent.c`.

The sweep is fired from the occupying-faction branch of the death handler (`:55-61`):

```c
if(IsOccupyingFaction())
{
    OVT_Global.GetOccupyingFaction().OnAIKilled(GetOwner(), instigator);

    //Check immediate surrounds for a vehicle (hoping for a better way soon pls BI)
    GetGame().GetWorld().QueryEntitiesBySphere(GetOwner().GetOrigin(), 5, CheckVehicleSetWanted, FilterVehicleEntities, EQueryEntitiesFlags.ALL);
}
```

and escalates unconditionally (`:106-135`):

```c
protected bool CheckVehicleSetWanted(IEntity entity)
{
    SCR_BaseCompartmentManagerComponent mgr = SCR_BaseCompartmentManagerComponent.Cast(entity.FindComponent(SCR_BaseCompartmentManagerComponent));
    autoptr array<IEntity> occupants = new array<IEntity>;
    mgr.GetOccupants(occupants);

    foreach(IEntity occupant : occupants)
    {
        OVT_PlayerWantedComponent wanted = OVT_PlayerWantedComponent.Cast(occupant.FindComponent(OVT_PlayerWantedComponent));
        if(wanted)
        {
            if(wanted.IsDisguisedAsOccupying()) { wanted.SetBaseWantedLevel(3, "WantedDisguiseBlown"); wanted.BlowDisguise(); }
            else                                { wanted.SetBaseWantedLevel(3); }
        }
    }
    return true;
}
```

The instigator is not passed in and is not compared against. There is no line-of-fire test, no time window, no "was this vehicle moving" test. The apologetic comment on `:59` ("hoping for a better way soon pls BI") makes the intent readable: it is a **heuristic for "the shooter was in that car"**, standing in for a vehicle-attribution API the engine did not expose. As a heuristic for a drive-by it is reasonable. Its false-positive case is a stationary bystander.

## Notes on scope

- **5 m is small**, which limits the blast radius considerably. The body must be essentially against the vehicle.
- `FilterVehicleEntities` (`:100-104`) matches on `entity.ClassName() == "Vehicle"` exactly. Whether that catches every vehicle type players actually drive was not verified statically; if it misses subclasses, the real-world reach of this is narrower still (and the intended drive-by case may itself be unreliable).
- `mgr` is dereferenced at `:112` without a null check, though `FilterVehicleEntities` makes a compartment-less match unlikely.

## Fix (proposed)

**This is a design question, not an obvious defect.** The behaviour is deliberate code written to compensate for a missing engine capability; the question is only whether the collateral case is acceptable.

Options, in increasing order of work:

1. **Accept it.** Document it and close. The radius is small and the case is rare.
2. **Attribute it.** Pass the instigator into the query and escalate only vehicles that contain the instigator (which makes the sweep a "was the shooter in a vehicle" test rather than a proximity test). This preserves the drive-by intent and removes the bystander case entirely, and is probably what the original comment was reaching for.
3. **Gate it on participation.** Only escalate occupants who have recently fired, or whose vehicle has moved within some window. More faithful to intent, considerably more machinery.

Option 2 looks like the smallest change that removes the false positive without losing anything the heuristic was for, but it is still a gameplay change and needs an owner's call.
