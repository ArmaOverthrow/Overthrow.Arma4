## How this was found

Source verification during `new-player-experience/field-manual` authoring. The wiki documented a real-estate discount that changes with difficulty; the sweep went looking for the code that applies it, found none, and **removed four "real estate discount" claims from the wiki** in phase 7A rather than document a setting that does nothing. Play-testing would never surface this: a server owner who sets it and sees no change has no way to distinguish "the setting is dead" from "I misjudged the effect".

## Symptom

`realEstateCostMultiplier` is a difficulty setting exposed to server owners, given a per-preset value in every shipped difficulty config, replicated to clients, and **applied to no price anywhere**. Setting it has no effect on anything. Easy servers do not get cheaper houses; Insane servers do not get dearer ones.

## Root cause

**It is declared like a real setting**, `Scripts/Game/Configuration/OVT_DifficultySettings.c:64-65`:

```c
[Attribute(defvalue: "0.5", desc: "Cost of Real Estate is multiplied by this value", category: "Economy")]
float realEstateCostMultiplier;
```

**It is configured like a real setting**, in four of the five shipped presets:

| Preset | Value |
|---|---|
| `Configs/Difficulty/Difficulty_Easy.conf:17` | 0.4 |
| `Configs/Difficulty/Difficulty_Hard.conf:20` | 0.7 |
| `Configs/Difficulty/Difficulty_Extreme.conf:21` | 1.5 |
| `Configs/Difficulty/Difficulty_Insane.conf:20` | 2 |

(Normal inherits the `0.5` default.) Note that the values are a deliberately shaped curve, which is good evidence somebody once intended it to work.

**It is never read.** A repo-wide grep across `Scripts/` returns exactly three hits, one declaration and two replication lines:

```
Scripts/Game/Configuration/OVT_DifficultySettings.c:65          float realEstateCostMultiplier;
Scripts/Game/GameMode/Managers/OVT_OverthrowConfigComponent.c:564   writer.WriteFloat(m_Difficulty.realEstateCostMultiplier);
Scripts/Game/GameMode/Managers/OVT_OverthrowConfigComponent.c:619   m_Difficulty.realEstateCostMultiplier = f;
```

So it is serialised to every client on config replication and then ignored by both ends.

The two prices it would plausibly apply to are computed without it, `Scripts/Game/GameMode/Managers/OVT_RealEstateManagerComponent.c:712-725` and `:731-744`:

```c
return config.m_BasePrice + (config.m_BasePrice * (config.m_DemandMultiplier * town.population * ((float)town.stability / 100)));
```

**Its two siblings work.** `placeableCostMultiplier` and `buildableCostMultiplier` are declared alongside it at `:61` and `:63`, and both are applied in `OVT_OverthrowConfigComponent`:

```c
252:  return Math.Round(m_Difficulty.placeableCostMultiplier * placeable.m_iCost);
257:  return Math.Round(m_Difficulty.buildableCostMultiplier * buildable.m_iCost);
```

There is no equivalent `GetRealEstateCost`. That asymmetry is the strongest signal that this is an unfinished third case rather than a decision.

## Fix (proposed)

**This is a design question with two clean answers, and the current state is neither.**

**Wire it up.** Add the multiplier to `OVT_RealEstateManagerComponent.GetBuyPrice` (`:712`), mirroring the sibling pattern. Two things need deciding first:

- **Does it apply to rent too** (`GetRentPrice:731`), or only to purchase? The attribute description says "Cost of Real Estate", which does not settle it. Applying it to both changes the buy-vs-rent balance in a way the presets' values may not have been chosen for.
- **Does it apply to warehouses**, which take the early `m_BasePrice` / `m_BaseRent` return at `:719-722` and `:738-741` and bypass the demand curve entirely?

Note that turning it on is a **large, immediate economy change on every server**: Easy houses drop to 40% of current price and Insane houses double. That is exactly the sort of change that needs a balance pass, not a one-liner.

**Or remove it.** Delete the field, the four preset lines and the two replication lines. Server owners lose a knob that never did anything, and the config stops advertising a capability the game does not have.

Whichever is chosen, the wiki's four removed "real estate discount" claims should be revisited: if it gets wired up they were right all along and should come back.
