## How this was found

Source verification during `new-player-experience/field-manual` authoring, phase 7B's wiki-staleness sweep. The `overthrow-config` wiki page documents this default verbatim, so verifying the page meant following the URL in it, which turned out to be dead. Play-testing would never surface this; it is only visible to a server owner opening a freshly generated config file, and only as a mildly confusing dead end rather than an error.

## Symptom

Every auto-generated `Overthrow_Config.json` seeds `discordWebHookURL` with a placeholder that tells the reader where to learn about the setting. **That address no longer serves the documentation.** GitHub redirects it to the repo wiki home, which as of 2026-08-08 contains only a stub reading:

> "This wiki has moved to http://wiki.armaoverthrow.com/"

So the first instruction a new server owner reads inside their own config file sends them to a page that has been retired, and the stub does not deep-link them back to the article they wanted.

## Root cause

`OVT_OverthrowConfigComponent.SetDefaults`, `Scripts/Game/GameMode/Managers/OVT_OverthrowConfigComponent.c:46-48`:

```c
void SetDefaults()
{
    discordWebHookURL = "see wiki: https://github.com/ArmaOverthrow/Overthrow.Arma4/wiki/Discord-Web-Hook";
```

The string predates the wiki migration to `wiki.armaoverthrow.com` and was not swept when the content moved. It is a hardcoded literal with no config or localisation indirection, so nothing else in the project could have caught it drifting.

**The wiki itself is not wrong.** The `overthrow-config` page documents this default verbatim (correctly, since it is what ships) and links alongside it to `/discord-web-hook`, which exists and is current. The defect is entirely in the shipped string.

## Fix (proposed)

One line:

```c
discordWebHookURL = "see wiki: https://wiki.armaoverthrow.com/discord-web-hook";
```

Verify the target resolves before committing, and prefer `https` (the stub's own redirect text advertises `http`).

Two consequential notes:

- The `overthrow-config` wiki page quotes the current default **verbatim**, so it must be edited in the same change or it becomes stale the moment this lands.
- The change only affects **newly generated** config files. Existing servers keep whatever string is already written to disk, including the dead one, so this fixes the problem for new owners only. That is probably acceptable: an existing owner has either already configured the setting or already discovered the dead link.

Low priority, trivial change, but it is a shipped default that is actively wrong and it costs nothing to correct. Worth a grep for any other hardcoded `github.com/ArmaOverthrow/Overthrow.Arma4/wiki` string in the same pass.
