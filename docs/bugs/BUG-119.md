> Filed from the `/discover-feature resistance/fob` code investigation (2026-08-09). Evidence is source-level; not yet reproduced at runtime.

## Symptom

Every FOB in the game is nameless:
- The FOB menu (`OVT_FOBMenuContext`) header renders blank.
- The `PriorityFOBSet` broadcast renders as "` has been set as the priority FOB`" — `localization_Overthrow.st:5295` expects a `%1` name that is always empty.
- `RpcDo_RegisterFOB` ships an empty string to every client and JIP streams it on.

## Root cause

`OVT_ResistanceFactionManager.RegisterFOB` (`Scripts/Game/GameMode/Managers/Factions/OVT_ResistanceFactionManager.c:1106-1121`) sets `persistentId`, `owner` and `location` on the new `OVT_FOBData` but never assigns `fob.name`. The camp path does this correctly — `RegisterCamp` (`:1096`) composes a name from the placeable label + player name.

The field round-trips faithfully everywhere else (JIP `RplSave`/`RplLoad`, `OVT_PersistedFOB`, delta RPC) — it is only ever the empty string because no live path writes it.

## Fix (proposed)

Compose a name in `RegisterFOB` the same way `RegisterCamp` does — e.g. `"FOB <owner player name>"` or "FOB near <nearest town>" (town manager already resolves town names for notifications). Existing saves will backfill on next registration or can be patched in `ApplyPersistedResistance` when `name` is empty.
