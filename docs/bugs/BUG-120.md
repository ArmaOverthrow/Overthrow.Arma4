> Filed from the `/discover-feature resistance/fob` code investigation (2026-08-09). Evidence is source-level; not yet reproduced at runtime.

## Symptom

Deploying an FOB is supposed to announce "player X has placed a new FOB near Y" to all players. No such message ever appears, on any client or the host.

## Root cause

`OVT_ResistanceFactionManager.RegisterFOB` (`Scripts/Game/GameMode/Managers/Factions/OVT_ResistanceFactionManager.c:1120`) sends a text notification with tag `"DeployedFOB"`. `Configs/overthrowBroadcastMessages.conf` contains no preset with `m_sTag "DeployedFOB"` (verified: 62 tags, none match). `OVT_NotificationManagerComponent.RpcDo_RcvTextNotification` (`:184-185`) does `if(!preset) return;` — the notification is dropped silently on every receiver.

The localization string that was authored for this — `OVT-Msg-HasPlacedFOB` (`Language/localization_Overthrow.st:3579-3585`, translated into 5 languages) — is orphaned; nothing references it.

## Fix (proposed)

Add a `DeployedFOB` preset to `Configs/overthrowBroadcastMessages.conf` wired to `#OVT-Msg-HasPlacedFOB`, following the shape of the existing `FOBUndeployed` preset (`:429-436`). Note the message takes a player name and location parameter — pair with BUG-119 (FOB names are empty) if the text references the FOB by name.

## Notes

- The undeploy side works (presets `FOBUndeployed`, `FOBUndeployFailed`, `FOBOperationInProgress` all exist) — only the deploy announcement is missing its preset.
- Nearby oddity spotted in the same sweep (cosmetic, no separate bug): `OVT-Msg-NewCamp` is worded "New FOB" (`.st:3727-3733`).
