> Filed from the `/discover-feature resistance/fob` code investigation (2026-08-09). Evidence is source-level; not yet reproduced at runtime.

## Symptom

`mobileFOBOfficersOnly` (default **true**, `OVT_OverthrowConfigComponent.c:32`) is meant to restrict Mobile FOB acquisition and deploy/undeploy to officers. In practice any player can:

1. **Acquire one legitimately through the UI**: `OVT_ManageVehicleContext.Upgrade()` (`Scripts/Game/UI/Context/OVT_ManageVehicleContext.c:125-143`) converts an `M923A1_transport` into a Mobile FOB for 10000 at any garage with **no officer check at all** — the upgrade tree (`Prefabs/GameMode/OVT_OverthrowGameMode.et:185-197`) is not gated.
2. **Deploy/undeploy with a modified client**: the RPCs accept anyone.

## Root cause

Three independent holes:

- **Upgrade path ungated + client-charged**: `Upgrade()` charges via `TakeLocalPlayerMoney` (`:138`) — client-side payment, the recurring exploit class (cf. BUG-047/048/051) — and performs no officer check before `OVT_VehicleManagerComponent.UpgradeVehicle`.
- **Shop gate is string-matching, client-side**: `OVT_ShopContext.c:747-759` hides the truck from non-officers by string-matching `"OverthrowMobileFOB"` in the prefab path (fragile — any renamed/added variant escapes it) and only in the UI; nothing server-side re-checks at purchase.
- **Deploy/undeploy RPCs check geometry, never the role**: `OVT_ResistanceFactionManager.DeployFOB` (`:466-555`) re-validates base/tower distance server-side (the BUG-046 fix), but neither it nor `UndeployFOB` (`:557-621`) re-checks `IsOfficer` when `mobileFOBOfficersOnly` is set. The only officer checks live in `CanBeShownScript` (`OVT_DeployFOBAction.c:17`, `OVT_UndeployFOBAction.c:17`).

## Fix (proposed)

1. Server-side officer check in `DeployFOB`/`UndeployFOB` when `mobileFOBOfficersOnly` (the config value is already replicated and available server-side), with a targeted refusal notification.
2. Gate the upgrade path: either check officer for upgrades whose target prefab is `m_pMobileFOBPrefab` (compare prefab resource, not path substring), or move the check into `UpgradeVehicle` server-side. Move the charge server-side while there (same pattern as the BUG-047 garrison fix, `ChargeForGarrison`).
3. Replace the shop's path string-match with a comparison against `m_pMobileFOBPrefab` from config.

## Notes

- `LocalPlayerIsOfficer` (`OVT_PlayerManagerComponent.c:487-493`) derefs `player.isOfficer` without a null guard; reached from every FOB action's `CanBeShownScript` — worth a guard while touching these paths (JIP timing can plausibly present a null player record).
- The "officer gates are client-side" observation existed in `resistance/core`'s retrospective doc; this filing adds the previously-undocumented upgrade-path bypass, which makes it exploitable through the normal UI, not just modified clients.
