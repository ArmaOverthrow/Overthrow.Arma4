> Filed from the `/discover-feature resistance/fob` code investigation (2026-08-09). Evidence is source-level; not yet reproduced at runtime.

## Symptom

The priority FOB (always-visible map icon, `fob_priority` icon at all zoom levels) is meant to be an officer-designated rally point set at the FOB flag. A modified client can re-designate it at will, from anywhere, as any player — and because the wire key is a position, it can point the designation at any FOB it likes.

## Root cause

`OVT_PlayerCommsComponent.RpcAsk_SetPriorityFOB` (`Scripts/Game/Components/Player/OVT_PlayerCommsComponent.c:1993-2003`):

- Does **not** call `ResolveSenderPlayerId` — unlike its siblings `RpcAsk_DeployFOB` / `RpcAsk_UndeployFOB` / `RpcAsk_AddGarrisonFOB`, which all had sender resolution added.
- No officer check (the only gate is `OVT_SetPriorityFOBAction.CanBeShownScript`, client-side).
- No distance/ownership validation: `SetPriorityFOB` (`OVT_ResistanceFactionManager.c:625-659`) accepts any RplId, resolves the entity, and flips whichever FOB is within 10 m of it.

## Fix (proposed)

Match the pattern already applied to the other three FOB RpcAsks: resolve the real sender, check `IsOfficer` when `mobileFOBOfficersOnly` is set, and validate the acting player is within interaction range of the FOB entity. Consider keying by `persistentId` instead of entity+position while touching the wire format (both sides already have it — see the position-keyed-identity debt in `resistance/fob`).

## Notes

- Low harm ceiling (it's a map-marker designation, not property/money), hence medium rather than high — but it is the last remaining fully-unauthenticated FOB RPC after the BUG-046/047 hardening, and worth closing with the same one-line pattern.
- `OVT_SetPriorityFOBAction.PerformAction` passes `pOwnerEntity` (the cargo-canvas child) rather than `GetParent()` — works only because `SetPriorityFOB` matches by 10 m tolerance; note it when refactoring.

## Closed 2026-09-03 (bug audit)

Fixed by commit 819cb2fd (core/controller-migration). `OVT_FOBRequestComponent.RpcAsk_SetPriorityFOB` (`Scripts/Game/Components/Controller/OVT_FOBRequestComponent.c:268-294`) now resolves the sender, refuses a non-officer, and refuses a caller more than 50 m from the FOB. The officer check is unconditional, stricter than this record proposed. Shipped in v1.5.0. No test exercises the rejection paths.
