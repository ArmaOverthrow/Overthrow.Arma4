> Filed from the `/discover-feature resistance/fob` code investigation (2026-08-09). Evidence is source-level; not yet reproduced at runtime.

## Symptom

Undeploying a Mobile FOB near someone else's camp (or another FOB's structures) silently destroys their tents, equipment boxes and built structures. The container-collection step at least empties nearby containers into the truck first, but structures without container storage (recruitment tents, ramps, walls…) are deleted outright, and the deletion honours no ownership or association boundary.

## Root cause

`OVT_ResistanceFactionManager.OnFOBCollectionComplete` (`Scripts/Game/GameMode/Managers/Factions/OVT_ResistanceFactionManager.c:1711-1766`) calls `CleanupFOBArea(fobPosition, 75.0)` (`:1630-1652`), whose `FOBAreaCleanupCallback` (`:1658-1682`) collects **anything** carrying an `OVT_PlaceableComponent` or `OVT_BuildableComponent` inside the sphere and runs `DeleteEntityAndChildren` on each.

Both marker components are stamped at spawn with owner UID + nearest-base association (`FindNearestBase` writes `persistentId` + `EOVTBaseType`), and the camp equivalent — `CleanupCampObjects` — **does** filter by `BelongsTo`. The FOB path never adopted the filter.

Compounding factor: `FindNearestBase` (`:1571-1624`) has no distance cap, so objects placed between a camp and an FOB may be associated with either — the filter fix needs the association to be trustworthy (see Notes).

## Fix (proposed)

Filter `FOBAreaCleanupCallback` by `BelongsTo(fobPersistentId, EOVTBaseType.FOB)`, mirroring `CleanupCampObjects`. Pass the FOB's `persistentId` into `CleanupFOBArea` (currently it only gets a position). Objects associated with *other* bases inside the radius are left standing — which is the correct outcome.

## Notes

- Known as an epic-level tech-debt cluster since the 2026-08-02 discovery ("CleanupFOBArea/CleanupCampObjects delete by radius with no association check") but never filed as an actionable bug; promoting the FOB half because undeploy is a routine player action, making accidental griefing of neighbours a live MP hazard, not a corner case.
- The uncapped `FindNearestBase` association drift is a separate (pre-existing) issue tracked in the resistance epic tech debt; a distance cap there would make this fix strictly better.
