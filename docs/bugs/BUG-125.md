> Filed from the `/discover-feature resistance/fob` code investigation (2026-08-09). Evidence is source-level; not yet reproduced at runtime.

## Symptom

Garrison groups purchased at an FOB (via the FOB menu, server-charged since BUG-047/064) are abandoned when the FOB is undeployed: the AI keeps holding a defend waypoint at a location that no longer has an FOB, the player gets no refund and no way to re-attach them, and on the next save/load the groups vanish entirely (their record went with the FOB, so `SpawnGarrisons` never replays them).

## Root cause

`OVT_ResistanceFactionManager.OnFOBCollectionComplete` (`Scripts/Game/GameMode/Managers/Factions/OVT_ResistanceFactionManager.c:1711-1766`) unregisters the FOB record but never despawns or transfers the entities in `fob.garrisonEntities`. The error path (`OnFOBCollectionError`, `:1770-1810`) shares the defect.

Camp removal has the same shape (`RemoveCamp`/`RemoveOldCamp` never despawn `garrisonEntities`) — noted in `resistance/core`'s docs since 2026-08-02; this filing makes the FOB half actionable and the camp half should be fixed with the same helper.

## Fix (proposed)

Before unregistering the record, iterate `garrisonEntities`, resolve each `SCR_AIGroup`, and either despawn it (simplest; optionally refund a fraction / return supporters to the nearest town — garrison hire draws supporters via `TakeSupportersFromNearestTown`) or convert survivors into the truck as "cargo" is out of scope. Extract as a shared `DespawnGarrison(record)` used by FOB undeploy, camp removal, and both error paths.

## Notes

- Distinct from BUG-121 (record leak on error path) — that is about the registry; this is about the live AI entities. Fixing both means the error path does: despawn garrison → unregister record → decide truck fate.
- The occupying-faction manager already has a despawn-groups-on-base-loss pattern to crib from.

## Closed 2026-09-03 (bug audit)

Obsolete. Commit cb6c9945 (resistance/high-command) removed purchasable FOB and camp garrisons. `OVT_FOBData` and `OVT_CampData` no longer hold garrison fields, and the serializer reads the old version-1 field and discards it (`OVT_ResistanceManagerSerializer.c:34-35`). Nothing can be orphaned on undeploy. Shipped in v1.5.0.
