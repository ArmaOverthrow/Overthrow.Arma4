> Filed from the `/discover-feature resistance/fob` code investigation (2026-08-09). Evidence is source-level; not yet reproduced at runtime.

## Symptom

When an officer who is not the vehicle's owner undeploys an FOB (a normal MP scenario — FOBs are shared infrastructure and any officer can undeploy), the `FOBUndeployed` confirmation (with its transferred-item count) is sent to the absent owner instead of the acting player. The actor gets no feedback; the owner gets a confusing notification about an action they didn't take.

## Root cause

`OVT_ResistanceFactionManager.OnFOBCollectionComplete` (`Scripts/Game/GameMode/Managers/Factions/OVT_ResistanceFactionManager.c:1735-1748`) derives the notification recipient from `vm.GetOwnerID(m_pCurrentMobileFOB)` — the vehicle-manager ownership of the freshly spawned truck (inherited from the deployed FOB, i.e. the original purchaser) — even though the initiating player is already tracked in `m_iFOBOperationPlayerId` (`:106`), which is exactly what the deploy-side targeted notifications use.

## Fix (proposed)

Use `m_iFOBOperationPlayerId` as the recipient. One-line change; check the error path (`OnFOBCollectionError`) for the same pattern while there.
