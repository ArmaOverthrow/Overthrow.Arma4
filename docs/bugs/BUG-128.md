> Filed from the `/discover-feature resistance/fob` code investigation (2026-08-09). Evidence is source-level; not yet reproduced at runtime.

## Symptom

During the (potentially long, batched) FOB deployment cargo transfer, players see the generic `#OVT-Progress-TransferringItems` progress label instead of the authored, localized "Deploying FOB" label. The undeploy side shows its specific label correctly (`#OVT-Progress-UndeployingFOB`).

## Root cause

`OVT_ResistanceFactionManager.DeployFOB` (`Scripts/Game/GameMode/Managers/Factions/OVT_ResistanceFactionManager.c:554`) calls the generic `transfer.TransferStorage(entity, newveh, false)`. The purpose-built `OVT_ContainerTransferComponent.TransferStorageForDeployment` (`Scripts/Game/Components/Controller/OVT_ContainerTransferComponent.c:76-139`), which starts the operation with `#OVT-Progress-DeployingFOB`, has no callers. The localization string exists (`Language/localization_Overthrow.st:5416`).

## Fix (proposed)

Call `TransferStorageForDeployment` from `DeployFOB` — verify its callback/completion contract matches what `OnFOBDeploymentComplete`/`OnFOBDeploymentError` subscribe to before switching (it may have drifted while dead). If it turns out redundant, delete it and pass the label through the generic path instead; either way the dead-code state ends.
