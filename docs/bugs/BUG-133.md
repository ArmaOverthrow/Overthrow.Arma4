## How this was found

Code reading during `/discover-feature map/core` (2026-08-10), on the `new-map` branch after it was merged up to date with `main` (`6b0169e4`). **Not observed at runtime** — the branch has not been play-tested since 2025-08-02. Filed as finding D1.

## Symptom (predicted)

Map location icons stay a single fixed size at every zoom level. The two configured size attributes on every location type have no effect, so the map does not declutter by shrinking icons when zoomed out — one of the stated reasons the new map system was built.

## Root cause

`OVT_MapLocationType.SetupIconWidget` resolves the widget it is meant to resize by name:

```
// Scripts/Game/UI/Map/Core/OVT_MapLocationType.c:321-330
SizeLayoutWidget sizeLayout = SizeLayoutWidget.Cast(iconWidget.FindAnyWidget("IconLayout"));
if (sizeLayout)
{
    int size;
    if (isSmall) size = m_iIconSizeSmall; else size = m_iIconSizeLarge;
    FrameSlot.SetSize(sizeLayout, size, size);
}
```

`UI/Layouts/Map/Core/OVT_MapLocationElement.layout` contains **no widget named `IconLayout`**. Its `SizeLayoutWidgetClass` is named **`IconContainer`** (layout `:53-54`) — the same name the element itself caches (`OVT_MapLocationElement.c:83`).

`FindAnyWidget` therefore returns null, the `if (sizeLayout)` guard swallows it, and the whole branch is skipped. The plumbing above it still runs: `ShouldUseSmallIcon()` computes the zoom comparison (`OVT_MapLocationElement.c:309-318`) and threads `isSmall` down through `UpdateIcon` → `SetupIconWidget`, where the result is discarded.

Consequently `m_iIconSizeSmall` (default 12) and `m_iIconSizeLarge` (default 24) are dead attributes on all ten configured types in `Configs/Map/OverthrowMap.conf`.

Most likely a rename (`IconLayout` → `IconContainer`) that was applied to the layout and the element but not to `OVT_MapLocationType`.

## Fix (proposed)

Change the lookup name to `"IconContainer"` in `OVT_MapLocationType.c:321`.

Before committing to that, confirm which widget is the intended resize target — `IconContainer` is the `SizeLayoutWidget` that wraps the icon, so it is almost certainly correct, but a play-test should verify the icon actually scales rather than the container clipping it.

## Notes

- This is one of two identical failures found in the same discovery — see **BUG-134**, where `ShowLocationInfo` wires a `CloseButton` that the info-panel layout also does not define. Both are silent: `FindAnyWidget` returning null is a no-op, and `tools/compile-check.sh` cannot see widget names at all.
- Worth doing a full layout↔code name audit across `Scripts/Game/UI/Map/**` while fixing this; the two known cases were found by spot-checking, not by an exhaustive sweep.
