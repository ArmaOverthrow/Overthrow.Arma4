## How this was found

Code reading during `/discover-feature map/core` (2026-08-10), on the `new-map` branch after merge to `main` (`6b0169e4`). **Not observed at runtime** — no play-test since 2025-08-02. Filed as findings D2 + D3, bundled here because they share one symptom and must be fixed together.

## Symptom (predicted)

Clicking a map location opens its info panel with no visible way to close it. The only dismissal is clicking an empty part of the map. On gamepad/console — where "click empty map space" is an awkward gesture — this is the difference between a usable panel and a stuck one.

## Root causes

**1. The close button does not exist.**

`ShowLocationInfo` wires a close handler by name:

```
// Scripts/Game/UI/Map/OVT_OverthrowMapUI.c:272-278
ButtonWidget closeButton = ButtonWidget.Cast(m_wInfoPanel.FindAnyWidget("CloseButton"));
if (closeButton)
{
    SCR_ButtonBaseComponent closeComp = SCR_ButtonBaseComponent.Cast(closeButton.FindHandler(SCR_ButtonBaseComponent));
    if (closeComp) closeComp.m_OnClicked.Insert(HideLocationInfo);
}
```

`UI/Layouts/Map/Core/OVT_MapInfoPanel.layout` defines no widget named `CloseButton`. Its named widgets are: `rootFrame`, `MainLayout`, `InfoBackground`, `InfoOverlay`, `InfoContainer`, `Header`, `HeaderBG`, `LocationName`, `LocationType`, `Distance`, `Owner`, `ContentSlot`, `FastTravelButton`, `FastTravelReason`, `OverthrowFastTravel`. The lookup returns null, the guard swallows it, and no handler is attached.

**2. Even if it existed, it would do nothing on a clicked panel.**

```
// Scripts/Game/UI/Map/OVT_OverthrowMapUI.c:291-297
void HideLocationInfo()
{
    if (m_bSelectionPinned)   // <-- early return
        return;
    ...
}
```

Any panel opened by *clicking* a location is pinned — `OnMapSelection` sets `m_bSelectionPinned = true` before calling `ShowLocationInfo` (`:52-59`). So `HideLocationInfo`, the handler the close button was meant to call, is a no-op in exactly the state where a user would reach for it.

The panel is only dismissable via `ForceHideLocationInfo`, which is reached from clicking empty map space (`:64-67`) or from `OnMapClose` (`:101`).

## Fix (proposed)

Two parts, both needed:

1. Add a `CloseButton` to `OVT_MapInfoPanel.layout` (Workbench), or drop the dead wiring if a close button is not wanted.
2. Point the button at `ForceHideLocationInfo` rather than `HideLocationInfo` — an explicit close should clear the pin, which is precisely what `ForceHideLocationInfo` does. Leave `HideLocationInfo`'s pinned guard alone; it exists so that hovering away does not tear down a deliberately pinned panel, which is correct behaviour.

Consider also giving the panel a keyboard/gamepad dismissal (e.g. the map's back/cancel action) rather than relying on a mouse target.

## Notes

- Same failure mode as **BUG-133** (`IconLayout` missing from the element layout). `FindAnyWidget` returning null is silent and invisible to `tools/compile-check.sh`.
- The interaction model here is *hover shows, click pins, click-empty dismisses* — not the conventional click-to-open. The dead close-button wiring suggests the panel was designed against a different model than the one that shipped.
