## How this was found

Code reading during `/discover-feature map/core` (2026-08-10), on the `new-map` branch after merge to `main` (`6b0169e4`). **Not observed at runtime** — no play-test since 2025-08-02. Filed as finding D7.

## Symptom (predicted)

Three things that look implemented do not happen:

1. **`OnLocationClicked` never fires.** It is part of the documented `OVT_MapLocationType` extension contract and its default implementation shows the info panel (`OVT_MapLocationType.c:116-121`). No shipped type overrides it, so nothing is visibly broken **today** — but the next location type author will reasonably override it and find their code never runs.
2. **The click sound never plays.** `m_sSoundClick` (`OVT_MapLocationElement.c:37-38`) is consumed only inside the dead method.
3. **Click-to-deselect does not exist.** The dead method implements "if already selected, deselect and hide the panel"; the live path has no equivalent.

## Root cause

`OVT_MapLocationElement.HandleSelection()` (`:105-136`) is `protected` and a repo-wide grep finds **no callers** — only its definition. It is the only caller of `m_LocationType.OnLocationClicked(...)` (`:134`).

Clicks are instead handled one level up, by the container subscribing to the map entity's selection invoker:

```
// Scripts/Game/UI/Map/OVT_OverthrowMapUI.c:89
m_MapEntity.GetOnSelection().Insert(OnMapSelection);
```

`OnMapSelection` (`:44-69`) pins whatever is currently hovered, or unpins on empty space. So the actual interaction model is **hover shows, click pins, click-empty dismisses** — driven entirely by `OnMouseEnter`/`OnMouseLeave` on the element (`:139-183`) plus the container's selection handler. The element's own click handling was written and then bypassed.

`GetClickRadius()` (`:468-482`) is dead for the same reason — it was presumably the hit-test for the abandoned click path.

## Fix (proposed)

Decide which model is intended, then make the code say so:

- **If hover-and-pin is the intended model** (it is what ships): delete `HandleSelection()`, `GetClickRadius()` and `m_sSoundClick`, and **remove `OnLocationClicked` from the `OVT_MapLocationType` contract** — or reimplement it so the container invokes it from `OnMapSelection` when a location is pinned. Leaving a documented virtual that never fires is the actual hazard here.
- **If click-to-select was intended**: wire `HandleSelection()` to the element's click event and reconcile it with `OnMapSelection` so the two do not both act on one click.

Whichever is chosen, the click sound and click-to-deselect should be resolved explicitly rather than left implied by dead code.
