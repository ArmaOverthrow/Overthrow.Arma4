## How this was found

Decoding `Configs/System/GunDealerConfig.conf` while building the gun-dealer map panel (`map/location-types` Phase 6, 2026-08-10) — the panel had to know which rows are per-dealer picks, which meant reading every rule. Recorded as finding **N17** and deliberately not fixed there (a config/economy defect, not a map defect). **Re-verified against the working tree 2026-08-11**, including the vanilla catalog data that makes it player-visible.

## Symptom

A gun dealer that rolled a sniper rifle sells the rifle and **no magazines for it**. The player buys an SVD and cannot feed it from any dealer in any town.

Second, milder effect: rifle magazines are added to every dealer **twice**, with two independent random quantities, so rifle ammunition stock is roughly double what the config appears to specify.

## Root cause

`Configs/System/GunDealerConfig.conf` pairs each weapon rule with an ammunition rule. Every pair names its type except one:

```
:45-50   OVT_ShopInventoryItem "{647C9C52CD61D256}" { m_eItemType SNIPER_RIFLE  m_eItemMode WEAPON  m_bSingleRandomItem 1 }
:51-54   OVT_ShopInventoryItem "{647C9C52CE140B08}" {                          m_eItemMode AMMUNITION                    }
```

which is byte-for-byte the same rule as

```
:26-29   OVT_ShopInventoryItem "{647C9C533634FD6A}" {                          m_eItemMode AMMUNITION                    }
```

the ammunition rule belonging to the RIFLE pair at `:21-25`. By position (immediately after the SNIPER_RIFLE weapon rule) and by the pattern of both neighbouring pairs — ROCKET_LAUNCHER `:34-39` + `:40-44`, MACHINE_GUN `:55-60` + its ammunition — `:51-54` was plainly meant to be `m_eItemType SNIPER_RIFLE`.

**An omitted type is not a wildcard, it is RIFLE:**

```
// Scripts/Game/GameMode/Managers/OVT_EconomyManagerComponent.c:26-27
[Attribute("2", desc: "Type of item", …, enums: ParamEnumArray.FromEnum(SCR_EArsenalItemType))]
SCR_EArsenalItemType m_eItemType;
```

`SCR_EArsenalItemType.RIFLE = 1 << 1 = 2` (vanilla `SCR_EArsenalItemType.c:4`), and `FindInventoryItems` never wildcards the type — `if(item.GetItemType() != type) continue;` (`:1511`) runs unconditionally, unlike the mode check just below it which honours `DEFAULT` as "any".

**Why the magazines really are missing:** vanilla types sniper magazines as `SNIPER_RIFLE` + `AMMUNITION`, on distinct prefabs from any rifle magazine — e.g. `Magazine_762x54_SVD_10rnd_Sniper.et` carries `m_eItemType SNIPER_RIFLE` / `m_eItemMode AMMUNITION` (`ArmaReforger/Configs/EntityCatalog/USSR/InventoryItems_EntityCatalog_USSR.conf:536-546`). No rifle rule can reach them, so nothing else in the config backfills the gap.

**Why it doubles rifle ammo:** neither ammunition rule sets `m_bSingleRandomItem`, so `SpawnGunDealer` takes the `else` branch and inserts **every** matching entry (`OVT_TownController.c:326-336`), and `AddToInventory` accumulates rather than sets (`OVT_PlayerCommsComponent.c:939`, `m_aInventory[id] + num`). Two identical rules therefore run twice over the same catalog entries, each rolling its own `RandFloatXY(1, GetTownMaxStock(...))`.

## Fix (proposed)

One line:

```
// Configs/System/GunDealerConfig.conf:51-54
OVT_ShopInventoryItem "{647C9C52CE140B08}" {
 m_eItemType SNIPER_RIFLE
 m_eItemMode AMMUNITION
 m_bIncludeOccupyingFactionItems 0
}
```

Then check the resulting stock levels: rifle ammunition halves back to the intended single roll, which is the correct outcome but is a visible economy change for existing campaigns. Nothing persists gun-dealer inventories (see BUG-144), so the change takes effect on the next campaign load with no migration.

**Audit the whole file in the same pass** — this is the second time an implicit-RIFLE default has been read as "all types" in this codebase. The rules at `:21-25` (WEAPON) and `:26-29` (AMMUNITION) rely on the same default *deliberately*, which is what makes the defective one hard to see. Making every rule state its type explicitly would cost four lines and remove the ambiguity permanently.

## Notes

- The map's gun-dealer panel already tolerates this: it lists only weapons with `stock > 0` and never claims ammunition is available.
- Occupying-faction items are excluded from every gun-dealer rule (`m_bIncludeOccupyingFactionItems 0`), so which sniper magazines appear after the fix still depends on the campaign's faction setup.
- Related default trap in the same attribute block: an `EQUIPMENT` rule with no `m_sFind` sweeps in support-station parts, which is BUG-098 — same file family, same "the default is broader than it looks" shape.

## Closed 2026-09-03 (bug audit)

Fixed by commit 9651570e. `Configs/System/GunDealerConfig.conf:51-55` rule `{647C9C52CE140B08}` now sets `m_eItemType SNIPER_RIFLE` with `m_eItemMode AMMUNITION`. Shipped in v1.5.0. Left as is: the rifle rules at lines 21-29 still rely on the implicit RIFLE default, and the new rule `{6A82A1B2C3D4E504}` omits its type.
