## How this was found

Code reading during `map/location-types` Phase 6 (2026-08-10) while establishing how the gun-dealer map marker reaches a client. Recorded as finding **N18**. **Re-verified against the working tree 2026-08-11**, including the start-order analysis below, which is what turns this from a theoretical gap into a reachable one.

## Symptom (predicted)

On an affected client:
- **No gun-dealer markers on the map**, in any town, for the whole session.
- Anything else that enumerates dealers client-side (`GetGunDealers()` `:945`, the nearest-shop search that scans `m_aGunDealers` `:875`) behaves as though the campaign has none.

The dealer NPC still exists in the world and can still be traded with face to face — the entity replicates normally. It is the *list* that is missing, so the player simply never learns where dealers are.

**Who is affected:** every client that was already connected when the campaign started. That is the normal listen-server flow — friends join the host's session, then the host presses Start.

## Root cause

`m_aGunDealers` has exactly one route to a client, and it is a snapshot:

```
// Scripts/Game/GameMode/Managers/OVT_EconomyManagerComponent.c:1257-1263
void RegisterGunDealer(EntityID id)
{
    IEntity entity = GetGame().GetWorld().FindEntityByID(id);
    RplComponent rpl = RplComponent.Cast(entity.FindComponent(RplComponent));
    if(rpl)
        m_aGunDealers.Insert(rpl.Id());
}
```

No `Rpc(...)`, no invoker, no `Replication.BumpMe()`. The list is written into `RplSave` (`:1908-1912`) and read back in `RplLoad` (`:1955`) — which runs **once**, when a client's replication session for this component is created. An insert after that point is invisible to everyone already connected.

**Why the timing is unlucky.** Shops and ports are scanned at world init, in `AfterInit` (`:1292`, `:1295`), long before any client can join — so `m_aAllShops` / `m_mTownShops` / `m_aAllPorts` are complete before the first JIP payload is ever built. Gun dealers are not: they are created when the **campaign starts**, not when the world loads.

```
DoStartGame() → OVT_TownManagerComponent.PostGameStart() (:197-211)
              → OVT_TownControllerComponent.ActivateTown() (:98-106)
              → CallLater(SpawnGunDealer, 0)  → RegisterGunDealer (OVT_TownController.c:342)
```

and `DoStartGame()` is triggered by a human on the host: `OVT_StartGameContext.StartGame()` (`:283-294`) calls `DoStartNewGame()` then `DoStartGame()` from the start menu. Any client connected at that moment has already taken its `RplLoad` snapshot with an empty dealer list. (On a dedicated server the campaign starts from `StartNewDedicatedGame()` before players connect, so that configuration is usually safe — but nothing enforces it, and a dealer added by any future code path would have the same problem there too.)

## Fix (proposed)

Give the registration a broadcast, mirroring the pattern already used in this codebase for late-registered records:

```
void RegisterGunDealer(EntityID id)
{
    IEntity entity = GetGame().GetWorld().FindEntityByID(id);
    if(!entity) return;                       // also fixes an unguarded deref (see BUG-140)
    RplComponent rpl = RplComponent.Cast(entity.FindComponent(RplComponent));
    if(!rpl) return;

    RplId dealerId = rpl.Id();
    if(m_aGunDealers.Contains(dealerId)) return;   // idempotent - the RPC lands on the host too
    m_aGunDealers.Insert(dealerId);

    if(Replication.IsServer())
        Rpc(RpcDo_RegisterGunDealer, dealerId);
}

[RplRpc(RplChannel.Reliable, RplRcver.Broadcast)]
protected void RpcDo_RegisterGunDealer(RplId dealerId)
{
    if(!m_aGunDealers.Contains(dealerId))
        m_aGunDealers.Insert(dealerId);
}
```

Points to get right:
- **Idempotence is required, not optional.** A broadcast RPC executes on the host as well, and `DoStartGame()` is documented as not re-entrant but *is* reachable twice in some restore paths — a duplicate entry would double-draw the marker.
- **`RplId`, not `EntityID`.** The list already stores `RplId`; do not widen the API.
- Send the RPC **after** the insert so host and client end in the same state regardless of ordering.
- Do not touch `RplSave`/`RplLoad` — the snapshot remains correct for genuinely late joiners, and the RPC covers the ones already present.

## Notes

- The map's gun-dealer type already carries a mitigation for a *different* symptom with the same feel: `m_aInventory` exists on a client only while the dealer entity is streamed in, so `OVT_MapLocationGunDealer.c:19-25` guards for it. The legacy map maintained an `m_aFailedGunDealers` retry list for the same reason (`OVT_MapIcons.c:357-380`, since deleted). Neither helps here — a missing id cannot be retried.
- Worth checking in the same pass whether any other campaign-start registration has the same shape. Ports and shops are safe by timing, not by design.
- Nothing in the automated spine can see this: the test world has no second client, so `RplSave` and the RPC path are equivalent there.
