## How this was found

Established while grounding a mid-run user directive during `map/location-types` Phase 6 (2026-08-10): the gun-dealer map panel was changed to list "what this dealer actually stocks", which required knowing how durable that answer is. Recorded as finding **N14**. **Re-verified against the working tree 2026-08-11.**

**Filed as a question, not a defect.** Nothing here contradicts a stated design; the behaviour may well be intended. It is filed because it is invisible from the code unless you go looking, and because at least one shipped feature had to be written around it.

## The behaviour

Each gun dealer rolls **four** per-dealer weapon picks — one RIFLE, one ROCKET_LAUNCHER, one SNIPER_RIFLE, one MACHINE_GUN (the four `m_bSingleRandomItem` rules in `Configs/System/GunDealerConfig.conf`). Everything else a dealer sells — all pistols, all ammunition, attachments, throwables, explosives — is identical at every dealer in the world. Those four picks are the only per-dealer information that exists.

They are re-rolled from scratch every time the campaign loads:

- **The roll is unseeded and global.** `int index = s_AIRandomGenerator.RandInt(0, entries.Count());` (`Scripts/Game/Controllers/OVT_TownController.c:310`) uses the engine's shared AI generator. There is no per-town or per-dealer seed anywhere in the codebase.
- **Nothing persists the result.** `Configs/Systems/Persistence/Overthrow.conf` lists no shop or shop-inventory serializer; `OVT_EconomyManagerSerializer` saves exactly two fields (resistance money and tax); and the dealer entity is explicitly excluded from persistence — `OVT_PersistenceManagerComponent.UntrackTransient(dealer)` (`OVT_TownController.c:276`), with the comment "respawned by this controller every session".
- **Only the location survives.** `OVT_TownData.gunDealerPosition` round-trips (`OVT_TownManagerComponent.c:89`, `:940`), so the dealer reappears in the same house with a different arsenal.
- **Within one session the roll is stable.** Restock tops up existing ids and never re-rolls (`OVT_EconomyManagerComponent.c:344-368`), so a player who finds an RPG dealer can go home and come back — until the campaign is reloaded.

## Why it is worth a decision

The four picks are the only thing that makes one dealer worth travelling to over another, so they are exactly the kind of fact a player learns and plans around ("the Levie dealer has the SVD"). Re-rolling them on load makes that knowledge worthless across sessions, which is a meaningful thing to choose deliberately rather than inherit.

Three defensible answers:

1. **Leave it.** Dealers restocking with different goods each campaign session is a legitimate flavour choice and keeps every load fresh. Cost: nothing, but write it down so the next person does not "fix" it.
2. **Seed per town.** Derive the generator from the town id (or persistent id) so a given town's dealer always rolls the same four. Cheap, needs no save data, and survives even a save wiped by hand. Cost: the four picks become fixed for the life of a world rather than a campaign.
3. **Persist the picks.** Save the rolled ids alongside `gunDealerPosition` (which already persists) and re-apply them instead of rolling. Most faithful, most work: it needs a serializer touch and a migration story for existing saves.

## Live consequence

`map/location-types` Decision 7 shipped the gun-dealer panel listing these four weapons, and its copy was deliberately written **present-tense** — "this dealer stocks X", never "always stocks X" — because of this. If option 2 or 3 is taken, that constraint can be relaxed; if option 1 is chosen, the constraint must stay, and it should be recorded here rather than only in a feature doc.

## Notes

- Related but separate: `RandInt` is **max-exclusive**, so `RandInt(0, entries.Count())` at `:310` is correct as written — this is not an off-by-one report.
- Town size gates only whether a dealer *exists* (`ActivateTown` skips `OVT_TownSize.VILLAGE`, `:100-103`) and how much stock it gets via `GetTownMaxStock`; it never changes which items are picked.
- The re-roll is also why BUG-141 (sniper ammunition never stocked) needs no save migration — the next load rebuilds every dealer's inventory from config anyway.
