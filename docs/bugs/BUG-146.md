## How this was found

Player reports: "when you recruit a civilian and arm them they are beyond useless — they run from a fight, don't shoot." Investigated 2026-08-13 immediately after the tower-guard fix, which established exactly how Reforger AI decides to fire (the only fire nodes in the entire AI live inside the attack behavior's trees; see `docs/features/occupying/base-upgrades/context.md` Gotchas).

## The disproven hypothesis (worth keeping)

The initial theory was that civilian characters lack combat behavior trees and the recruit body would need to be swapped for a military character and re-dressed. **This is false** and the entity-swap fix would have changed nothing:

- The complete combat AI stack — `ChimeraAIControlComponent`, `PerceptionComponent`, `SCR_AICombatComponent`, agent template `SCR_ChimeraAIAgentFull.et` (which carries ALL reactions incl. `SCR_AIGoalReaction_Attack`), and `Soldier.bt` — lives on `Prefabs/Characters/Core/Character_Base.et` (vanilla, :247-295), inherited **identically** by civilian and soldier prefabs.
- There is no civilian behavior tree, no panic BT, no "civilian mode" flag anywhere in the 1.7 engine. Civilian meekness is emergent **data**: the CIV faction is friendly to everyone (`Configs/Factions/Non-Combatant.conf`) so `IsEnemy()` never returns true; and an AI with no weapon **or no magazines** converts threats into retreat targets (`SCR_AICombatComponent.EvaluateWeaponAndTarget` → `GetMostRelevantTargetCantAttack` → `RetreatFromTarget.bt`).
- `Character_CIV_Recruit.et` inheriting `Character_CIV_base.et` is therefore fine as-is; the recruit flow already sets the entity's affiliated faction to FIA at recruit/respawn time (`OVT_RecruitManagerComponent.SetRecruitFaction`, `:1675-1721`, called at `:841` and `:1505`), and joining the player's slave group does not clobber it (`SCR_AIGroup.OnAgentAdded` touches no faction).

## Root cause (updated after play-test falsified the first fix)

**Primary: recruits never actually left the CIV faction.** `OVT_RecruitManagerComponent.SetRecruitFaction` resolved the *vanilla* `SCR_FactionManager.GetPlayerFaction(playerId)` — but Overthrow players never go through vanilla faction selection, so that returns null (early return) or CIV (making the `currentFaction != playerFaction` guard false, skipping the FIA assignment). Either way the recruit stayed affiliated CIV — friendly to every faction — so no enemy classification, no danger reactions (no turning toward gunfire), no combat. Play-test confirmed: recruits with rifles **in hands** and magazines (i.e. with the disguise-gate bypass below active) still ignored everything, which isolates the affiliation as the blocker. Fixed: `SetRecruitFaction` now assigns `OVT_Global.GetConfig().m_sPlayerFaction` unconditionally, with no dependency on the vanilla per-player faction registry. Both the recruit path and the body-restore path call it, so existing saves heal on next load.

## Root cause (secondary)

`Scripts/Game/AI/Modded/SCR_ChimeraAIAgent.c` — the disguise logic (added so undercover recruits wouldn't cower from occupying patrols) gates BOTH `IsPerceivedEnemy(IEntity)` and `IsEnemy(Faction)`:

```
if (myWantedComp && myWantedComp.GetWantedLevel() < 1)
    ...
    return false;   // "no one is enemy to me" — for EVERY target
```

A recruit whose **own** wanted level is 0 can never classify anyone as an enemy. `SCR_AITargetReaction_SelectedTargetChanged.CreateAttackActionForTarget` (the ONLY constructor of `SCR_AIAttackBehavior`, vanilla `SCR_AITargetReaction.c:76-115`) therefore never runs. **And it is a deadlock:** a recruit only becomes wanted by acting hostile, which this gate prevents. So recruits stay pacifist through every firefight their owner drags them into — regardless of faction, group, weapon, or ammo.

## Fix (implemented 2026-08-13, VERIFIED IN PLAY — armed recruits engage)

1. **`SetRecruitFaction` rewritten** (primary, see above) — recruits are always affiliated to the configured resistance faction.
2. **The disguise gate only pacifies genuinely unarmed recruits**: both `SCR_ChimeraAIAgent` overrides skip the civilian-disguise branch when the recruit owns any weapon — `OVT_PlayerWantedComponent.HasAnyWeapon()`, a new check covering hands AND weapon slots. (`IsVisiblyArmed()` only sees the weapon currently in hands, so a slung rifle read as "unarmed" — wrong signal for combat-capability, kept unchanged for the player wanted-escalation.) Handing a recruit a weapon is the switch that makes them fight; unarmed recruits keep the fearless-civilian behavior the gate was written for.
3. **Slave groups get the resistance faction** (`Scripts/Game/Modded/SCR_AIGroup.SetSlave`) — vanilla never factions the commanding slave group and the master is CIV by design (players register civilian), so the group brain (perception clusters, danger sharing, combat-mode evaluation) never ran for recruit squads; `SetFaction` also re-asserts member affiliation.

Residual: **unarmed** recruits walk backwards while following orders — filed separately as BUG-147 (suspected UNKNOWN-target stare: OF is neither friendly nor — while unarmed — enemy, so the look system pins their gaze). A probe script for recruit combat state lives at `.tmp/probe-recruit-state.c` (Script Console, prints affiliation/hostility/AI-active/group per recruit).

## Secondary findings (not fixed here, note for future work)

1. **Give recruits magazines, not just a rifle.** Vanilla retreat path: a weapon with no compatible mags still produces "can't attack" → flee. Player-facing docs/help should say this; nothing in code enforces it.
2. **The player group's slave group has no faction.** `Group_Player.et` (ours) sets no root `m_faction` and vanilla slave-group creation (`SCR_GroupsManagerComponent.c:1255-1280`) never calls `SetFaction` on the slave. A faction-less group fails `SCR_AIGroupUtilityComponent.IsMilitary()`, so **group-level** perception clusters and combat-mode evaluation never run for recruit groups — individual reactions carry all combat. Works, but group coordination (danger sharing, combat mode) is silently absent. Worth a look if recruit squads still feel passive after this fix.
3. **`Group_CIV.et:4-8` AI-disable flags are ~dead**: of `m_Skill 0 / m_EnablePerception 0 / m_EnableAttack 0 / m_EnableAimingError 0`, only `m_EnablePerception` has any consumer in 1.7 (`SCR_AIFindTargetToLookAt.c:32`), and group-level config is not read by member agents anyway. Misleading, essentially no-op.
4. **Perceived faction ≠ affiliation:** with `FULL_OUTFIT` perceived-faction mode, a recruit in civvies is *perceived* as CIV by enemies — enemies ignore them until they act. That is arguably the disguise feature working; it does not stop the recruit from firing.
