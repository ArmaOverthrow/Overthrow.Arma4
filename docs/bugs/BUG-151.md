## Symptom, two halves

1. `Update()` walks `m_Widgets` and, for a player whose controlled entity cannot be resolved, calls `SetOpacity(0)` on that player's marker widget — and **nothing ever sets it back**. There is no `SetOpacity(1)` anywhere in the class. A player briefly without a controlled entity (respawning) has an invisible marker for the **rest of the map session**, even once alive again. A map close/reopen — which rebuilds the widget set — is the only recovery.
2. `m_Widgets` is populated in `OnMapOpen` (and cleared there, at the top) but is **not cleared on map close**. Between sessions the component holds `Widget` references to widgets the engine has destroyed. Latent rather than active: `Update()` is the only reader and does not run between close and open — but it is one added caller away from being a crash.

**Where:** `Scripts/Game/UI/Map/Visualization/OVT_MapPlayerLocation.c` — symbols `Update()`, `m_Widgets`, `OnMapOpen`, `OnMapClose`.

## Constraint on the fix

`map/map-layers`' player-row toggle (`SetMarkersVisible`) uses **`SetVisible`, never `SetOpacity`**, precisely so the toggle and this defect cannot interact — and `Update()` early-returns while markers are hidden, so the two cannot fight over the same widgets. **A fix must not "unify" the two by converting the toggle to opacity.**
