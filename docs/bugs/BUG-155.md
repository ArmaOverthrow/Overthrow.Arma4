## Symptom (observed on gamepad, 2026-08-13 Phase 7 pass)

With the map layers panel open and a row focused, pressing **D-pad Left** unticks the row **and** leaves the panel, so the player must re-enter the panel through the tool strip for every layer they want to switch off. Phase 4b predicted the first half (the `OverthrowMapLayersContext` `MenuLeft` shadow over `MapToolMenuFocus` — `SCR_ToolboxComponent` steps YES→NO on `MenuLeft` alone with `m_bCycleMode` false); **the panel-exit half was not predicted**. Either both actions fire despite the priority-70 context, or the toolbox's own `MenuLeft` handling moves focus out of the row list — undiagnosed.

The same session closed the easy fix: **pressing A on a focused row does nothing** (the toolbox does not listen to `MenuSelect` without multiselect), so `MenuLeft` is load-bearing for unticking and cannot simply be dropped from the context.

**Where:** `Configs/System/chimeraInputCommon.conf` (Overthrow) — `ActionContext OverthrowMapLayersContext`; `Scripts/Game/UI/Map/OVT_MapLayersUI.c` (per-frame activation while the panel is open); `Scripts/Game/UI/Map/Core/OVT_MapLayerRowComponent.c` (row wiring).

## Suggested fix shape

Give `OVT_MapLayerRowComponent` its own `MenuSelect` listener so **A toggles the focused row** (the checkbox state change goes through the existing owner callback, never a second state path). Once A toggles, `MenuLeft`/`MenuRight` become droppable from `OverthrowMapLayersContext`, which un-shadows `MapToolMenuFocus` — D-pad Left then returns to the tool strip cleanly, matching vanilla's map-panel conventions. Diagnose the panel-exit half first; if it persists with `MenuLeft` removed, the exit has a different source than the shadow.

## Provenance

Found by the user's Phase 7 gamepad pass (2026-08-13) — the only F-series finding found by observation rather than code reading. Recorded as F7 in `docs/features/map/map-layers/findings.md` and `tasks.md`.

## Audit 2026-09-03

The panel-exit half now has a cause. `OverthrowMapLayersContext` (`chimeraInputCommon.conf:1319-1329`) has Flags 0x26 with no exclusive bit, so vanilla `MapToolMenuFocus` on D-pad Left fires with `MenuLeft` (BUG-156 rule). The fix shape in this record still holds: a `MenuSelect` listener on `OVT_MapLayerRowComponent`, then drop `MenuLeft` and `MenuRight`. Flags 0x8 alone would only make the untick half deliberate.
