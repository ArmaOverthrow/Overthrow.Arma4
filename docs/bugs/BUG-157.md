## Symptom (observed on gamepad, 2026-08-13)

Rotating a placeable with X/Y moves it ~1 degree per button press; holding the button does nothing further, so any real rotation means mashing — and mashing Y trips vanilla's double-tap weapon switch (that half is BUG-156's suppression to fix).

## Mechanism

`OVT_PlaceContext.RegisterInputs` already listens with the **continuous** trigger — `AddActionListener("OverthrowRotateLeft"/"OverthrowRotateRight", EActionTrigger.PRESSED, …)` — which fires every frame while the action's value is live (vanilla uses PRESSED for exactly this, e.g. editor camera rotation). The asymmetry is in the conf: in `Action OverthrowRotateLeft`/`OverthrowRotateRight`, the keyboard sources (`KC_COMMA`/`KC_PERIOD`) have **no filter** — hold-to-repeat works there — while the gamepad sources (`gamepad0:x`/`gamepad0:y`) each carry an **`InputFilterDown`**, which clips the value to the press edge: one PRESSED fire per physical press.

## Fix shape

Remove the `InputFilterDown` filter blocks from the two gamepad `InputSourceValue` entries so pad and keyboard sources match; the existing PRESSED listener then repeats while held. Check the resulting rate at the handler (`RotateLeft`/`RotateRight` apply a fixed step per call, so per-frame firing ≈ step × framerate degrees/sec — if too fast, scale the step or gate by an accumulator, matching whatever the keyboard already feels like, since that path has always been continuous).

Sequence after BUG-156: with the context raised to Priority 45, holding Y to rotate no longer risks the double-tap equip at all, so this fix is pure ergonomics.
