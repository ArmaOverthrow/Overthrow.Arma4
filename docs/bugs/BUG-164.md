**Fix target: the `main` / 1.4.x monolith** (`OVT_PlayerCommsComponent.c`). On the `v1.5` branch this
entire class is already fixed structurally by `core/controller-migration` (the monolith no longer
exists there); this bug carries the hotfix onto `main` since 1.5 is some way out. Security-class
defects (arbitrary-entity delete, dismiss-any-recruit, possess-any-entity, warehouse string injection,
remote medical-supply looting) are deliberately **excluded** — they need an altered client and are
superseded by 1.5.

## Mechanism (one root cause, ~20 buttons)

Nearly every public entry point on `OVT_PlayerCommsComponent` is an **unconditional
`Rpc(RpcAsk_…)`** with no `Replication.IsServer()` direct-call branch. An `RplRcver.Server` RPC
marshalled **by the authority is delivered to nobody** (BUG-045/052/088 family). Dedicated-server
clients are fine — but for a **listen host or SP player** (who IS the authority) the request is a
dropped packet: no action, no error, no log line. The button just does nothing.

## Affected requests (code-derived on the 1.4.x monolith)

- **Save from the main menu** — `RequestSave()` is an unconditional `Rpc()`; on a listen host the
  Save button never started a save (found in P8 of the migration). Interacts with BUG-006's old
  "menu claims success" behaviour.
- **Vehicles:** lock, unlock (via the user actions), and the host side of the
  claim/upgrade/repair/import/buy-vehicle entry points.
- **Radio-tower sabotage** — `OVT_TowerSabotageComponent.RequestSabotage()` has the same shape (this
  one is on the controller component, not the monolith; fixed in place on v1.5 — port the same
  4-line fix).
- **Real estate:** buy / sell / rent / stop-renting / set-home.
- **Economy:** donate, send resistance funds, send money, set tax, buy skill (buy-items itself is
  BUG-161).
- **Resistance ops:** place item, build item, remove placed, add officer, add garrison; camp/FOB:
  garrison camp/FOB, deploy, undeploy, set-priority, camp privacy, delete camp.
- **Recruits:** recruit civilian, recruit from tent, rename, dismiss.
- **Loadouts:** save / apply-from-box / delete.

**Separate but same family — `OVT_OpenInventoryCommand` (recruit inventory) never worked on dedicated
servers at all:** `SCR_CommandingManagerComponent.RPC_DoExecuteCommand` is `RplRcver.Broadcast` and
the command's `if (isClient) return true;` meant the body only ran on the authority — which then did
a self-Rpc. Fix: gate with `playerID != SCR_PlayerController.GetLocalPlayerId()` so the body runs on
exactly the commanding player's machine, and give the send the IsServer branch.

## Minimal fix on main

For each public entry point, apply the project's standard rule:

```c
if (Replication.IsServer())
    RpcAsk_TheHandler(args);   // direct call — authority never Rpc()s itself
else
    Rpc(RpcAsk_TheHandler, args);
```

No handler bodies need to change (the handlers are fine once actually invoked). Watch the two
handlers whose internals also self-Rpc: `RpcAsk_Buy` pays via `Rpc(RpcAsk_TakePlayerMoney)` /
`Rpc(RpcAsk_TakeFromInventory)` — that half is **BUG-161**, fix together (call the two handlers
directly, exactly as `RpcAsk_BuyVehicle` already does); and `SendNotification()`'s dropped self-Rpc
is **BUG-162** (call `OVT_Global.GetNotify().SendTextNotification` directly).

## Verification

Code-derived; per-path runtime confirmation on 1.5 rides the migration's §6 MP play-test. On main,
spot-check as a listen host after the fix: Save from the menu produces a real save file; locking your
own car works; one real-estate purchase; one donate. Note some SP flows may have masked individual
paths via other mechanisms — treat any path that already works on main as evidence that entry point
had a direct-call branch, not as a reason to skip the rest.

## Closed 2026-08-14

Fixed on `main`. 52 public entry points on `OVT_PlayerCommsComponent` plus
`OVT_TowerSabotageComponent.RequestSabotage` now carry the standard branch. Two things the report
above did not anticipate:

- **The reply direction needed the same treatment**, or the ask-side fix would have made a host
  worse rather than better. `RpcDo_SaveResult` (the Save menu blocks on its invoker) and
  `RpcDo_DoneTakingMoney` (which clears the `takingMoney` latch — without it the *first* host debit
  would have wedged every later one) are `RplRcver.Owner` and equally dropped once the authority is
  the requester. Both now branch on a new `IsLocalServerRequest()` helper ("am I the game mode's
  copy on the authority"), which leaves the dedicated-server path sending over the wire unchanged.
- **`OVT_OpenInventoryCommand` needed no change.** The proposed `playerID != GetLocalPlayerId()`
  re-gate is unnecessary: the entry-point branch alone is sufficient, the body stays on the
  authority (where `SetPossessedEntity` must run), and the existing `RpcDo_OpenInventory` broadcast
  already reaches the commanding client.

Also fixed in passing: `ImportToVehicle`'s `Rpc(...)` was missing its semicolon.

**Deliberately still open — `ConvertSupporter`.** Same defect, not in this bug's list, and unlike
every other entry point its handler derives the player, the distance check and the cooldown from
`GetOwner()` being a character — while `OVT_Global.GetServer()` hands a host the game mode's copy.
A plain `IsServer` branch there returns immediately, so it needs a routing change and its own bug.

Verified: compile clean, All group 142/142, and a listen-host play-test of save-from-menu, shop buy,
vehicle lock/unlock, a real-estate purchase, donate, tower sabotage and recruit inventory.
