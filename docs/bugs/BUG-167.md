**Found by the recruit-ux Phase 8 docs fact-check (2026-08-14).**

The join-group confirmation dialog counts the player's **entire** roster: `SCR_GroupSubMenuBase.c:444-462` → `GetRecruitCount(persistentId)`. Since recruit-ux, the actual transfer excludes recruits that are holding position (`OVT_GroupRecruitTransfer.c:84`, skip + `outSkippedInactive`), so a player with e.g. 3 active + 2 parked recruits is told 5 will come when only 3 move.

**Fix shape:** the dialog should count active recruits only — `GetPlayerRecruitsByState(persId, false).Count()` (public manager API added in recruit-ux Phase 1), or an active-only variant of `GetRecruitCount`. Cosmetic/consistency only; the transfer itself is correct.

The wiki (`player-groups` page) was worded around this in the meantime ("the join dialog counts the whole roster").
