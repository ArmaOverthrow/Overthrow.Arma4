## How this was found

Code inspection during the 2026-08-14 disguise-icon investigation. Matches player reports
of the wanted/undercover HUD showing stale state.

## Problem

`OVT_WantedInfo.UpdateValues` only called `InitCharacter()` while `m_Wanted` was null.
`InitCharacter` resolved `m_Wanted` / `m_Percieve` / `m_FactionAffiliation` from
`SCR_PlayerController.GetLocalControlledEntity()` — but after death the old character's
components stay alive on the corpse (player bodies are deliberately kept, and since
BUG-130/131 reserved bodies can persist a long time), so `m_Wanted` never went null and
the HUD kept polling the **previous** body's wanted level, seen state, recognition factor
and disguise state after respawn or possession switch. Rebinding only happened if the old
entity was actually deleted.

## Impact

After any death/respawn (or entity switch via possession), the wanted stars, seen-eye and
undercover clothes icon show the corpse's frozen state instead of the live character —
e.g. a permanently dark eye and white undercover icon regardless of current disguise.
Self-heals only when the old body despawns.

## Fix

`Scripts/Game/UI/HUD/OVT_WantedInfo.c`: `UpdateValues` now tracks the controlled entity
in `m_BoundCharacter` and re-runs `InitCharacter()` whenever it changes (or `m_Wanted` is
null). `InitCharacter` clears all three component references up front so controlling a
non-character (or nothing) detaches the HUD from the old body instead of silently keeping
it, and the undercover widget lookup is now cached one-time instead of per rebind.
