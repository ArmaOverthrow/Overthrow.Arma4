## Report

Server owner (#overthrow-reforger, 2026-08-15 03:31 UTC): "Me and my guys are having trouble with
radios, we cant hear eachother no matter what faction radio." Tried both US and FIA radios bought
from shops. Setting `VONCanTransmitCrossFaction: true` in `gameProperties` did **not** help. Reported
as new behaviour ("We havent experienced this until today"). Proximity/direct voice was not reported
as broken. Party had also been using Game Master, which they suspected — it is not implicated by the
code below.

**Not yet play-test confirmed.** Diagnosis is from code + vanilla source only; see "Confirmation" below.

## Two independent causes. Fixing either one alone does not restore radio comms.

### Cause 1 — every player is on a different radio frequency (the regression)

Since `core/player-groups` (146b1bed, 2026-08-06) every player gets their **own private group** on
every spawn:

- `Scripts/Game/Respawn/Logic/OVT_SpawnLogic.c:955` — `EnsureOwnGroup(playerId)` on every spawn
- `Scripts/Game/GameMode/Managers/OVT_PlayerGroupManagerComponent.c:262` — `CreateNewPlayableGroup(faction)`
- `Scripts/Game/GameMode/Managers/OVT_PlayerGroupManagerComponent.c:363-370` — `BrandOwnGroup`:
  `SetPrivate(true)`, `SetPrivacyChangeable(false)`

Vanilla gives **every playable group a unique radio frequency** and then **auto-tunes each player's
radio to their own group's frequency at spawn**:

- `ArmaReforger/scripts/Game/Groups/SCR_GroupsManagerComponent.c:1254` — `CreateNewPlayableGroup`
  calls `AssignGroupFrequency(group)`
- `.../SCR_GroupsManagerComponent.c:705-716` — `AssignGroupFrequency` → `GetFreeFrequency` claims an
  unused frequency from the 38000–54000 pool (`m_iPlayableGroupFrequencyMin/Max`, `:16-19`)
- `.../SCR_GroupsManagerComponent.c:25-26` — `m_bTunePlayersRadioToGroupFrequency` defaults to **1**
- `.../SCR_GroupsManagerComponent.c:1740-1741` — hooks `TunePlayersFrequency` to `OnPlayerSpawned`
- `.../SCR_GroupsManagerComponent.c:1671-1698` — `TunePlayersFrequency` sets transceiver 0 to
  `GetActualGroupFrequency()`

Overthrow does not override any of this: `m_bTunePlayersRadioToGroupFrequency` is not set in
`Prefabs/GameMode/OVT_OverthrowGameMode.et:278-283`, and **no code in `Scripts/` ever calls
`SetFrequency`, `SetEncryptionKey` or touches `BaseRadioComponent` / `RadioTransceiver`** (grep is
clean). So two players end up on two different frequencies and physically cannot hear each other,
regardless of radio model. `VONCanTransmitCrossFaction` has no effect on this — which is exactly what
the reporter observed.

The groups are also `SetPrivate(true)` with `SetPrivacyChangeable(false)`, so players cannot simply
join one shared group from the group menu to share a frequency; only a leader invite gets them there.

### Cause 2 — the starting radio's encryption key does not match the player faction (long-standing)

- Players are assigned the **FIA** faction: `OVT_OverthrowConfigComponent.c:81-82` (`m_sPlayerFaction`
  defaults to `"FIA"`) → `Scripts/Game/Respawn/Logic/OVT_SpawnLogic.c:993-1056` `SetCivilianFaction`.
  Vanilla `Configs/Factions/FIA.conf:10` → radio encryption key **`candleSauce`**.
- The starting radio in every difficulty preset is `Prefabs/Items/Equipment/Radios/Radio_R148.et` —
  the **USSR** radio, `"Encryption key" "coldBorscht"`:
  `Configs/Difficulty/Difficulty_Normal.conf:23`, `Easy:36`, `Hard:37`, `Extreme:38`, `Insane:40`,
  `TestWorld:12`. Present since 0dca031f (2023-09-04).
- `ArmaReforger/scripts/Game/VON/SCR_VONController.c:555-573` (`ActivateVON`): when
  `VONCanTransmitCrossFaction` is false and the player is not admin, it compares the **held radio's**
  baked encryption key against the **local player faction's** key (`InitEncryptionKey`, `:801-810`).
  On mismatch it refuses radio transmit, forces proximity VON and shows the "VON disabled" hint.
- US radios are `chickenNuggets` (`Radio_ANPRC68.et:5`), USSR `coldBorscht`. The only `candleSauce`
  radios are `Radio_R148_FIA.et:5` and `Radio_R107M_FIA.et:5` — **neither is referenced anywhere in
  the mod**, including the shop catalogs.

This is why enabling `VONCanTransmitCrossFaction` has historically been the documented workaround
(wiki: dedicated-server-setup → common issues): it defeats cause 2 only.

Also worth noting: vanilla's `SCR_VONAutoTune.SetRadios` (`scripts/Game/VON/SCR_VONAutoTune.c:63-68`)
looks up radios *by the player faction's encryption key*, so it cannot find an FIA player's USSR
radio either — the mod gets no help from that path.

## Confirmation (cheap, no code change)

Two players in one session open the radio/VON menu and read their frequency. Different numbers
confirms cause 1. Then have both manually tune to the same frequency — if they can talk, cause 1 is
the whole player-visible break and cause 2 is being masked by the server's
`VONCanTransmitCrossFaction: true`.

## Workaround for server owners today

Manually tune both radios to the same frequency, and re-tune after each respawn (the spawn hook
overwrites transceiver 0). Keep `VONCanTransmitCrossFaction: true` set.

## Fix direction (NOT to be implemented on v1.5 — user will do this on `main` after the GM work lands)

1. **Frequency.** Put all player groups on one shared resistance net: after `EnsureOwnGroup` creates
   the group, call `group.SetRadioFrequency(sharedFreq)`. The frequency pool only guards
   *auto*-assignment (`GetFreeFrequency`/`ClaimFrequency`), so an explicit set is legal and keeps the
   per-player private groups intact. Alternative: clear `m_bTunePlayersRadioToGroupFrequency` on
   `SCR_GroupsManagerComponent` in `OVT_OverthrowGameMode.et` so radios keep their prefab frequency —
   simpler, but leaves the group frequency shown in the UI lying about the radio.
2. **Encryption.** Change `startingItems` in all six difficulty presets to `Radio_R148_FIA.et`
   (`candleSauce`), and make sure the FIA radio variants — not the US/USSR ones — are what the shops
   sell. That makes radio VON work without requiring `VONCanTransmitCrossFaction`, i.e. on a default
   dedicated server config.

Both are needed. (1) alone leaves servers dependent on the cross-faction setting; (2) alone still
leaves every player on their own frequency.

## Play-test to confirm the fix

Two clients, dedicated server, `VONCanTransmitCrossFaction` **absent/false** in `gameProperties`.
Both players spawn fresh, take the starting radio, and must hear each other on squad radio at range
without touching the frequency dial. Then both die and respawn — must still work (proves the spawn
re-tune is consistent). Direct/proximity voice must be unaffected.
