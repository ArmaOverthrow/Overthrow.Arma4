## Symptom

Placing a base-game waypoint on an AI group in the Game Master editor throws a Virtual Machine Exception:

```
ScriptInvoker: Recursive call of Invoke!
Class: 'SCR_AIGroup'
Function 'OnWaypointAdded' — SCR_AIGroup.c:2528 appears TWICE in the stack
```

Reported by user 2026-08-16 during gm/waypoint-viz Phase 4 verification (Workbench, fresh session).

## Root cause — pure vanilla, pre-existing

The recursion only occurs for a group whose editable component has a **cycle waypoint** (`SCR_EditableGroupComponent.m_CycleWaypoint`) — and **every Overthrow perimeter patrol is cycled** (`OVT_OverthrowConfigComponent.GivePatrolWaypoints` nests all waypoints in one `AIWaypoint_Cycle`), so in Overthrow this crashes on essentially every patrol group. Chain (all vanilla frames, zero Overthrow frames in the stack):

1. GM places waypoint → engine `AddWaypoint` → `SCR_AIGroup.OnWaypointAdded` → `Event_OnWaypointAdded.Invoke(wp)` (invoke #1, `SCR_AIGroup.c:2528`)
2. `SCR_EditableGroupComponent.OnWaypointAdded` (`:208`): `wp != m_CycleWaypoint` → `waypoint.SetParentEntity(this)`
3. → `OnParentEntityChanged` → `AddToParent` → `AddChild` → `OnChildEntityChanged` (`:849` region): because `m_CycleWaypoint` is set, it inserts the new waypoint into the cycle's children, strips the group's waypoints, then calls **`m_Group.AddWaypoint(m_CycleWaypoint)`**
4. That `AddWaypoint` synchronously re-enters `Event_OnWaypointAdded.Invoke` while invoke #1 is still on the stack → VM exception.

Overthrow has **zero** subscriptions to `Event_OnWaypointAdded` and no `OnWaypointAdded` override (grep-verified); `gm/waypoint-viz` is strictly read-only and does not participate. The bug predates waypoint-viz — the feature just made GMs actually interact with Overthrow groups, exposing it (exactly the epic's I-5 check).

## Repro

1. Start a campaign, let a base/town spawn a perimeter patrol (cycled waypoints).
2. Open GM, select the patrol group, place any waypoint (e.g. Move) for it.
3. VM exception, every time. A vanilla GM-*created* group (no cycle) does not crash.

## Possible fixes (needs a decision)

- **Workaround in Overthrow:** mod `SCR_EditableGroupComponent.OnChildEntityChanged` (or `OnWaypointAdded`) to defer the `m_Group.AddWaypoint(m_CycleWaypoint)` re-add one frame via `CallLater(..., 0)` — breaks the synchronous re-entry. Forks vanilla editor behaviour; needs care around the `RemoveWaypointAt(0)` loop and MP authority.
- **Upstream report:** this looks reproducible in vanilla Conflict with any cycled group; candidate for the RFG series (check `docs/reforger` upstream report list before filing — RFG/ARMD series already has 8 submitted).
- Epic Phase 3 ("base-game GM cleanup") is the natural home for the decision.
