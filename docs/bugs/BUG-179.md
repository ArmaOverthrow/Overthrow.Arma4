**Historical defect in the pre-2026-08-17 town civilian spawner, found while planning `virtualization/civilians` and fixed by the migration.** Filed for history — the fix already landed with the migration (Phase 2).

`OVT_TownControllerComponent.DespawnCivilians()` did `SCR_EntityHelper.DeleteEntityAndChildren(aigroup)` and nothing else. Group members are spawned as **world-root** entities by `SCR_AIGroup.SpawnGroupMember` (`SCR_AIGroup.c:1658-1757` — no `AddChild`, no `spawnParams.Parent`), the group destructor only destroys *edit-mode* scene instances (`:3391-3409`), and vanilla's own `DespawnMembers` deletes controlled entities **explicitly** (`:2897-2906`). So deleting the group entity left **every civilian character standing in the town**, plus their free-standing waypoint entities.

**Impact:** every "player left the 1000 m ring" event leaked a town's worth of characters for the session — AI-count/performance creep in long sessions, visible ghost crowds.

**Fix:** shipped in the `virtualization/civilians` migration — `OVT_TownCivilianSourceConfig.OnEntityDespawning` deletes member characters explicitly (`GetAgents()` → `GetControlledEntity()` → `RplComponent.DeleteRplEntity`) before core deletes the group.
