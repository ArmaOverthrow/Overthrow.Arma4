**Historical defect in the pre-2026-08-17 town civilian spawner, found while planning `virtualization/civilians` and fixed by the migration.** Filed for history — the fix already landed with the migration (Phase 2).

`SCR_AIGroup.GetOnAgentAdded()` publishes an **`AIAgent`** (see `OVT_LoadoutUtils.RandomizeCivilianClothes(AIAgent)` and `OVT_BaseUpgradeTowerGuard.c:190`, same signature), but `OVT_TownController.DisableCivilianWantedSystem(IEntity)` called `FindComponent(OVT_PlayerWantedComponent)` **on the agent entity**, where that component does not exist — it silently found nothing and returned. `m_bWantedSystemEnabled` defaults **true**, so town civilians have been running with the wanted system live the whole time, despite being meant to be exempt.

**Impact:** gameplay — civilians participated in the wanted system (aim-at/proximity wanted escalation could trigger off civilians).

**Fix:** shipped in the migration — `OVT_TownCivilianSourceConfig.OnCivilianAgentAdded(AIAgent)` resolves `agent.GetControlledEntity()` before the component lookup, so the disable now actually works (deliberate behaviour change, recorded as decision D11).
