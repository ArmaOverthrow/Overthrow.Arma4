Found by the user in the `virtualization/civilians` play-test (2026-08-17): VM-exception spam `NULL pointer to instance` in `OVT_VehicleManagerComponent.FilterKerbAddToArray` (:264) via `FindNearestKerbParking` (:220) from the ambient vehicle `RollPosition`.

**Root cause (pre-existing latent bug):** `GetNearestParkingSpot` allocates `m_aParkingSearch`; `FindNearestKerbParking` only `.Clear()`s it and the query filter `.Insert()`s into it. All three pre-existing callers happened to run after some allocation; the ambient parked-vehicle source can call `FindNearestKerbParking` **first** in a session, so the filter dereferences a null array once per queried entity (hence the spam). Vehicle placement still worked because the kerb failure fell through to the road-derived path.

**Fix:** `FindNearestKerbParking` now allocates a fresh array instead of clearing (mirrors `GetNearestParkingSpot`), same semantics for existing callers. One line + comment in `OVT_VehicleManagerComponent.c`.
