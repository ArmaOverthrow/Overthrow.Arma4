## Symptom (player report, 2026-08-18)

Picking a location on the respawn screen spawns the player **inside geometry** — inside the deployed
FOB truck, inside house walls, etc. The authored `OVT_SpawnPointComponent` points on those prefabs are
ignored. "Respawn at home" is unaffected.

## Root cause

The chosen-location path is the **only spawn path that never consults the spawn-point query**:

1. `OVT_RespawnService.CollectEligiblePositions` (`Scripts/Game/Services/OVT_RespawnService.c:251`)
   records **raw entity origins**: `base.location`, `fob.location` (the deployed truck's origin),
   `camp.location`, `house.GetOrigin()`.
2. `ResolveRespawnPosition` (`:395`) correctly uses the client's vector only as a lookup key and
   returns the server's recorded vector — which is that same raw origin.
3. `OVT_SpawnLogic.CompleteRespawn` (`Scripts/Game/Respawn/Logic/OVT_SpawnLogic.c:1662`) passes it to
   `CreateFreshCharacterAt(..., true, resolvedPos)`, whose contract is to use the chosen position
   **as given** (`:358-361` — "re-deriving or re-safety-checking it here would move the player away
   from the location they deliberately picked"). The premise was wrong: the recorded vector was never
   a standing position, it is the origin of the base controller / FOB truck / camp tent / house
   building.

Contrast: the HOME path goes through `GetCreationPosition` → `EnsureClearSpawnPosition` (`:905`),
which heals a colliding vector via `OVT_Global.FindSafeSpawnPosition` **with** its spawn-point branch
(`Scripts/Game/Global/OVT_Global.c:433-467`) — a 15 m `QueryEntitiesBySphere` for
`OVT_SpawnPointComponent`, returning an authored point. Those components exist on exactly the prefabs
players are clipping into: `OverthrowMobileFOBDeployed.et`, `OVT_RecruitmentTent.et`, `OVT_Camp.et`,
`OVT_BaseController.et`, and the spawn-point house variants.

## Fix

`OVT_SpawnLogic.CompleteRespawn`: after the eligibility match succeeds, route `resolvedPos` through
`OVT_Global.TryFindSafeSpawnPosition` before handing it to `CreateFreshCharacterAt`. The raw origin
remains the lookup key both machines agree on (`MATCH_TOLERANCE` matching is untouched); only the
spawn moves — to the location's own authored spawn point when one is within 15 m, else to a
traced-clear spot nearby, else (loud WARNING) the recorded origin, which is today's behaviour.
`CreateFreshCharacterAt`'s "used as given" doc comment updated to state the caller now heals the
vector first.

## Acceptance check (manual — no automated gate can see this)

1. Deploy a mobile FOB, die, pick the FOB on the respawn screen → arrive at the truck's authored
   spawn point, not inside the truck.
2. Repeat for a camp, a captured base, and an owned house with an authored spawn point → arrive at
   the authored point.
3. Pick a location whose surroundings author no spawn point → arrive on clear ground near it, never
   inside geometry.
4. "Respawn at home" unchanged.
