## Symptom (server-owner reports, 2026-08-18)

Players do not disappear on disconnect: their body stands frozen where they logged out, visible to
everyone, but cannot be killed or interacted with.

## Root cause

The BUG-086 reservation model deliberately keeps a disconnected player's body (and an offline
owner's locked vehicle) alive, tracked, and hidden in place via
`OVT_PersistenceReservation.Reserve()` → `ClearFlags(VISIBLE | TRACEABLE | ACTIVE)`. Those flags
are LOCAL engine calls — measured during BUG-086 and documented on the class as a "cosmetic"
residual for clients already streaming the entity. In practice it is worse than cosmetic:

- a client already streaming the body keeps rendering its own copy (the documented residual), and
- a client that streams it in LATER — JIP, or walking into range — receives the prefab's default
  flags, i.e. fully visible. Every client on a dedicated server sees the ghost.

Unkillable/uninteractable is correct behaviour (TRACEABLE is cleared on the authority, where hits
and use-actions resolve); visible was not meant to survive.

## Fix

`OVT_ReservationSyncComponent` (new): `[RplProp(onRplName: "OnReservedChanged")] bool m_bReserved`,
mirrored by `Reserve()`/`Release()` (the only writers) and applied on each proxy as
`ClearFlags/SetFlags(VISIBLE | TRACEABLE)` locally. RplProp state rides the streaming snapshot, so
JIP and late-streaming clients get it too. ACTIVE is deliberately not cleared on proxies — they
must keep accepting replication updates; simulation is the authority's, which already cleared it.
Same pattern as vanilla `SCR_ResourceComponent.m_bIsVisible`.

Wired into the prefabs whose instances can be reserved:
- `Prefabs/Characters/Factions/INDFOR/FIA/Character_Player.et` (`{6B0F52A100000003}`)
- `Prefabs/Vehicles/Core/Wheeled_Base.et` (`{6B0F52A100000001}`)
- `Prefabs/Vehicles/Core/Helicopter_Base.et` (`{6B0F52A100000002}`)

The component is optional: an entity without it keeps the old authority-only behaviour.

## Test

`OVT_TEST_Init_Persistence_ReservationReplicatesToClients` — pins the prefab wiring (vehicle chain
by spawning, character chain via the spawn logic's default-prefab attribute) and the
Reserve()/Release() mirror both ways. Can-fail method in the case header; the proving run is owed.
