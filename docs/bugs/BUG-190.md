## Symptom

Using the "Set priority FOB" action on a deployed FOB truck has no effect — no error, no result.

## Root cause

`OVT_SetPriorityFOBAction.PerformAction()` passed `pOwnerEntity` — the cargo-canvas slot child the action lives on, not the FOB truck. On main's monolith path its origin is a local offset, so the server's 10 m position match against the FOB record never hit; on v1.5's controller path the child has no RplComponent of its own, so the RplId lookup fails. Either way the action silently did nothing.

## Fix

Pass `pOwnerEntity.GetParent()` — what the sibling `OVT_DeployFOBAction`/`OVT_UndeployFOBAction` already pass. Applied to the v1.5 controller pattern at merge time.
