> ID note: fixed on main 2026-08-20, where the session numbered it BUG-188 locally; filed as BUG-192 at merge time — v1.5 numbering had already reached BUG-187.

## Symptom

FOBs on dedicated-server clients can end up with no recorded owner, with the same downstream symptoms BUG-177 had for camps (behaviour depending on an owner id that is empty).

## Root cause

BUG-177 fixed `RpcDo_RegisterCamp` to carry the persistent id string resolved ONCE on the server, but the FOB path kept re-deriving the owner from the runtime playerId on the receiving client — racing the player-id table's own replication and, on a lost race, permanently recording owner `""`.

## Fix

`RpcDo_RegisterFOB` now receives `ownerPersistentId` resolved once on the server, exactly as `RpcDo_RegisterCamp` does (`OVT_ResistanceFactionManager.c`).
