**Found during `core/damage` Phase 1 (spike question S5), 2026-08-20 — shipped-code defect independent of that feature.**

The buildable Bunkers prefab `PrefabsEditable/Auto/Props/Military/Sandbags/E_Sandbag_01_bunker_plastic_foundation_camonet.et` has **no active `RplComponent`** anywhere in its chain on `main`:

1. The Overthrow delta declares no `RplComponent`.
2. Parent `Prefabs/Props/Military/Sandbags/Sandbag_01_bunker_plastic_foundation_camonet.et` — none.
3. Grandparent `Sandbag_01_bunker_plastic_foundation.et:20-21` declares `RplComponent "{5E76C88E937D49B8}" : "{3B686EF5E3C610B9}Prefabs/Props/Core/DestructionMultiPhase_Rpl_Base.ct" { }` and overrides nothing.
4. That preset is `RplComponent { Enabled 0 }`.
5. Vanilla's own sibling that wants replication re-declares it `Enabled 1` (`Prefabs/Compositions/Misc/CustomEntities/DestructionEntities/Sandbag_01_bunker_plastic_CompositionDestruction.et:7-9`).
6. Bunkers is a live buildable at cost 750 (`Configs/Resistance/buildables.conf:53-64`).

**Consequences:** with no `RplComponent` a built bunker has no `RplId`, so `OVT_ResistanceRequestComponent.RpcAsk_RemovePlacedItem(RplId)` can never name one — **dismantle is unreachable for a built bunker**. Wider question to confirm in MP: does a built bunker replicate to clients at all (JIP/stream-in)?

**Status:** the `core/damage` retrofit on `v1.5` authors `RplComponent "{5E76C88E937D49B8}" { Enabled 1 }` on the prefab, which fixes it forward there; `main` still carries the defect until that merges. Evidence is from the prefab chain — an in-game dismantle attempt on a fresh build is the confirming repro.

## Closed 2026-09-03 (play-test passed)

Play-test on a dedicated server passed on 2026-09-03: a client built a Bunker at an FOB, saw it after a rejoin, and dismantled it from the client. Fix: `E_Sandbag_01_bunker_plastic_foundation_camonet.et:72-74` re-declares the inherited `RplComponent` (commit 00949009, in v1.5.0).
