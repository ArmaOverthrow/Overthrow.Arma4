## Summary

`Prefabs/Vehicles/Wheeled/M923A1/OverthrowMobileFOB.et:13` sets `Description "#OVT-MobileFOBDescription"`, but that key exists **nowhere** — not in the `.st` master and not in any exported `.conf`. Wherever the Mobile FOB's description is drawn, the literal string `#OVT-MobileFOBDescription` appears instead of English text.

## Evidence

```
$ grep -c '"OVT-MobileFOBDescription"' Language/localization_Overthrow.st
0
$ grep -rl "OVT-MobileFOBDescription" Language/ Configs/
(no matches)
```

Sibling keys **do** exist, which is what makes this look like a simple omission rather than a rename:

```
Language/localization_Overthrow.st:9186:   Id "OVT-MobileFOB"
Language/localization_Overthrow.st:9195:   Id "OVT-MobileFOBHelp"
```

## Pre-existing, not introduced

Found incidentally during the `logistics/resources` Phase 11 localization audit. The `logistics/resources` work touches `OverthrowMobileFOB.et`, but only to add a cargo-store block — `git diff` on that file is exactly:

```
+  OVT_ResourceStoreComponent "{6A8E2E0000000010}" {
+   m_fCargoVolume 8
+  }
```

Line 13 is untouched and the missing key predates the branch.

## Fix

Add an `OVT-MobileFOBDescription` entry to `Language/localization_Overthrow.st` beside `OVT-MobileFOB` / `OVT-MobileFOBHelp`, with a filled `Comment` and a fresh GUID, then re-export the localization `.conf` files from Workbench.

⚠️ Never hand-write `Language/*.conf` / `Configs/Language/*.conf` — they are Workbench build output. Edit only the `.st` master, and count the braces before and after (an unbalanced `.st` means the next Workbench save eats entries).

## Closed 2026-09-03 (bug audit)

Fixed by commit c525181d. `Language/localization_Overthrow.st:12136` now holds `OVT-MobileFOBDescription` with en-us and ru-ru text, and all seven exported `.conf` files carry the key. Shipped in v1.5.0.
