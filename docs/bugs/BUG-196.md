## Symptom (player reports, 2026-09-01)

Using **Catch a bus** at a bus stop, or **Show on Map** in the High Command roster, opens the
fullscreen map and the player cannot get out of it again. Escape does nothing, the map key does
nothing. The map opened with the map key behaves normally.

## Root cause

`OVT_MapContext.ShowMap()` opened the map by calling `SCR_MapGadgetComponent.SetMapMode(true)`
directly. That is the _view_ toggle only — it queues `ToggleMapGadget(true)`, which opens
`ChimeraMenuPreset.MapMenu` — and it never touches the gadget's mode. The map item stays stowed, so
`SCR_GadgetManagerComponent.m_HeldGadget` / `m_HeldGadgetComponent` stay null.

Two consequences, both fatal:

1. `SCR_GadgetManagerComponent.Update()` (`:1195`) early-returns and calls
   `DisconnectFromGadgetsManagerSystem()` when there is no held **and** no hidden gadget — so it stops
   ticking. Its last statement (`:1232`) is the only place in the game that activates
   **`GadgetMapContext`**, and that context (`chimeraInputCommon.conf`, Priority 55, Flags 0x2) is the
   only one carrying **`MapEscape`** (Escape / gamepad B) and **`GadgetMap`** (M). With the context
   never activated, neither input is bound while the map is open.
2. `OnPauseMenu()` — the `MapEscape` handler — gates on
   `SCR_MapGadgetComponent.Cast(m_HeldGadgetComponent)`, so Escape would be a no-op even if the
   context were active.

Both reported entry points are the only two callers of `ShowMap()`:
`OVT_CatchBusAction.PerformAction` → `OVT_MapContext.OpenMap()`, and
`OVT_HighCommandRosterContext.ShowOnMap()`. `OVT_RecruitsContext.ShowOnMap` and
`OVT_JobsContext.ShowOnMap` only write a waypoint and never raise the map, which is why they are
unaffected.

This is the mirror image of the close-side defect already documented in `OVT_MapContext.HideMap()`:
`SetMapMode` is not a substitute for a gadget mode change in either direction.

## Fix

`Scripts/Game/UI/Context/OVT_MapContext.c` — `ShowMap()` now raises the map the way pressing the map
key does: `SCR_GadgetManagerComponent.SetGadgetMode(gadget, EGadgetMode.IN_HAND)`. Vanilla's
`SCR_MapGadgetComponent.ModeSwitch` then fires `ToggleFocused(true)`, which calls `SetMapMode(true)`
itself, and the held-gadget state is consistent, so `GadgetMapContext` activates and Escape / the map
key close the map normally. If the map is already the held gadget, `SetMapMode(true)` is kept for that
one case (the view may be unfocused while the item is in hand).

The header comment on `ShowMap()` records why `SetMapMode(true)` must never be called from a
not-in-hand state.

`OVT_HighCommandRosterContext.ShowOnMap()` needs no change: its selection is already deferred to
`SCR_MapEntity.GetOnMapOpenComplete()`, which still fires — the raise animation just adds one more hop
before it.

## Verification

Compile: `tools/compile-check.sh` exit 0 (6357 files, Game module).

Runtime acceptance is manual — no automated gate can press Escape:

1. At a bus stop, **Catch a bus** → map opens → press **Escape** → map closes and the map item is
   stowed, not left in hand.
2. Same, but close with the **map key** instead of Escape.
3. Gamepad: **Catch a bus** → press **B** → map closes.
4. High Command roster → **Show on Map** → the group is selected on the map → Escape closes it.
5. Raise the map with the map key first, then Escape — unchanged vanilla behaviour.
6. **Catch a bus** while the map is already in hand and open → no double-raise, map stays usable.
