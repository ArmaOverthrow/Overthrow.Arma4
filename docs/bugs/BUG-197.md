## Symptom (player report, #overthrow-reforger, 2026-09-03)

A player took four UAZ-469 PKMs and one BRDM-2 from the occupying faction. Only one of them shows
on the map. The vehicle menu shows a blank owner for the other vehicles. A vehicle that survives a
server restart shows on the map. A vehicle that the player took after the last restart does not.

## Root cause

Ownership lives in two places:

- `OVT_PlayerOwnerComponent.m_sOwnerUID` on the vehicle (an RplProp). Lock and unlock, the get-in
  gate, the garbage system, and persistence read this field.
- `OVT_RplOwnerManagerComponent.m_mOwned` and `m_mOwners` on the vehicle manager. The key is the
  RplId. The server sends this map to JIP clients. `OVT_MapLocationVehicle.PopulateLocations` reads
  it through `m_Vehicles.GetOwned(persId)`. `OVT_VehicleMenuContext` reads it through `GetOwnerID`.

Each path that gives a vehicle to a player writes both places. `SpawnVehicleMatrix`,
`AdoptRespawnedVehicle`, `RebuildVehicle`, and the post-load re-index (BUG-129) all do this. The
path for a stolen vehicle did not.

`OVT_VehicleRequestComponent.RpcAsk_ClaimUnownedVehicle` called
`SetPlayerOwner` and `RegisterPlayerVehicle` only. `RegisterPlayerVehicle` maintains the persistence
registry, not the owner map. Thus the claimed vehicle was owned, lockable, and saved, but it was not
on the map, and the menu showed no owner.

The claim handler never wrote the owner map. The first version (89e15752, 2025-06) is older than the
map marker (map/location-types, 7ddfbb8b). The post-load re-index does write the owner map. This is
why a stolen vehicle shows on the map after a server restart, and not before.

## Fix

`Scripts/Game/Components/Controller/OVT_VehicleRequestComponent.c`: `RpcAsk_ClaimUnownedVehicle`
now calls `SetOwnerPersistentId(playerUid, vehicle)` before `RegisterPlayerVehicle`. This is the
same pair of calls that `SpawnVehicleMatrix` makes. A RplComponent check guards the call, as at the
other call sites.

## Verification

Compile: `tools/compile-check.sh` exit 0 (6357 files, Game module).

Manual, on a dedicated server with one client:

1. Sit in the driver seat of an occupying-faction vehicle that nobody owns.
2. Open the map. The vehicle marker is there at once, with no restart.
3. Open the vehicle menu. The owner line shows the name of the player.
4. Walk out of streaming range and open the map again. The marker goes away. See Known limitation.
5. Connect a second client to the same server. The second client does not see the marker.

## Known limitation (not fixed here)

`GetOwned` resolves each RplId through `Replication.FindItem`. Thus a client lists only the
vehicles that the server streams to it at that time. An owned vehicle outside the replication
range of the client has no marker. The player report about a vehicle that is far away is this
limitation. It is separate from the claim defect.
