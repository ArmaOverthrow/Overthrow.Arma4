## Symptom (player report, #overthrow-reforger, 2026-09-03)

A player took four UAZ-469 PKMs and a BRDM-2 from the occupying faction. Only one of them shows on
the map. The vehicle menu shows a blank owner for the missing ones. Vehicles that survived a server
restart show up; freshly stolen ones never do.

## Root cause

Ownership lives in two places:

- `OVT_PlayerOwnerComponent.m_sOwnerUID` on the vehicle (RplProp). Lock/unlock, the get-in gate, the
  garbage system and persistence read this one.
- `OVT_RplOwnerManagerComponent.m_mOwned` / `m_mOwners` on the vehicle manager (RplId-keyed,
  JIP-synced). `OVT_MapLocationVehicle.PopulateLocations` (`m_Vehicles.GetOwned(persId)`) and
  `OVT_VehicleMenuContext` (`GetOwnerID`) read this one.

Every path that gives a player a vehicle writes both — `SpawnVehicleMatrix`, `AdoptRespawnedVehicle`,
`RebuildVehicle`, and the post-load re-index (BUG-129) — except the one a stolen vehicle goes
through. `OVT_VehicleRequestComponent.RpcAsk_ClaimUnownedVehicle` called `SetPlayerOwner` and
`RegisterPlayerVehicle` only. `RegisterPlayerVehicle` maintains the persistence registry, not the
owner map, so the claimed vehicle was owned, lockable and saved, but absent from the map and shown
as owner-less in the menu.

The claim handler has never written the owner map: the original (89e15752, 2025-06) predates the map
marker (map/location-types, 7ddfbb8b). The post-load re-index does write it, which is why a stolen
vehicle appears on the map after the server restarts and not before.

## Fix

`Scripts/Game/Components/Controller/OVT_VehicleRequestComponent.c` — `RpcAsk_ClaimUnownedVehicle`
now calls `SetOwnerPersistentId(playerUid, vehicle)` before `RegisterPlayerVehicle`, the same pair
`SpawnVehicleMatrix` performs. Guarded on the RplComponent as the other call sites are.

## Verification

Compile: `tools/compile-check.sh` exit 0 (6357 files, Game module).

Manual, on a dedicated server with a client:

1. Get into the driver seat of an occupying-faction vehicle nobody owns.
2. Open the map — the vehicle marker is there immediately, without a restart.
3. Open the vehicle menu — the owner line shows the player's name.
4. Walk out of streaming range and reopen the map — the marker is still expected to drop out, see
   Known limitation.
5. A second client on the same server does not see the marker (owner-only).

## Known limitation (not fixed here)

`GetOwned` resolves each RplId through `Replication.FindItem`, so a client only lists vehicles that
are currently streamed to it. An owned vehicle beyond the client's replication range has no marker.
The same player's "I can't see it from further away" is this, and it is independent of the claim
defect.
