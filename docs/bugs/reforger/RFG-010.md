## Summary

An **unarmed** character driven by `SCR_AIMoveInFormationBehavior` (`KeepInFormation.bt`) backpedals almost constantly: its body stays fixated on a world position (often nothing visibly there) and locomotion resolves as strafing/walking backwards toward the formation slot. Armed characters in the same formation are unaffected, and unarmed characters on ordinary individual/waypoint moves are unaffected — the defect is specific to the combination *empty hands + formation move*.

Vanilla gameplay never fields unarmed formation-followers, so this is mostly a modding-facing defect (mods that put civilians or disarmed characters into player-commanded groups hit it immediately).

## Mechanism (traced in 1.7.0.54 script/BT source)

1. `LookAction.bt` runs permanently in parallel with the active behavior (`Soldier.bt:196-199`). It is fed by `SCR_AILookAtThreatSystemLogic` → `SCR_AISectorThreatFilter`: **averaged threat-sector estimates** with `SECTOR_FORGET_S = 45.0` (`scripts/Game/AI/Components/SCR_AISectorThreatFilter.c:19`), refreshed by mundane danger events (doors, horns, physics contacts). This produces aim targets at world positions where nothing actually is, held for up to 45 s — the "fixated on a random sticky direction" the player sees.
2. An active aim request pins the character's yaw. With a weapon in hands the yaw is absorbed by the weapon/torso aiming layer and the body keeps facing the movement direction; with empty hands the requested yaw is realized as **full-body heading**, so the mover backpedals.
3. `KeepInFormation.bt` contains no facing/aim/look management at all — unlike `MoveIndividually.bt:41-52`, which re-establishes upper-body state on entry (weapon-raised + stance), which is why unarmed characters on individual moves do not exhibit the bug. The only aim-stop in the entire vanilla BT set is `AITaskCharacterStop` with `"Stop flags" 2`, present in exactly one tree (`LookAction.bt:23, :190, :264`) and gated on the current behavior's `m_bAllowLook`.
4. Additionally, `KeepInFormation.bt:258-265` sets `OrientationType ToPoint` on its `AITaskMoveInFormation` node while leaving `InTargetOrientation` unconnected (`-1`) — an orientation-to-point request with no point supplied. It is the only vanilla move node in that state (`MoveIndividually.bt:76/:105` leave `OrientationType` at the engine default; every other `ToPoint` user feeds a real position, e.g. `Defend.bt:322-327`, `CombatMoveRequest_Move.bt:505-513`).

## Steps to reproduce

1. Put an unarmed character (e.g. a civilian, or any character with its weapons removed) into a player-commanded group (commanding slave group) so that its movement is driven by `SCR_AIMoveInFormationBehavior`.
2. Walk around as the group leader, or issue move orders, in an environment with occasional ambient danger events (a town works; enemies are NOT required).
3. Observe the follower: it fixates on a direction (varies per occurrence, sticky once acquired) and walks backwards/strafes to keep facing it, often for the entire move.

## Observed

Persistent backpedaling; body heading pinned to a stale threat-sector estimate; no target, `EAIThreatState.SAFE`, no enemies present (verified via agent state dump: current action `SCR_AIMoveInFormationBehavior`, combat target null).

## Expected

An unarmed formation-follower faces its movement direction like an unarmed character on an individual move does.

## Suggested fix

Either of:
- Have `KeepInFormation.bt` re-establish/clear upper-body state the way `MoveIndividually.bt` does (or issue `AITaskCharacterStop "Stop flags" 2` on entry), and/or not request `OrientationType ToPoint` without a connected point;
- Or have the character-side aim realization ignore/expire aim requests that cannot be absorbed (no weapon in hands) while a locomotion target is active.

## Workaround (modded, ships in Overthrow)

`modded class SCR_AIMoveInFormationBehavior` — `OnActionSelected()` sets `m_bAllowLook = false` when `m_Utility.m_CombatComponent.GetCurrentWeapon()` is null, which routes through the existing `SCR_AIDecoBehaviorAllowsLooking` gate into `LookAction.bt`'s own aim-stop. Armed followers keep full look behavior; the flag self-cleans when the behavior ends.
