## Summary

1.8.0.10 adds a new `EntityPersistenceConfig` for buildable compositions (`{6968896F29096D64}`,
inheriting `Configs/Systems/Persistence/Configuration/Building/BuildableComposition.conf`) to the
shared `Structures` persistence group — but connects it to a collection **only** in
`EditableMission.conf`. Neither the entity config itself, nor the `Structures` group, nor
`Common.conf`, nor `Mission.conf` assigns it a collection. Since an unconnected entity
configuration is a **fatal** initialization error, any persistence config that inherits
`Common.conf` or `Mission.conf` directly — the documented extension points for modded game modes —
now fails to initialize entirely:

```
DEFAULT   (E): [PERSISTENCE] Failed to connect entity configuration '6968896F29096D64' to collection ''.
DEFAULT   (E): [PERSISTENCE] Persistence system could not be initialized. See previous errors for details. No progress will be saved!
```

Every vanilla shipping mode inherits through `EditableMission.conf` (GameMaster directly; Conflict
via `Conflict.conf` → `EditableMission.conf` → `Mission.conf` → `Common.conf`), which patches the
collection in — so the base game never hits this. Mods that used `Common.conf`/`Mission.conf` as
their base in 1.7 (where they were valid, self-consistent configs) get a completely dead
persistence system on updating to 1.8, with no save/load at all.

## Steps to reproduce

1. Create a minimal mod with a persistence config inheriting the shared base, e.g.:
   ```
   PersistenceSystemConfig : "{3A03B52D11F7C36A}Configs/Systems/Persistence/Common.conf" {
   }
   ```
   (inheriting `{8532E1DD4E714D95}Configs/Systems/Persistence/Mission.conf` reproduces identically)
2. Register `SCR_PersistenceSystem` with that config in the world's systems config and load any world.
3. Observe the two `[PERSISTENCE]` errors above in the log; `SCR_PersistenceSystem` state is
   FAILURE and nothing is ever saved or loaded.

On 1.7.0.54 the identical config initializes cleanly (the entity config did not exist yet).

## Observed

- `Configs/Systems/Persistence/Group/Entities/Structures.conf:11` (new in 1.8) declares
  `EntityPersistenceConfig "{6968896F29096D64}" : "{9316504DE39FAD9B}Configs/Systems/Persistence/Configuration/Building/BuildableComposition.conf"`
  with an empty body.
- `Configuration/Building/BuildableComposition.conf` (new in 1.8, moved from
  `Configuration/Editor/`) declares a rule, priority, and serializers — but **no `Collection`**.
- `Common.conf:203-215` (`PersistenceConfigGroup Structures`) connects the *other* structure
  configs to the Structure collection `{65B4DD18C4F30AC9}` (`{65B682661F79DDBE}` Building,
  `{65E07D0515A16C1F}` Static, `{65D48532390E1D96}` Composition) — `{6968896F29096D64}` is missing
  from this list.
- `Mission.conf` contains no reference to `{6968896F29096D64}` either.
- `EditableMission.conf:77-79` is the **only** place the config is connected:
  ```
  EntityPersistenceConfig "{6968896F29096D64}" {
   Collection "{65B4DD18C4F30AC9}"
  ```
- Result: `Common.conf` and `Mission.conf` are internally inconsistent — they include an entity
  configuration that can never connect, which the initializer treats as fatal for the whole system.

## Expected

Either of:
- `Common.conf`'s `Structures` group connects `{6968896F29096D64}` to `{65B4DD18C4F30AC9}`
  alongside its three siblings (one-line fix, matches the clear intent of `Common.conf:203-215`), or
- the entity config is introduced at the `EditableMission.conf` level rather than in the shared
  `Structures` group, so the shared bases stay self-consistent.

Alternatively (defensively): an entity configuration without a collection could degrade to a
per-config warning instead of failing the entire persistence system — an unconnected config
contributes nothing, but killing all persistence over it turns a content oversight into a total
save-system outage.

## Workaround (shipped in Overthrow)

`Configs/Systems/Persistence/Overthrow.conf` adds the missing connection in its own delta,
mirroring `EditableMission.conf`:

```
PersistenceConfigGroup Structures {
 Configurations {
  EntityPersistenceConfig "{6968896F29096D64}" {
   Collection "{65B4DD18C4F30AC9}"
  }
 }
}
```

Fragile for the ecosystem: every mod inheriting the shared bases needs to discover this
independently, and the failure mode (persistence silently absent, two log lines) is easy to miss
until players report lost progress.
