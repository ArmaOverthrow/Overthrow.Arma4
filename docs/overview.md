# Overthrow - Project Overview

**Last Updated:** 2026-08-06
**Version:** v1.9

## Project Summary

Overthrow is a dynamic, persistent revolution mod for Arma Reforger, built on EnforceScript and the Enfusion engine's entity-component architecture. Towns have populations, stability and support that shift over time; money, gear, vehicles, houses and recruits persist across sessions. Current engineering priority is the **dev-ops epic** — replacing the manual Workbench/play-testing quality gate with automated compile checks, an autotest suite and CI, built on Reforger 1.7.0's shipped tooling.

## Integration Points

- **dev-ops → core/persistence:** the epic's future `test-coverage` feature writes behaviour-level persistence tests (no EPF/vanilla API in assertions) that become core/persistence's acceptance gate on resume. The compile check already guards its API assumptions (~5s feedback).
- **dev-ops feature #1 → #2/#4/#5:** `tools/README.md` is the stable contract (commands, exit codes 0/1/2/124, `KEY=value` launcher output, `OVERTHROW_*` env overrides). Sibling features consume it without reading script source.

## Changelog

- v1.9 (2026-08-06): **core/player-groups built (issue #147, second half) — 30/31 tasks, 6 phases in one autorun, awaiting MP play-test.** Players can finally squad up. Every player's group is now **private by default** and named after them; joining someone else's goes through vanilla's request/approve (and invite/accept) flow behind an **Overthrow confirmation dialog** that names the other leader and your exact recruit count; and the governing rule — **recruits are owned by a player, not a group** — is enforced server-side: they follow their owner into and out of any group, the group's leader commands them while they are there, but dismiss/rename/inventory/loadout/XP never transfer and they come back when you leave, switch or reconnect. New `OVT_PlayerGroupManagerComponent` (stateless server-side reactor on `SCR_AIGroup`'s membership invokers, **no replicated Overthrow state, nothing persisted**), a world-free `OVT_GroupRecruitTransfer` helper, and three `modded class` overrides on the vanilla group stack. **No new client→server RPC** (D1) — nothing added to the frozen `OVT_PlayerCommsComponent`, no getter on `OVT_Global`, both verified by empty diffs. **Phase 1's diagnosis cleared the Group Menu**: all of #147's "can't manage the Group menu" was downstream of BUG-088's single un-replicated faction map (no faction → no tiles → no selection → Join never appears); the greyed-out "Create new group" is vanilla-by-design. All four fixed. Also closed by the same work: recruiting while inside a shared group did nothing (leader guard → membership guard), an unbounded 500 ms respawn-retry loop (capped at 10), and a vanilla hole where a rejected join to a full group **stranded the player with no group at all**.
