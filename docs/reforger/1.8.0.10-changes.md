## Summary

1.8 is a major update for Overthrow. Two systems Overthrow depends on were rewritten: the **script testing framework** (breaks compilation of the entire test tree, ~300 call sites, all mechanical fixes) and **AI group spawning**, which moved from per-group frame-by-frame spawning to a world-scoped, budgeted, importance-tiered spawn queue with engine-driven dormancy/eviction. The second one compiles clean but invalidates a core assumption — "0 agents = dead group" — used by garrisons, patrols, deployments and two persistence serializers, and is the highest-risk behavioral change in this update.

## Breaking / High-Risk Changes

### 1. Test framework rewrite — compile FAIL, ~300 call sites (mechanical)

`scripts/GameLib/tests/TestingFramework.c` and `scripts/Autotest/Game/TestFramework/` were reworked:

- The deprecated typedefs `Step` → `TestStep` and `EStage` → `TestStage` were **removed**. Overthrow has **147** `[Step(EStage.X)]` usages across `Scripts/Game/Tests/` — every one is now an undefined identifier (reported as "Syntax error").
- `SCR_AutotestResult.c` is **deleted**, replaced by a failure model (`SCR_AutotestFailure.c`, `TestFailureBase`):
  - `SetResultFailure("msg", p1..p3)` → `SetFailure("msg", p1..p3)` (same string-interpolation params, `SCR_AutotestCaseBase.c:88` in the new tree)
  - `SetResult(SCR_AutotestResult.AsFailure(...))` → `SetFailure(SCR_AutotestFailure.Create(...))`
  - `SetResultSuccess()` (**146** Overthrow usages) has **no replacement** — success is implicit when no failure is set. The vanilla example (`scripts/Game/Tests/TestSuites/Example/SCR_TEST_Example1TestSuite.c`) replaces it with `AssertTrue(GetFailure() == null, ...)` or simply nothing.
- `[Test(suite: X, timeoutS: N)]` is **unchanged and still valid** — the 144 errors on those lines are cascades from the suite classes failing to compile. `Test` did lose its legacy `suiteStr` string-typed first parameter; Overthrow already uses the typename form.
- New capabilities: parameterized tests (`SCR_ParamTest`, `CreateParams()`, `SetParams()`), run settings container (`SCR_AutotestRunSettings` with `m_eActionAfterRun`, world-time coefficient), suites now auto-apply a time multiplier in Setup/TearDown.
- `SCR_AutotestHelper` gains `SwitchToGameMode()` and `WorldSetTimeCoef()`; all four statics Overthrow overrides in `Scripts/Game/Tests/TestFramework/OVT_AutotestFramework.c` (`GetDefaultWorld`, `GetDefaultSystemsConfig`, `GetDefaultLaunchParams`, `RequestScenarioChangeTransition`) still exist — note `RequestScenarioChangeTransition` is now `protected static`.
- `SCR_AutotestHarness` was refactored (bootstrap via `SCR_TestRunner`, statics made private behind getters). **`tools/run-tests.sh`'s launch/JUnit-parsing contract must be re-verified** once the sources compile; the parameterized-test naming scheme (`Name_###_Param`) may also affect JUnit parsing.

**Affected:** every file under `Scripts/Game/Tests/` (37 files), root fix in `OVT_TEST_SuiteBase.c` + `OVT_AutotestFramework.c`. Fixes are sed-able renames plus a decision per `SetResultSuccess()` site (delete vs assert).

### 3. AI group spawning rewritten: budgeted queue + dormancy — compiles clean, HIGH behavioral risk

`scripts/Game/Entities/SCR_AIGroup.c` (~734 changed lines): the 1.7 per-group delayed-spawn mechanism (`SCR_AIGroup_DelayedSpawn`, one member per frame) is deleted. Spawning now goes `RequestSpawn` → `ChimeraAIWorld.EnqueueSpawnRequest` → a 2 Hz, frametime-throttled queue ordered by a new importance tier (`SCR_EAISpawnImportance`: LOW capRatio 0.50 … CRITICAL 1.00). Requests are **deferred or dropped** under AI-budget pressure, and the engine can **evict members of low-importance groups into dormancy** (`DespawnMembersFromC()` deletes member characters but keeps the group entity; dormant groups deliberately survive `OnEmpty`).

Consequences for Overthrow (all verified against current code):

- **"0 agents = dead" pruning now races the queue and misreads dormancy.** A queued or dormant group looks dead to every `GetAgentsCount() == 0` check; none consult `IsDormant()`/pending state:
  - `Scripts/Game/GameMode/Managers/Factions/OVT_OccupyingFactionManager.c:576` — deletes "empty" tower garrison groups; when the list empties, `:586` hands the **radio tower to the resistance for free**.
  - `Scripts/Game/Controllers/OccupyingFaction/BaseUpgrades/OVT_BasePatrolUpgrade.c:42` (`CheckClean`, ~10 s cadence) — deletes 0-agent patrols whose resources were already spent; same pattern in `OVT_BaseUpgradeSpecops.c:30`, `OVT_BaseUpgradeDefensePosition.c:65`, `OVT_BaseUpgradeSniperPosition.c:110`, `OVT_BaseUpgradeTowerGuard.c:107` (the latter three also re-buy on 0 agents → duplicate requests / resource drain).
  - `Scripts/Game/GameMode/Deployments/Modules/OVT_InfantrySpawningDeploymentModule.c:251-293` — `IsGroupAlive` = agents > 0; a QRF can be declared **eliminated before it materialises**. Same prune in `OVT_VehicleSpawningDeploymentModule.c:433`.
  - **Save-time:** `Scripts/Game/Persistence/Serializers/Components/OVT_OccupyingFactionManagerSerializer.c:293` and `OVT_ResistanceManagerSerializer.c:205` skip groups with `< 1` agents — a save taken while garrisons are queued **silently shrinks them**.
- **Overthrow's hostile AI spawns at default (LOW) importance** — capped at 50% of the AI budget and first to be dropped/evicted. Player groups are fine: `SCR_GroupsManagerComponent.CreateNewPlayableGroup` now stamps master and slave groups CRITICAL, so recruit groups get full budget. Occupying-faction spawns (`OVT_EntitySpawningAPI`, tower defense, `BuyPatrol`) never call `SetImportance()`.
- **`Event_OnInit` semantics changed:** it now fires only when the group reaches *complete* fill, once per lifetime (1.7 fired even when the AI limit under-filled the group). `OVT_VehicleSpawningDeploymentModule.c:266` drives crew boarding solely from `GetOnInit()` — a budget-dropped or partially filled crew group means **the vehicle never gets crewed**. Consider driving from `GetOnAgentAdded` instead.
- **Intact:** Overthrow's modded `SCR_AIGroup` hooks (`AddAIEntityToGroup`, `OnAgentAdded`, `AddWaypointsDynamic`, `EOnInit` — the BUG-118 untracking chokepoints) are still on every 1.8 spawn path, including `ExpandOneMember`. `SetSlave` faction-stamp unaffected. Navmesh-stall retry loop replaced with a 30-attempt cap then spawn-anyway (removes a 1.7 never-appears failure mode).

### 4. `SCR_ChimeraAIAgent.EnsureAILimit` deleted — MEDIUM, mixed

1.7 self-deleted any non-player AI spawned over the limit (a standing threat to individually spawned recruit bodies — that risk is now **gone**). But individually spawned AI (`OVT_EntitySpawningAPI.SpawnSoldier`, town civilians, recruits) now bypasses **all** AI-limit enforcement: total agent count can exceed the configured cap, and what they consume pushes Overthrow's LOW-importance group requests further back in the queue (compounds finding 3). Overthrow's modded `IsPerceivedEnemy`/`IsEnemy` are untouched.

## Changed Systems Relevant to Overthrow

- **Group join/invite RPCs gained a server-side faction gate** (`SCR_PlayerControllerGroupComponent.RPC_AskJoinGroup` / `RPC_AskInvitePlayer`): the join is silently refused unless the group's faction equals `SCR_FactionManager.SGetPlayerFaction(playerId)`. Overthrow's own-group flow passes today (group is created from the same faction object, `OVT_PlayerGroupManagerComponent.c:250-262`), but any registration-timing slip (faction set in `OVT_SpawnLogic.c:924` moments earlier) now fails silently into the "player did NOT join group" warning (`OVT_PlayerGroupManagerComponent.c:296`). Watch that line in 1.8 MP logs. Many other group RPCs gained is-leader authority checks — Overthrow bypasses them (direct server-side calls), unaffected.
- **`SCR_GroupsManagerComponent.TryFindEmptyGroup` now skips private groups** by default — `OVT_PlayerGroupManagerComponent.FindAdoptableGroup` (`.c:336`) can no longer adopt an empty private group; worst case is one extra created group/radio frequency, not a break.
- **Inventory: moves now require both storages to have a valid `RplId`.** `SCR_InventoryStorageManagerComponent.TryMoveItemToStorage` fails via new `CanUseStorageForMove()` (`scripts/Game/Inventory/SCR_InventoryStorageManagerComponent.c:882`) when either storage isn't replication-registered. Overthrow prefabs have previously shipped missing vanilla components (BUG-088, BUG-132 precedent) — any container transfer involving a non-replicated storage now fails where it used to succeed. Equipment swap also gained a compatibility pre-check (`CanStoreItem` both ways) before swapping attachments.
- **Game-mode disconnect flow re-ordered** (`SCR_BaseGameMode.OnPlayerDisconnected`): the character lookup and a persistence hook now run **before** `m_OnPlayerDisconnected`/component callbacks fire ("has to be called prior to other events to read save-game data … before any cleanup logic"). `OVT_OverthrowGameMode.OnPlayerDisconnected` (`.c:898`) does its own work before `super.` — re-verify the disconnect/reservation flow (player-body reservation model) on 1.8, especially the `OVT_ReconnectComponent` claim noted at `.c:923`.
- **Faction JIP stream rewritten** (`SCR_FactionManager.RplSave/RplLoad` now delegate per-faction to `SCR_Faction.DoRplSave/DoRplLoad`; the client-side pending-limit-update queue was removed). Same-version server+client is fine; `OVT_OverthrowFactionManager` doesn't override these.
- **Reconnect:** `SCR_ReconnectComponent` now aborts a reconnect if the player's faction is no longer available (limits), and `SetInitialMainEntity` moved after the faction check. Overthrow doesn't use faction player-limits — low risk, but the reconnect path is part of the disconnect/reservation flow above.
- **Spawn logic:** `SCR_SpawnLogic` (base of `OVT_SpawnLogic`) fixed typos in *protected* members (`ApplyPendingPosession` → `ApplyPendingPossession`, `m_mPendingPosessions` → `m_mPendingPossessions` — Overthrow doesn't reference them; compile confirms) and now deletes + untracks a persisted self-spawned player character when the controlled-entity id points elsewhere.
- **`SCR_PlayerController`:** identity IDs moved from `array<string>` to `array<UUID>`; a few early-outs added. Overthrow's modded file unaffected (compile clean).
- **Group menu UI** (`SCR_GroupSubMenuBase`): selection now auto-defaults to the local player's group (and an index-vs-ID bug was fixed), so the `GetSelectedGroupID() < 0` vanilla-fallback branch in Overthrow's modded `JoinSelectedGroup`/`AcceptInvite` (`Scripts/Game/UI/Modded/SCR_GroupSubMenuBase.c:95,139`) rarely triggers now; confirmed the confirm-dialog flow re-asserts the selection, so no redirect risk.
- **Nametags** (`SCR_NameTagRulesetBase`, base of `OVT_NameTagRulesetFaction`): additive performance work — per-frame LOS trace budget, FOV caching, behind-camera cull. Behavioral only; low risk.
- **Cosmetic/no-op:** `SCR_PersistenceSystem` (typo rename `DeferredNotifcation`→`DeferredNotification`), `ScriptedComponentSerializer` **unchanged** (persistence serializer API stable), `SCR_MapUIElement.SetImage` gained an optional `imageset` param. Unchanged: `SCR_GarbageSystem`, `SCR_CharacterDamageManagerComponent`, `SCR_FieldManualUI`, `SCR_InventorySlotUI`, `SCR_ItemAttributeCollection`, all storage/loot user actions, `SCR_RespawnSystemComponent`, map modules, button/widget bases.

## New Systems & Content

- **AI group lifecycle & budget system** (`scripts/Game/AI/SCR_EAIGroupLifecyclePolicy.c`, `SCR_EAISpawnImportance.c`, plus `ObserversSystem` and `VisibilityConsumerSystem` registered in `Configs/Systems/ChimeraSystemsConfig.conf`): groups can be `Manual` or `ProximityDriven` — a proximity-driven group auto-materialises when an observer is within spawn distance and despawns members when all observers leave, via the new ObserversSystem. **Opportunity:** this is native engine support for exactly what Overthrow hand-rolls with virtualization/spawn-distance logic; adopting `ProximityDriven` + `SetImportance` for garrisons could eventually replace custom despawn management.
- **AI ladder traversal**: vanilla ladder prefabs gained `NavmeshCustomLinkComponent` with `NavmeshLadderLink` (e.g. `Prefabs/Structures/BuildingParts/Ladders/Ladder_CoastalBattery_USSR_01/*.et`). AI could not climb ladders in 1.7 (a known constraint for Overthrow's elevated guard posts) — re-evaluate elevated-post AI on 1.8.
- **Vanilla persistence expands to AI**: new serializer configs `Configs/Systems/Persistence/Configuration/AI/AmbientPatrol.conf` and `AIWaypointCycle.conf` (e.g. `SCR_AmbientPatrolSpawnPointComponentSerializer`) — vanilla now persists ambient patrol state through the same `EntityPersistenceConfig` machinery Overthrow uses.
- **Vanilla Tasks system deleted** (~30 files: `SCR_BaseTask`, `SCR_BaseTaskManager`, all `SupportEntities/`, campaign tasks). Overthrow has zero references (verified by grep + compile) — its jobs system is unaffected.
- **Arsenal alternative-cost data** (`scripts/Game/Components/Arsenal/SCR_ArsenalAlternativeCostData.c` + 3 siblings) — new cost/sell-amount hooks on arsenal items; potentially useful for shop/arsenal economy integration.
- **Commanding/emotes**: loiter and salute emote commands moved out of `Configs/Commanding/Commands.conf` into per-emote configs (`Configs/Commanding/Emotes/*.conf`, 15 new files); commands gained `m_bTargetSelf`. New `Configs/Character/LoiterItemPresets.conf`.
- **Misc new configs**: `Configs/Map/BaseServiceIcons.conf`, `Configs/System/Actions/PlayerListActions.conf`, `Configs/Systems/MapPreviewSystemsConfig.conf`.
- **Removed**: GameLib dialogue system (`DialogueSystem`, `DialogueController`…), `SoundManagerModule`, `TestResultBase` (generated), `SCR_AutotestToolPlugin`.
- **Bulk prefab migration** (most of the 4,403 modified `.et`): mechanical `angleY N` → `angles 0 N 0`, ancestor-path rewrites after folder reorganisations, and some item prefab roots changing `GenericEntity` → `GameEntity`. Spot-checked samples show no behavioral content in the bulk.
